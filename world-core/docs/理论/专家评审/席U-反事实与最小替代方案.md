## 零、先说方法论：本席不判"这件事有没有意义"

委托要求的是**反事实与代价**，不是价值判断。所以本席把"干"定义为一条**可计量的工程动作序列**，
而不是一个理念。判断只依据两类量：

1. **可引用的数字**（本仓库实测／估算，逐字给行号）；
2. **可指名的角色在一个可描述的日期遇到的一个可描述的场景**。

凡落不到这两类上的论证，本席一律标注「**无数字，属推断**」，并且**不让它承担判决重量**。

**本席的第一条发现（贯穿全篇）**：这个项目自己的成本账已经算出来了，**而收益账被自己宣布为无定义**。
判决之所以困难，不是因为缺数据，是因为**两边的数据不是同一种东西**——
成本是"人日"（可加、可比、有量纲），收益是"0 ÷ 0 无定义"（不可加、不可比、无量纲）。见 C5。

## C1 · 反事实：不干，会怎样

### C1.0 反事实的基线：先把"不干"说准

"不干"不是"什么都不做"。本席把"不干"定义为：**不造语义世界；保留现有工具、现有系统、现有纪律，不做任何以"语义事件＋唯一账本"为形态的新基础设施。** 这个基线是真实存在且可运行的——本仓库自己已经证明它存在，逐字：

> `2-依据/05-Omarchy机制实证.md:118`
> 「一句话收束：**Omarchy 已经把"桌面"做到了 agent 可用（IPC + 技能 + 崩溃闭环），把"系统"留成了空白（无门禁、无审计、快照没接给 agent 当 API）。**」

这份文件自己的判定表（`:107-116`）逐行写着现成机制的可用性：`snapper + btrfs + limine` 是"**一等公民（更新前自动快照）**"（`:109`）、崩溃闭环"**已完整**"（`:113`）、IPC 面"**完整（CLI → JSON）**"（`:114`）、GUI 自动化"**不重做**"（`:115`）。所以"不干"的基线**不是一个裸系统**，而是一个已经相当好用的桌面环境加一个空白的系统层。

**这就是反事实的真实形状**：不干的代价，恰好等于"系统层那块空白"在被真实使用中产生的代价。

### C1.1 角色一：项目负责人（这台机器的唯一操作者）——"这些活谁干"

**场景**：2026-10 的某个周末，他决定"先不干，先用手上这套把日子过下去"。

**代价 A：他发现所有他本来指望"项目会替他解决"的运维活儿，一样没少，只是从"系统的事"变回了"他的事"。**

这不是推断。席 G 已经把这笔账逐项列出来并加总，逐字：

> `专家评审/席G-经济与运维-独立评审.md:450`
> 「| **合计** | | **≈27.3 人時/月 ≈ 3.4 人日/月 ≈ 41 人日/年** |」

> `:454`
> 「**经常性成本 ≈3.4 人日/月**，其中 **77% 是文档与评审**（21.0 / 27.3）。」

**这笔 3.4 人日/月不是"不干"省下的钱**——它是"干"的成本。本席要指出的是反事实方向的那一半：席 G 那张表（`:416-431`）里的 14 项动作，**在"不干"的世界里有 9 项根本不存在**（升级契约评审、Poisoned 处置、损坏调查、账本备份、重放巡检、工具链复验……），因为它们处置的是**语义世界自己引入的新对象**（账本、本体、门禁、锁）。

**⇒ 反事实的结论是反的**：**不干，运维面是"变小"，不是"变没"**——剩下的是普通 Linux 运维（Omarchy 已覆盖大部分），量级参考席 G 自己的对照估算逐字：

> `:883`
> 「| **日常运维** | **≈3.4 人日/月 ≈ 41 人日/年**；其中文档与门禁 **77%**；**无 runbook、无监控** | git：**≈0.1 人日/月**【估】；Kafka 单机：**1–3 人日/月**【估】 | 见 2.5 逐项表【估】 |」

**算法与假设（本席的估算）**：不干 ⇒ 省下的是**语义世界自己引入的新对象**的运维面。席 G 的 27.3 人時/月里，与"语义世界新对象"直接绑定的科目是第 4/5/6/7/8/10/11/12 项 = 2.00+0.25+0.13+1.00+0.33+0.67+0.17+0.33 = **4.88 人時/月**；剩下的 16.00（文档与门禁维护）+ 5.00（门禁评审摊薄）+ 1.10+0.10+0.17 = **22.37 人時/月，是"这套流程器具"本身的成本，不干则一并消失**。**合计 ≈27.3 人時/月全部消失。**

**⇒ 不干，省下 3.4 人日/月。这是"不干"的第一笔确定收益，且它是本报告中唯一一笔双向可加的量。**

**代价 B：他失去了"这件事有人在做"这条心理账。** **无数字，属推断。** 本席不采信它作为判决依据。

### C1.2 角色二：AI agent（被管者，uid 1001）——"每一次调用都是一次谈判"

**场景**：某个 agent 在 10 分钟内完成一个长任务。它不知道任务什么时候干完。

**代价**：它只能轮询。本仓库有实测口径的数字，逐字：

> `2-依据/07-硌牙清单与单机经济账.md:27`
> 「| 5 | 事件总线碎片化 | 世界的声音散在七八个喇叭里；**完工不拉铃，agent 只能反复轮询** | agentd 事件网关缝合 coredump/udev/inotify/NM 各协议；**完工铃 = 第一优先**（10 分钟任务轮询 20 次推理 → 2 次） |」

> `00-总纲.md:262`
> 「**完工铃第一优先**——长任务零轮询（10 分钟任务从 20 次推理降到 2 次）（07:20）」

**算法（把这 18 次差额折成代价）**：一次"推理"的代价 = 输入 token × 单价 + 输出 token × 单价 + 一次工具往返延迟。
**本仓库没有 token 计数台账，也没有 agent 负载画像**——席 G 已如实登记这一点，逐字：

> `专家评审/席G-经济与运维-独立评审.md:908-910`
> 「2. **1000 万条/天场景下的突发分布** —— **无 agent 负载画像**。项目内唯一相关的量级是
> `2-依据/07-硌牙清单与单机经济账.md:27` 的"10 分钟任务轮询 20 次推理 → 2 次"，
> 那是**轮询次数**，不是**事件速率**。我在 2.2 假设"一分钟 7 000 条突发"，**该假设无来源**，仅为量级演示。」

**⇒ 所以本席只能说：差额是每 10 分钟 18 次推理。** 把它折成钱需要 token 单价与上下文长度，**这两个数本仓库查不到**。**「无数字，属推断」**：本席推断这笔差额在"上下文长、任务多"的用法下会累积成可观的成本，但**本席拒绝给出一个编造的 token 数**——因为席 G 刚刚因为假设无来源而自我批评过（`:910`），本席不重犯。

**但这里有一条被本项目自己实测、且比 token 更硬的事实**：

> `WC-THEORY-DEFECT-001-v0.2.md:45`
> 「| **D-03** | **严重** | `notice` **不进读模型**（只 `notices += 1`）⇒ **两个投影永远看不到通告**；连带"同源"核对对通告**不敏感** | …… | 完工铃成了**结构性死信**：写进账本，再也出不来 |」

**⇒ 反事实在这里是"不分叉"的**：**干，今天也是 20 次轮询。**
"不干"的代价不是"多了 18 次轮询"，而是"这 18 次轮询永远没有尽头"。
**但请注意**：造语义世界**今天并没有把 18 次变成 2 次**——席 B 的判定是「**它不是坏了，是不存在**」（转引自 `WC-BOOK-001-v0.1.md:597` 与 `:621` 的收敛）。**所以"干"在这条上的兑现是 0，不干在这条上的代价也是 0。这条不能用来支持"干"。**

**★ 本席给这条一个精确的判决**：C1.2 是**一条"干与不干代价相同"的反事实**。
它在 C1 里出现，是为了**排除一条看起来很有力、实际不成立的论据**。这是本席与席 S、席 T 分工的边界。

### C1.3 角色三：项目负责人——"配置被改了，查不出是谁改的"

**场景**：某个早上（比如 2026-10-05 08:40），他发现服务行为不对。`stat` 告诉他文件昨天 03:14 被改过。

**代价**：本仓库有逐字描述，且是"五则具体场景"的第一则，逐字：

> `WC-BOOK-001-v0.1.md:441`
> 「1. **配置漂移**：一个 agent 半夜把配置改了。早上服务行为异常。`stat` 告诉你"文件昨天 3:14 被改过"，**但不告诉你改了什么、为什么改**。你得靠 `diff` 一个备份。**若备份周期是一天，你连 diff 都做不成。**」

**同一份书还给了这块空白的机制级说明**，逐字：

> `:433`
> 「| 文件系统 | **字节与时间**（mtime、size、inode） | **字段与意义**：`config.yaml` 变了，它不知道"变的是 `max_retries`，从 3 变成 30，谁改的，为什么" |」

**代价的形态（本席的推断）**：不是"多花 3 小时"，而是**"你不敢回滚"**——因为不知道那次改动是合法的还是非法的，回滚会连带撤掉别的合法修改。这一段本仓库也写了，逐字：

> `:443`
> 「3. **"我装好了"无法验证**：agent 说它装了包。你没法验证它**到底装了什么、装之前是什么**。"回滚"要靠整机快照——而快照不知道"世界上发生了什么"，所以**你不敢回滚**（怕把别的合法修改一起撤掉）。」

**⇒ 不干的代价在这条上是最实的**：**从"能查出"退化为"靠直觉 + 二分法试错"**。
席 D 有一句更锋利的定性，逐字：

> `专家评审/席D-外部系统反面举证-独立评审.md:43`
> 「- **谁受损**：机器的所有者（人）。**损失**：服务不可用时间 ＋ 定位时间（**真实成本是"你不知道该怀疑什么"，所以只能二分法试错**）。」

**数字**：**无数字，属推断**。本仓库没有任何"一次配置漂移平均定位多久"的记录。席 G 也承认项目"**无工时记录**"（`:914`）。

### C1.4 角色四：项目负责人 + 一个未来接手人——"四本账拼不起来"

**场景**：半年后（2027-03），一次真实事故需要复盘。他要回答"上个月 14 号那个改动是谁做的、从什么变成什么"。

**代价**：四本账没有共同主键。本仓库逐字：

> `WC-BOOK-001-v0.1.md:445`

**⇒ 这条反事实有两个时间尺度，第二个比第一个更贵**：

|---|---|---|
| **复盘当时** | 2027-03 | 人工拼四本账，**无数字，属推断** |

**★ 这里有一个容易被读反的地方，本席必须指出**：这 25–40 人日**不是"不干"的代价，是"干了之后"的代价**——它是接手**语义世界**的成本。**"不干"的接手成本是"接手一套普通 Linux 桌面"，量级参考席 G 对 git 的对照估算逐字「git：**0.5–2 人日**【估】」（`:886`）。**

## C2 · 最小可行替代：不造语义世界也能拿回大部分收益

**先划一条判据线**。本席用的判据来自项目自己，逐字：

> `语义世界-序.md:55`
> 「不过这里要说准：要拿到"改了哪个字段、前值是什么、因为哪一条、谁批准、可不可逆"这几样，才必须有那个共同的东西；如果只要求"能协作"，没有它也能做到，上面那张表里的东西就是现成的例子。」

**⇒ 项目自己承认：五样能力里，"改了哪个字段／前值是什么"这两样，是判"必须有那个共同的东西"的分界线。**
所以 C2 的每一条替代方案，都要回答一个问题：**它能不能拿到"改了哪个字段 + 前值是什么"，或者至少其中的一半？**

下面三条，按"代价从低到高"排。

---

### C2.1 方案甲：**什么都不做，只用现有工具与纪律**（git ＋ 约定 ＋ 一次变更纪律）

**具体做法（谁做、做什么、多少工作量）**

| 步 | 动作 | 谁做 | 工作量 |
|---|---|---|---|
| 甲-1 | 把"改配置"这件事**全部收进一个 git 仓库**（`~/.config`、`/etc` 的受管子集），`git init` + 一个裸仓库或 U 盘副本 | 人（一次性） | 0.5 人日 |
| 甲-2 | 写一条约定：**每一次改动一个 commit，subject 用 `动词(对象): 从 X 到 Y`**；前值靠 `git diff` 或 `git show` 拿到，不额外写 | 人（一次性） | 0.1 人日 |
| 甲-3 | **`git commit -S`（GPG/SSH 签名）＋ 一个 `pre-commit` 钩子强制 subject 格式** | 人 | 0.2 人日 |
| 甲-4 | agent 改配置时**必须走 `git commit`**，由 harness 的 PostToolUse 钩子自动提交（不给 agent"改完不提交"的选项） | 人（改 harness 配置） | 0.5–1 人日 |

**它拿回了什么**

- **"改了哪个字段、从什么变成什么"** —— **拿到了**。这是 git 的本职：`git diff` 逐行给前值。
- **"谁改的"** —— **名义上拿到**，有签名则更强。
- **"能带全部历史离开、可独立复算"** —— **拿到了，而且是所有方案里最强的**（席 G 逐字，`:857`）：
  > 「**内容寻址 + append-only 对象图 + Merkle 提交链 + 零服务依赖 + 单机 + 近乎零运维 + `.git` 可整体复制**。」
- **"不可逆要批准"** —— **拿到一半**：靠 `pre-commit` 钩子做**默认拒绝**（未签名的、格式不合的一律拒），这是"约定级"的强制，不是内核级。

**它没拿回什么**（逐条对 `序.md:65` 的七项）

| 序的三样 | git 方案 | 引用 |
|---|---|---|
| ① 语义事件（七项自描述） | **只拿到 3 项**（主体、改了哪个字段、前值） | —— |
| ① 的"因为哪一条" | **拿不到**。git 无因果字段 | `席G:882`「| **因果链** | …… | git：**无**；CloudTrail：**无**（要自己拼 correlation-id） |」 |
| ① 的"谁授权、可不可逆" | **拿不到**。"谁批的"不在配置里 | `席G:803`「**② "谁批的"不在配置里**（`stateVersion` 是兼容标记，不是批准链）」 |
| ① 的"全序与时间基准" | **拿不到**。git 允许多分支任意合并，无全局单增序 | —— |
| ② 一本账 | **拿不到"一本"**。Git 有历史但**不是唯一权威账**；且"跨过接口、跨过主体"没有权威 | `序.md:77`「Git、SQL、HTTP 都没有一本唯一的权威账，却确实是共同的说法」 |
| ③ 出口 | **拿不到**。git 给的是 diff 文本，不是"各方按最优方式取"的出口 | —— |

**★ 一个必须写明的事实：git 记不住 mtime，也记不住"什么时候"**
Git 的对象里只有**提交时间戳**（且由提交者自报），**不保存文件的修改时间**。
外部依据：git 自身的文档与长期已知限制（`git-verify-commit` 只验签名，不验时间戳真伪，见
[git-verify-commit Documentation](https://git-scm.com/docs/git-verify-commit)；
"Git itself does not save original times"见 [Stack Overflow: Restore a file's modification time in Git](https://stackoverflow.com/posts/64147402/timeline)）。
**⇒ 在 C1.3 那个场景里，git 方案的答案是"我能告诉你改了哪一行，但我给不了你一个可信的改动时刻"。** 这一项它比 `stat` 的 mtime **更弱**（mtime 至少是内核写的）。

**与"造语义世界"相比，成本差多少倍**

依据席 G 的两个数：

> `:871`「| **一次性建设** | 主张 **≤21 人日**【实/无凭证】…… | git + 约定：**2–5 人日**【估】；Kafka/Kurrent：**5–15 人日**…… |」
> `:883`「| **日常运维** | **≈3.4 人日/月**…… | git：**≈0.1 人日/月**【估】…… |」
> `:886`「| **第二人接手** | **能操作 12–18 人日；能安全改动 25–40 人日**…… | git：**0.5–2 人日**【估】…… |」

| 成本项 | 造语义世界 | 方案甲（git＋约定） | 倍数 |
|---|---|---|---|
| 一次性 | ≤21 人日（无凭证） | 2–5 人日【估】 | **4–10×** |
| 日常运维 | 3.4 人日/月 | ≈0.1 人日/月【估】 | **34×** |
| 接手 | 12–40 人日 | 0.5–2 人日【估】 | **6–80×** |

**本席的估算（区别于席 G 的）**：甲-1 到 甲-4 合计 **1.3–2.1 人日**（本席自己的假设：一次性的 `git init` 0.5、约定 0.1、签名与钩子 0.2、harness 钩子 0.5–1）。
**⇒ 按本席的估算，一次性成本差 10–16 倍；按席 G 的估算差 4–10 倍。两法同向。**

**它会不会在半年内退化成"又一个两两约定"？**

**会，但不是最坏的那种。** 理由：git 方案的强制力来自**钩子**（`pre-commit` 拒绝格式不合的提交），而钩子是**可以被 `--no-verify` 绕过**的。`序.md:21` 担心的正是这个形态：
> 「**每一对交界各谈一份约定。** ……每一份约定自己又要有人维护、有人批准、有人决定改了以后旧记录还读不读得懂。」

**退化的具体机制（本席的推断）**：半年后会有**两个**约定——一个给"我自己的 dotfiles"，一个给"agent 改的东西"，因为 agent 的 commit 需要机器可读的字段（actor、capability），而人的 commit 只要人读得懂。**两个约定就是"两两约定"的最小形态。**

**⇒ 所以方案甲不是终局，它是"把退化推后 6–12 个月、并把退化成本降到近乎零"的方案。这是它的真实定位。**

### C2.2 方案乙：**统一 trace id ＋ 结构化事件（OpenTelemetry 思路），不改写入路径**

**具体做法**

| 步 | 动作 | 谁做 | 工作量 |
|---|---|---|---|
| 乙-1 | 在 agent harness 的**入口**生成一个 `trace_id`（一次人为意图 = 一个 trace） | 人 | 0.5 人日 |
| 乙-2 | 约定**6 个字段**写进所有日志：`ts / trace_id / actor / subject / field / before`。用 OpenTelemetry 的 Logs 数据模型承载（`trace_id` 是它的**一等字段**） | 人 | 1 人日 |
| 乙-3 | 汇聚到**一个 JSONL 文件**（不部署 Collector，不起服务），`jq` / `sqlite` 查询 | 人 | 0.5 人日 |

**外部依据**：OpenTelemetry 的 Logs 数据模型把 `TraceId`／`SpanId` 列为日志记录的字段，且明确设计为与 Traces 关联
（见 [OpenTelemetry Logs Data Model](https://opentelemetry.io/docs/specs/otel/logs/data-model/)）；
但**分布式追踪的设计目标是"解释一次请求为何慢/为何失败"，不是"向监管者举证"**——
这一点有独立的工程界定性，见
[Distributed Tracing Shows You What Happened. It Cannot Prove It to a Regulator.](https://tsecurity.de/e/3671570/it+programmierung/distributed+tracing+shows+you+what+happened.+it+cannot+prove+it+to+a+regulator./)。
**⇒ 这条外部证据正好对上本项目自己的差异化主张**，逐字 `席G:790`：
> 「**① 测的是"系统健康"不是"谁做了什么"**——Prometheus 的模型是时间序列，
> 它天然**丢样本、做聚合、算 rate**；而可问责要求**逐条不丢**。把审计塞进 Prometheus 是范畴错误。」

**它拿回了什么**

- **"因为哪一条"** —— **拿到了**，而且这是七项里**唯一一项 git 方案完全拿不到、而方案乙能廉价拿到**的（靠 trace_id 串起同一次意图下的所有动作）。
- **"改了哪个字段、前值是什么"** —— **拿到前提是每个写入点都主动填** `field` 与 `before`。这是它最大的脆弱点。
- **跨工具的统一查询** —— **拿到了**（一个 JSONL + `jq`），这直接对上 `BOOK:445` 的"四本账没有共同主键"。

**它没拿回什么**

- **"不能事后改写"** —— **完全没有**。JSONL 是普通文件，谁有权限谁能改。这与 git 方案形成鲜明对比：**git 的 Merkle 链使"历史改写必然改变所有后代 hash"（`席G:878`），而 JSONL 没有这个性质。**
- **"谁授权、可不可逆"** —— 没有。门禁需要写入路径上的裁决点，而方案乙**刻意不改写入路径**。
- **全序** —— 没有。`ts` 是墙钟，可回拨。**本仓库自己实测过这个坑**，逐字 `BOOK:602`：
  > 「实测：事件身份押在墙钟上（纳秒 + **进程内**计数器，重启归零、墙钟可回拨、**无检测**）」

**与"造语义世界"相比，成本差多少倍**

本席估算 **2–2.5 人日**一次性 + **≈0.5 人日/月**（约定漂移的维护）。
依据：席 G 把"可观测三件套"的部署成本列为"**4 个有状态组件 + 对象存储 + 反代 + TLS + 认证，对单机个人是纯负债**"（`:793`），而本方案的差异恰恰是**不部署那 4 个组件**——只借它的**数据模型**（字段名与 `trace_id` 语义），不借它的运行时。
**⇒ 相对造语义世界：一次性差 8–10 倍；日常差 ≈7 倍。**

**它会不会在半年内退化成"又一个两两约定"？**

**会，而且比方案甲更快——退化周期本席估 2–3 个月。** 理由：方案乙的强制力**完全依赖"每个写入点都主动填 6 个字段"**，而它**没有钩子、没有拒绝**。任何一次"先跑通再说"的临时脚本都会写出缺 `before` 的行。
**⇒ 这是三条里最脆弱的一条。** 本席把它列出来，不是推荐它，而是**指出它是一个真实存在的中间档**：比 git 方案灵活（有因果），比造语义世界便宜（不改写入路径），**但它两头的好处都只拿到一半，且没有强制力**。

### C2.3 方案丙：**旁路采集器 + 固定字段 JSONL ＋ 每次变更一个 blob hash**（"Kubernetes audit log 思路的单机版"）

**先说清"K8s audit log 思路"到底借什么**。Kubernetes 的审计机制有三个结构特征值得借：
① **固定字段的 JSON 事件**（`user`／`verb`／`resource`／`requestObject`／`responseObject`／`stage`）；
② **分级 + 策略决定记什么**（`None`/`Metadata`/`Request`/`RequestResponse`）；
③ **审计发生在服务端写入路径上，不由客户端决定**。
参考：[Kubernetes Auditing](https://kubernetes.io/docs/tasks/debug/debug-cluster/audit/)。

**★ 本席必须点明一条落差**：本项目**已经借了 ③ 的形状**（唯一写入口），但**③ 的强制力靠"被管者与它不同身份"**，而这个前提在单机形态下不成立。本项目自己写了，逐字 `序.md:115`：
> 「它的强制力今天靠约定，不靠内核。门禁靠进程边界与文件权限，前提是"被管者与它不同身份"；而在当前唯一现实的部署形态里，这条前提不成立。这不是将来才有的风险，是今天的实况。」

**⇒ 所以方案丙的关键设计约束是：不假装有强制力，只做一个"采集器"，把强制力留给已有的东西（内核权限位）。**

**具体做法**

| 步 | 动作 | 谁做 | 工作量 |
|---|---|---|---|
| 丙-1 | 一个**旁路守护进程**（约 200–400 行 Rust/Python），监听 `inotify` 对受管目录的写入 | 人 | 1–1.5 人日 |
| 丙-2 | 每检测到一次写入：`git -C <受管目录> stash` 前后对比，或直接 `git show HEAD:<file>` 取**前值**，写一行 JSONL：`{ts, path, field, before_sha256, before_excerpt, after_sha256, actor_hint}` | 人 | 1–1.5 人日 |
| 丙-3 | **每条记录把前值的内容 hash 写进一个另存文件**（"blob 锚"），防止"有人改了 JSONL 而不改文件" | 人 | 0.5 人日 |
| 丙-4 | 查询用 `jq` + `git log` 交叉 | 人 | 0.2 人日 |

**它拿回了什么**

- **"改了哪个字段、从什么变成什么"** —— **拿到了**，且**前值是从 git 对象里取的，不是从内存里记的**——这一点比方案乙硬（不依赖写入点主动填）。
- **"不用 agent 配合"** —— **这是它相对方案乙的核心优势**：agent 不需要知道这套东西存在。**这正好绕开 `序.md:87` 承认的第三种角色**：
  > 「还有第三种角色容易被漏掉：把东西写进来的那一侧。设备的动作、旧系统的状态，得有人把它写成语义事件。这是入口，不是翻译。」
  **方案丙把"入口"从"要求每个写入者配合"改成"在文件系统层截获"。**
- **一条可核的痕迹链** —— 部分拿到（丙-3 的 blob 锚使"改 JSONL"与"改文件"必须同时做才不被发现）。

**它没拿回什么**

- **因果** —— **没有**（不如方案乙）。
- **全序** —— 没有（`inotify` 给的是墙钟顺序）。
- **门禁** —— **完全没有**。它只记，不拦。**这是它最大的缺口**：它能回答"发生了什么"，不能回答"这件事该不该发生"。
- **它不解决 `序.md:107` 那条**："写一条从未声明过的实体、加上一个从未声明过的字段，照样能落账"——方案丙根本不看语义，只看字节。

**与"造语义世界"相比，成本差多少倍**

本席估算 **2.7–3.7 人日**一次性 + **0.3–0.5 人日/月**。
**⇒ 相对造语义世界：一次性差 5.7–7.8 倍；日常差 7–11 倍。**

**它会不会在半年内退化成"又一个两两约定"？**

**不会退化——但它会"停在一个固定的能力上限上"。** 理由：方案丙**只有一条写入路径**（inotify → JSONL），没有"两两"的空间。它的上限是确定的：**它能覆盖"文件系统上的变更"，覆盖不了"没有落到文件上的变更"**（内存态、网络调用、GUI 操作、GPU 分配）。
**⇒ 本席的定性：方案丙是三条里"能力上限最清楚、退化风险最低"的一条。它的适用边界与 `2-依据/06-重复工作审计.md:53` 那句同向，逐字：**
> 「生态越热闹，这个位置越缺——因为云平台、容器 AOS、GUI 驱动都假设"下面有个可信的系统"，而这个"下面"今天还是裸的 sudo 或没有。」
