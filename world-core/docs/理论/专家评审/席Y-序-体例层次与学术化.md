## Y1 · 它像不像一条序

### Y1.0 先定"序"与"全书"的分工界

一份**序**与一份**全书**的分工，不是篇幅之分，也不是深浅之分，而是**承担的义务种类之分**。本席据本项目自己两份对照件的实际体例，把界划在四处：

| | **序**（独立件） | **全书**（`WC-BOOK-001`） | **记录件**（`WC-PREFACE-LOG-001`） |
|---|---|---|---|
| 体例证据 | `WC-MERGE-001-v0.1.md:43` 逐字：「`语义世界-序.md` 序 · 书稿体（正文）**← 各方先读这一件**」 | `WC-BOOK-001-v0.3.md:6` 逐字：「**性质**：理论立场文件（不是规范、不是判据）」 | `WC-PREFACE-LOG-001-v0.3.md:3` 逐字：「**本件是什么**：记录件（工作文件，不是书稿）**」** |
| 承担 | 主张 ＋ 理由 ＋ 边界 | 主张 ＋ 论证 ＋ 依据出处 ＋ 逐条对照表 | 版本、处置、台账、检验表、签字 |
| 不承担 | 版本、判据、实现进度、评审处置、出处脚注 | —— （全书承担） | 主张本身 |

**一份序应当让读者带走的四样**：

1. **它要造什么**（一句话能复述，且**有名字**）；
2. **为什么非它不可**（一条可复述的命题，含它的前提）；
3. **它站在什么位置**（哪一层、上不下探、不取代谁）；
4. **它不假装能做什么**（**声明式**的失效边界，一句话级）。

**一份序不应当承担的四样**：

1. **版本与进度**（属记录件）；
2. **验收判据与其执行结果**（属记录件 §九检验表；`WC-PREFACE-LOG-001-v0.3.md:114` 已把该表收在记录件内，理由是"D-38：正文改书稿体时丢掉了编号检验表"——**记录件自己承认这是记录件的活**）；
3. **实现机制与实测缺陷**（属全书的"实现未及"章与缺陷台账）；
4. **对第三方的条款清单**（属契约件，或全书的前置契约节）。

### Y2.3 作者要的"我们的理论系统层面"是什么

作者逐字：「要把这个**从系统层面**，就是**我说的不是说是操作系统，我说的是说我们的、理论系统层面**，把这个事儿要说清楚。」

**这句话里有两个否定和一个肯定，必须拆开读**：

- 否定一：**不是操作系统那一层**（不是说内核、进程、文件权限）。
- 否定二：**不是"某个系统"这一层**（不是讲某个软件的架构）。
- 肯定：**"我们的理论系统"这一层**——即**这套理论自身的层次骨架**：它主张什么、这条主张的前提是什么、它在整座楼里占哪一层、它下面靠什么、上面托什么。

## Y3 · "更学术化"的边界

### Y3.1 作者的两条要求为什么看起来冲突

- 要求 ①：「**这是一条序，不是具体的细节。**」
- 要求 ③：「你写的倒是**现在差不多了**，对，**再详细的更学术化的表达一下**。」

不冲突。作者说的"细节"指的是**实现细节**（机制、进度、判据、参数）；作者说的"学术化"指的是**论证形式**（命题、前提、界定、可证伪）。**两者作用在不同的轴上**：学术化加的是**形式的严格度**，去细节去的是**内容的层位**。⇒ 可操作的口径是：**内容上提一层，形式上收紧一档。**
