## 二、逐条攻击

### 攻击 1 ·「没人造的是同一个航站楼」——这是警告，不是机会

**原主张引用**（`2-依据/11-总线工程规格.md` §七，第 99–101 行）：

> **缺口判断**：六件参考件各就各位，没人拼成"世界观总线"（自描述消息+双投影+语义级治理）
> ——马路（NATS）、海关（MCP 网关）、值机柜台（browser-use/CUA）、航显屏（A2UI）都有人造，
> **没人造的是同一个航站楼**：同一 IR、同一条广播、同一份世界状态。

（`2-依据/13-总线与通道外部参考.md` §四 用覆盖矩阵把这条量化："①③② 都有成熟形态可抄，④ 全缺"、
"顺序/序号与按能力治理，没有任何一件同时做好……这两件是我们**真正的新增**"。）

#### 我的攻击：这条"没人做"是**稳态的必然产物**，不是市场空隙。至少六种非愚蠢的解释

**解释一：它被刻意设计掉了（RFC 3439 / 沙漏模型）。**
所有长寿的协议（IP、TCP、HTTP、JSON、Unix、SMTP）都遵守同一条规律：**腰部最窄、两端最肥**。
把语义放进腰部，腰部就不再窄，所有演化成本立刻转嫁到最不愿意改的那一层。
其中第 ④ 类"引用（内容 hash）"是唯一"五件全缺"的东西——而它不是遗漏：
**内容寻址（git/IPFS）之所以不放进通用消息总线，正是因为它是策略而不是机制**
（引用要不要解析、由谁解析、失败怎么办，每个使用场景答案都不同）。
项目的解法是把策略焊进腰部。**这是我的推断**，但它有 50 年协议演化的样本支撑。

**解释二：语义的所有权在领域，不在基础设施。**
"通知""任务""静音"在医疗、金融、工业控制里不是同一个概念。
成功的"语义"基础设施无一例外**只定义结构原语、把语义留给服务方**——最贴切的对照就在项目
自己的参考表里：LSP 定义"文档/位置/符号"这种**结构**，把"什么叫类型错误"留给各语言服务；
varlink 定义"NUL 分帧 + 注释即文档"，把接口语义留给服务。
项目把这条读成"它们缺治理"，然后据此决定自己去承担语义——**顺序反了**。

**解释三：语义级总线的协调成本随参与方数量超线性增长。**
一旦总线定义语义，每一个应用都成了 schema 的干系人。N 个应用 = O(N²) 协商。
这正是为什么业界把语义下沉到应用、把 schema 交给各自领域（OpenAPI、AsyncAPI、Protobuf）。

**解释四：商业模式上这是"要建就建不成"的东西。**
语义层是**产品**（要有人定义、维护、解释"什么算合法语义"）；
传输层才是**公共品**。同一个人或公司既做语义又做传输，就同时是立法者与运营商——
外部参与者没有任何理由把本体交给一个与自己利益不一致的立法者。项目在
`1-理论与哲学/00-理论定稿.md` §1.3「定义即参战」已经承认了这一点，却**没有把它当成
"为什么没人做"的答案**，而是当成"我要更小心"的忠告。

**解释五：最像的先例都死在那道坎上，而且它自己的文档写了原因。**
`2-依据/08-创世路线论证.md` §五 待批判 3 自首：

> **单机世界的历史宿命**：Smalltalk/Genera 皆败于与开放生态的竞争——不兼容路线的历史胜率极低

`2-依据/09-理论修正推导.md` §三 给出了败因机制："它们不是败于'不兼容'，是败于**自足但空转**
——没有外部性来源，优雅的世界里没有事可做。"
**把这句读两遍**：已有的两次完整实践**做出来了**，用了几十年，然后**没有事可做**。
这不是"他们没想到"，这是"做出来之后发现了下一个更难的问题"。
项目给出的差异点（"脐带接通"）恰好需要旧世界持续愿意把真任务送进来——而这需要旧世界认这个世界的接口。

**解释六：它其实正在被做，只是以项目拒绝承认的形式——都在"腰部保持窄"的约束下。**
Kubernetes（声明式期望状态 + 控制器）、CRDT/OT 协同（如 Automerge）、事件溯源/CQRS
（EventStoreDB、Axon）、Matrix 的状态解析与 `/sync`、Home Assistant 的实体模型、
Nix 的 store 派生图——**都是"一份真相 + N 个只读投影"。**
它们全都在"语义"这一步主动刹车。`2-依据/13` 末段自己登记了"第三路（状态与事件底座）"
**在定稿时仍在进行、尚未并入**——**这是我的推断**：那一路的结果，恰恰会证明"航站楼"已被
部分建造，只是分散在若干名字下。

#### 攻击成立的条件

这条攻击成立当且仅当：**这个缺口有非愚蠢的解释**。上面给了六种，其中解释五、六是**项目自己
提供的证据**。只要有一种成立，"没人做"就从"机会"退化为"警报"。

#### 它若想活下来必须做到什么

给出**一个可证伪的差异点，并把它写成淘汰赛**：不是"没人做过"，而是
**"我们做过 X 实验，证明在腰部保持窄的前提下这件事做不到；而我们找到了一个能保持窄的做法"**。
具体到工程：
1. 在 `2-依据/13` §四 的覆盖矩阵旁，加一列"**为什么它们主动选择不做**"——逐件写，
   不许写"没想到"；
2. 选上面"解释六"里最像的一件（我建议 **Kubernetes 的期望状态模型**或 **Automerge/CRDT**），
   用**同一个真实任务**在两边各实现一次，逐项对照"哪一步在对方那里做不到"；
3. 做不到就等于这条缺口判断被否证——**必须允许这个结论出现**。

### 攻击 2 ·「换轨即拆楼」是一个自我实现的预言

**原主张引用**（`00-总纲.md` §2.2「存」的判断标准，第 109–110 行）：

> **判断标准**：**不用载体快照，能否回滚一次改动。** 这是全系统最承重的一条——
> 换轨时只有它不能靠"换插座"解决（image 若建在载体的文件/快照抽象上，换轨就是拆楼）。

配套论证（`00-总纲.md` §8「换轨触发条件」；§2.1 最强反驳的幸存者写入；`2-依据/09` §二）：

> ② §6 中某项能力在 Linux 上被证明**不可满足**；③ 目标载体**通过 §6 能力列的验收**
> ——不是"更优雅"，是"挡住了"。

#### 我的攻击：这条论证在结构上是自证循环，且它的判据在实现层已被自己的做法违反

**（a）循环是这样闭合的。**
- 判据 A（§2.2）：世界的持久化**不得**建立在载体抽象上 → 自建存储通过，任何"建在宿主"的方案失败；
- 判据 B（§2.1）：可换性 = 一个**必须被工程保证**的性质，兑现物是"载体适配层"（动作 8）→
  只要造适配层就算兑现；
- 判据 C（`2-依据/09` §二）：锚定 vs 依赖 → "本体用 MCP 方言"判锚定（拒绝），
  "LLM 算力"判依赖（接受）。

C 的判决标准是"**接口在不在自己手里**"。于是一旦把某个候选判为"接口在别人手里"，
它就同时被 A 否掉、"自造"就被 C 推为唯一幸存者。**每一次判决都在为"自造"增加胜率，
而"自造"本身从未被任何判据单向检验过。** 三个判据互相担保，没有一个是外部锚。

**（b）兑现物从未被验收，而且被判为"不做"。**
`00-总纲.md` §12 待批判 6 自首：

> **`载` 的首要判据是个软条件**——"可开发性"（跑得动什么算够）**未量化**：
> §11 动作 8 只检查"不出现 Linux 特有系统调用"，没有回答"跑得动编辑器与浏览器"怎么算达标。
> 这条不量化，选型与换轨都会被自我豁免。

`00-总纲.md` §11 动作 8 的判据是：

> [ ] 世界核心的代码里**不出现** Linux 特有系统调用（`clone` / `epoll` / `btrfs` 等）——即：接口薄到能替换

**实测反驳（本席亲验）**：`world-core/src/channel.rs:180-218`（`UnixListener::bind` + `chmod` +
`chown` + `IntoRawFd::into_raw_fd`）、`src/guard.rs:44-89`（`PermissionsExt::mode` + `0o022`）、
`src/channel.rs:9-10`（`peer_cred()`）、`src/ledger.rs:67`（`sync_data`）——
**全是 Linux/Unix 特有系统调用**，且都在"世界核心"里，不在适配层里。
`00-总纲.md` §11 动作 8 的判据今天**不成立**。

**（c）最贵的一句在后面。** "载体适配层"的效果不是"薄"，而是**把不变性从系统里删掉**：
一旦世界只经薄接口调用载体，**任何契约都必须是世界自己的**，于是"能不能换轨"这个问题
**永远无法在真实载体上被回答**——因为没有第二个实现，也没有被测量的差异。
这不是我编的：`00-总纲.md` §8 的换轨触发条件 ② 要求"某能力在 Linux 上被证明**不可满足**"，
但"证明不可满足"没有定义（谁判、什么算证明、几次算成立）；条件 ③ 要求"通过能力列验收"，
而能力列本身未量化（§12 自首 6）。**两个触发点都是不可判定的，所以"自造"是唯一永远存活的选项。**

**（d）"拆楼"的责难其实指向了一个无人验证的假设。**
"image 若建在载体的文件/快照抽象上，换轨就是拆楼"——这句话假设了
**换轨的首要成本是数据迁移**。但对一个还没有任何用户的系统，**真正的换轨成本是重写代码与重建生态**，
数据迁移在 6 591 行规模下是小头。**这是我的推断**：这条论证把一个尚未被测量的问题
（换轨成本分布）当成了已被证明的前提，然后用它淘汰了所有备选方案。

#### 攻击成立的条件

成立当且仅当：**"自造"没有被任何独立判据检验过，且备选方案的失败理由全部来自同一套判据。**
实测（b）（c）已给出：兑现物未验收、触发点不可判定。**攻击成立。**

#### 它若想活下来必须做到什么

1. **把"自造 vs 借用"变成有成本的对照实验，而不是有判决的分类**：
   用**同一个单元**（建议就是"回滚一次改动"）各写两份实现——一份建在 SQLite / 宿主快照上，
   一份建在世界核心账本上；**实测两边的代码量、回滚延迟、崩溃恢复正确率**，
   公开哪一边在哪个数字上更差。
2. **删除"锚定 vs 依赖"作为淘汰判据，改作风险登记**：它只能用来标注风险等级，
   不能用来否决方案——否则它永远只会否决别人的方案。
3. **把动作 8 判据改成可执行的**：今天它是"不出现 Linux 特有系统调用"，而实测已违反。
   建议改为"**换轨演练**"：在第二个载体（哪怕是一个只提供 POSIX 子集的 shim）
   上跑通 `00-总纲.md` §11 动作 7 的全部五项验收；跑不通就是没兑现，没得商量。

### 攻击 3 ·「内容相关 vs 内容无关」——"自己承担意义"在实现层是空的

**原主张引用**（`00-总纲.md` §2.2 的"幸存者写入"，第 113–115 行）：

> 但"工程常识"的反驳**不成立**：常识是在**应用层**做，这里要求在**本体层**做——
> 差别在于换轨时谁付迁移成本。

（`00-总纲.md` §10 文档地图把 `2-依据/15-世界核心的组成与职责.md` 记为
"**内容无关 vs 内容相关**、主线与管道"的落点——该篇本席**未能读到**，故本条攻击只针对
`00-总纲.md` 与实现层可核对的部分，凡涉 15 篇原文的推论均标注为推断。）

#### 我的攻击：让基础设施承担意义的每一次成功，承担的都是**结构**，而项目把"结构"误读为"不够"

**实测证据（本席亲验，杀伤力最大的一条）：**

`ontology.json`（全文 1 928 字节）是这个世界全部的"本体"。它的 `concepts` 段写着：

```json
"concepts": { "notice": { "fields": { "muted": "bool" } },
              "job":    { "fields": { "status": "enum(todo,doing,done)" } } }
```

**实测：`concepts` 在 `src/` 里零命中。** 唯一提到它的是
`tests/acceptance.rs:733`（`raw["concepts"]["job"]["fields"]["status"] = ...`）——
即**用例通过改词表来验证"词表变则 hash 必变"**，而不是验证概念是否被遵守。
`00-总纲.md` §11「动作 1」判据却写着"五个概念各有 schema 文件"、"`版本历史` 字段存在"。

而 `src/ontology.rs::validate` 的全部违规只有四种（本席实测 `Violation::` 去重）：

| 违规 | 含义 |
|---|---|
| `NotAnObject` | 事件不是 JSON 对象 |
| `MissingField` | 信封或信纸**缺一个键** |
| `UnknownKind` | `kind` 不在三类家族里 |
| `BadVersion` | `world` 版本号不符 |

**没有字段类型**（`"bool"`、`"integer"` 是字符串注释，不是可执行断言）、
**没有值域**、**没有量纲/单位**、**没有跨字段一致性**、**没有引用完整性**。
`2-依据/13` §四 自己定的目标——"判据是**每条消息自带 schema 版本 + 语义类型 + 单位/量纲**"——
**在实现里一条都没有。**

再看"语义能力名"到底是什么（`cap.d/` 全部三个文件，本席逐字读过）：

| `cap.d` 文件 | `provider` | 实际动词 | 它到底是什么 |
|---|---|---|---|
| `notice.mute.json` | `backlight` | `get` / `set` | 写 `/sys/class/backlight/*/brightness` |
| `ledger.compact.json` | `package` | `list` / `install` | **包管理器安装** |
| `job.start.json` | `job` | `start`/`status`/`list` | `spawn` 一个进程 |

`notice.mute.json` 的注释自己也承认："**注意能力名用语义层的名字**（notice.mute 对应世界里的
『静音一条通知』），不是设备名。"——**这是一次重命名，不是一次语义建模。**
"静音一条通知"与"调低屏幕背光"在实现里是同一件事，而本体对此**无话可说**
（`concepts.notice.fields` 只声明了 `muted: bool`，且无人读它）。

**结论（这是我的推断，但推断的每一步都有实测支撑）**：
"世界核心自己承担意义"在**架构图上成立、在代码里不成立**。
它实际承担的是**信封形状 + 主体白名单 + 能力名词表**——
这三样恰好就是 `2-依据/13` §一 所归类的外部协议已经做的事
（"能力协商 + 工具定义 schema"）。**它比 MCP 多的不是"语义"，是把 RPC 的动词搬到 JSON 字段里。**

#### 那么会不会"注定失败"？——答：不会注定，但会退化成下面这个东西

**意义来自使用者的约定，不来自基础设施**——这条通常的反驳方向是对的，但**太粗**。
精确的版本是：**基础设施可以承担"结构"，无法承担"约定"**；
而"结构"恰好是 LSP 的胜负手（它定义了位置/符号/诊断，让所有语言服务都能被同一个编辑器驱动）。
项目的错误不是"想承担意义"，而是**用"承担了约定"当旗号，交付了"承担了形状"**。

于是它退化的形态是可以精确预测的——**这是我的推断**，但两条路都被现有代码指向：

**退化路径甲：变成"个人机配管理器的审计日志"。**

**这门"评审 + 门禁"的机器，反复宣布它无法交付自己承诺的东西。** 四处实测：

四处**没有一处是文档写少了**，四处都是**文档写多了**：宣布得越细，越没人回头核对。
这就是"文档体量"作为失败征兆的**真实机制**（**这是我的推断**）：

> 这套流程在**为验收生产凭证**，但凭证的完备性**不蕴含**被验物的存在性。
> 一份自洽的契约可以描述一个不存在的东西——而"自洽"恰好是唯一能从内部检查的性质。

**更贵的一层：验收人 = 作者。** `WC-RV-R5-001-v0.1.md` 开头自己写着
"**记录人 ＝ AI（DeepSeek Harness）**：可代写、**不可代签**"，

由同一个执行者核对、结论栏与签字栏留空。四份文件的签字栏里 **项目负责人、技术负责人、
质量负责人、配置管理员没有一个人签过字**。**这是我的推断**：整个评审体系目前是
**九个席位的自我确认**，它的独立性来自"分了席"，不来自"分了人"。
`00-总纲.md` §11 的反自我豁免条款写得很对——"每条判据必须由脚本执行，
或由非作者的人执行"——**而它至今没有"非作者的人"。**

#### 攻击成立的条件

成立当且仅当：**文档的增长速度显著高于交付物的落地速度，且验收者与作者同一。**
实测四处"已宣布未落地"+ 签字栏全空。**攻击成立。**

#### 它若想活下来必须做到什么

1. **量一个比例，而不是量体量**：取最近 N 次文档改动（`WC-CR-*`、`WC-RV-*`），
   统计"**改完后代码必须跟着改**"的比例。若这个比例低于某个自定阈值（我建议 1/3），
   说明文档在**尾巴**上而不是在**头**上——立刻停止新增评审件，只允许修已有件。
2. **把审查机器从"生产文档"改为"生产拒绝"**：门禁的产出应当是
   **一份会红的清单**（哪些宣布项没落地），而不是一份会绿的结论表。
   今天 `WC-RV-R5-001` §4.2 已经展示了正确形态——"全库 76 件受控文档，通过 75 件、失败 2 处"，
   **并且没有顺手修**（理由写得极好："顺手修会让'签署对象 = 当时那一版字节'这条约束当场失效"）。
   **这一段是本仓库最健康的做法，应当推广到全部宣布项。**
3. **首次引入"外部验收者"**：只需一个人、一件事——请一个不参与本项目的人，
   按 `00-总纲.md` §9 的起手式（一页纸本体 + 手工推演一个任务）独立走一遍，
   记录他在哪一步卡住。**这是这个项目从"私人语言"变成"语言"的唯一入口。**

### 攻击 7-A ·（项目未承认的弱点之一）唯一写者的身份链终点是**明文 JSON + 文件模式**

**这不是"还没接 Landlock"的重复。** `系统全景图.md` §五 ⚠️ 第 2 项承认的是
"未接 Landlock / seccomp"，项目把它读作"强度还差一档"。
**我的攻击不是"差一档"，是"链条不闭合"**：

1. **身份映射是数据，不是世界**（实测 `src/channel.rs:61`/`:101-111`：`Listener{ socket, actor, uid }`
   来自 `channel.json`）。也就是说：**"谁是世界的主人"这件事，由一份世界之外的、
   由部署方手写的文件决定**，而它不受账本约束、不进事件、不可版本化、无变更留痕。
   世界的"唯一真相"里没有"身份"这一格——而身份是所有授权的前提。
2. **身份与模式的保护是两套独立机制**：mode 位（`src/guard.rs`）保护不了"文件内容被正确填写"；
   而 `--owner-uid` 是**可选**的自我断言（`src/guard.rs:130` 注释逐字：
   "⚠️ 它是**部署方的自证工具**，不是自动安全机制：没人传 `expected_uid` 时它不会运行"）。
   `deploy/README.md:68` 传了，`00-总纲.md` §11 与 §2.4 都没要求必须传。
3. **CLI 默认最高特权**（`src/main.rs:338-341`，见攻击 4(c)）——这是身份链的**第二个出口**，
   比通道更宽松，且**不需要任何身份**。

**论证**：一个系统的"唯一写者"性质，其强度等于**通往写入口的所有路径中最弱的那一条**。
现在有两条路径：通道（靠 uid + JSON）与 CLI（无身份要求）。
而 `00-总纲.md` §2.4 的判断标准是"**一个越界声明能否被拦下**"——
**"越界"的定义必须先有"界"，而界的定义权在系统之外。**
故这条性质目前**不可证**，不是"不够强"。

**它若想活下来必须做到什么**：把身份搬进世界——
`channel.json` 的每一行都对应账本里一条 `change` 事件（谁、何时、把哪个 uid 绑到哪个 actor），
启动时**逐条重放并核对**；不一致即**拒绝启动**。
这样"谁是主人"就成了世界自己的事实，账本的不可变性才真正覆盖了权力。

### 攻击 7-B ·（项目未承认的弱点之二）事件身份用墙钟，而世界没有时间权威；本体版本被冻死

**（a）身份与时间同源。** 实测 `src/event.rs:69-73`：

> `/// 事件身份。不引入 uuid crate：**纳秒 + 进程内计数器**已足够唯一。`

`new_id()` = `format!("e{}-{}", unix_nanos(), c)`，其中 `c` 是**进程内** `AtomicU64`
（`src/event.rs:21`），`at` 字段是 `unix_secs()`（`src/event.rs:103-107`）。
`ontology.json` 自己写："`at`: integer # 时间戳，Unix 秒。**顺序由 seq 决定，at 只作辅助**"。

**问题不在"够不够唯一"，在"它是什么"**：
1. **`c` 在进程重启后归零**——`e<nanos>-0` 的唯一性完全押在墙钟上。
2. **墙钟可回拨**（NTP、虚拟机暂停/恢复、容器迁移、手动改时区）。
   回拨后重启，第二条事件可能拿到与旧事件**相同的前缀**；虽然纳秒精度降低了概率，
   但**没有任何机制检测或拒绝**这种情况——`src/ledger.rs:291-299` 只查 `seq` 连续与 `id` 去重，
   而"去重集"是**进程内 `HashSet`**，跨启动不会累积。
3. **世界没有时间权威**：`at` 是本地墙钟，没有单调查询、没有单调性断言、
   没有"时间倒退则拒启"的守卫。而对一个自称"可问责"的系统，
   **"谁在何时做了什么"里的"何时"目前是一个不可信、不可验、可回拨的数字。**
4. 更微妙的一层（**这是我的推断**）：`seq` 是唯一的全局序，而 `seq` 由**唯一写者**分配。
   这意味着世界的**因果序是写者的调度序**，不是事件的发生序。
   在"意图先于执行"这个具体场景里（`系统全景图.md` §二），
   真实世界里的"执行"发生在两次落笔之间——**账本里看不到这段时间**。
   项目把它当成优点（"意图先于执行、因果闭合"），但它同时也是
   "账本无法表达并发"的同义语。

**（b）本体版本被冻死。** 实测 `src/event.rs:15-19`：

```rust
/// 出厂词表版本。**只加 flags，永不改这个数的含义**。
pub const WORLD_VERSION: u64 = 1;
/// 已定义的能力旗标。未知旗标**必须忽略**（本体纪律）。
pub const FLAGS: [&str; 0] = [];
```

`FLAGS` 是**空数组**。`2-依据/13` §五.3 定的纪律是"**永不升版本号，只加 flag**"，
`WC-RV-R5-001` §三 `R5-D` 又把"词表变更的兼容性档位"登记为**待人裁**。

**论证**：`ontology.json` 里 `concepts` 的值域写成字符串
（`"enum(todo,doing,done)"`）而非可执行断言，所以**任何语义变更都无法与旧变更区分**——
`vocab_hash` 会变（`src/ontology.rs` 的用例证明"改语义必须换词表"），
但 `WORLD_VERSION` 仍写 1，而 `BadVersion` 只在 `world != 1` 时触发。
**结果**：一个三年尺度的账本**必须持续被一份会变的词表解释**，而解释它的规则
**要么是"只加不改"（则本体永远不能修正——这在一个声称"判据会移动"的理论里是自相矛盾）**，
**要么是破坏性变更（则旧账本不可读，唯一真相不可读）**。
项目在 `2-依据/09` §四 给寄主期设了退出条件，却**没有给"本体的第一次修正"设任何机制**——
而 `00-总纲.md` §5 第 4 条铁律恰恰是"**本体公开且版本化**"。

**它若想活下来必须做到什么**：
1. 事件身份改用不依赖墙钟的构造（`(boot_id, 计数器)` 或"账本内 `seq` + 写者身份"），
   并在 `check` 里加一条"**时间倒退 ⇒ 拒启**"的守卫；
2. 把 `at` 明确降级为"**提示，不可作判据**"，并在 `ontology.json` 与判据件里同步改口径
   （今天写的是"只作辅助"，措辞太软）；
3. 在 `WORLD_VERSION` 之外引入**真正的本体版本与迁移事件**（一条 `change` 事件声明
   "词表从 hash A 变为 hash B"），并写一条会红的判据：
   "**用新本体读旧账本、或用旧本体读新账本，必须各自给出确定行为（拒绝或降级），不得静默**"。

## 四、总问题 A / B / C

### A. 这个理念还缺什么？—— 缺**一条能让它不至于自嗨的外部约束**

**它缺的不是理论、不是文档、不是判据，是"外人"。**

`00-总纲.md` §11 的「反自我豁免条款」已经写对了一半："每条判据必须由脚本执行，
**或由非作者的人执行**——作者自己说'通过了'不算通过。"
**而从 R0 到 R5，这个项目从来没有第二个执行者。**
`WC-RV-R5-001` 的九席由同一轮生成，签字栏四个角色全空；
`WC-RV-R0-001` 有 1.26 MB 的篇幅，但没有一行来自一个需要为结果负责的人。

所以我建议的那条外部约束，具体是一件**可执行的事**，不是一句原则：

> **单一外部约束：任何"已通过"的结论，必须附带一个由非作者身份执行、
> 且执行脚本由非作者编写（或至少由非作者修改过一处）的可复现命令。**

这条约束的效力来自它的**可证伪性**：它把"自证"和"他证"变成两个不同的字节产物，
而差的那些字节会立刻暴露——今天按实测，四处宣布项会当场变红
（`LICENSE`、`docs/证据/`、30 天保留窗、动作 8 的无 Linux 系统调用）。

**附带缺的第二样（同样具体）：缺一个"失败的定义"。**
`00-总纲.md` §7 写了三条停机线，但**没有一条是可判定的**——
"连续三次尝试仍做不到"（谁数？）、"超过开工前预设的工期"（预设是多少？从未写）、
"世界内工具不可用"（不可用的判据？）。**这是我的推断**：
一个没有可判定失败条件的项目，**不能失败，因此也不能成功**——
它会无限期地停留在"正在收敛"的状态里，而 4.7 MB 的文档正是这个状态的沉积物。

**第三条（我把它放在 A 里，因为它比 B 更像"缺"而不是"改"）：缺"时间"这一维。**
`00-总纲.md` §2 的五概念是**载 / 存 / 传 / 管 / 显（+进）**——
**没有"时"**。而这个世界的一切主张都建立在时间上：
"谁在何时做了什么"（可问责）、"监督位随时间衰减"（核心动力学）、
"判据会移动"（`2-依据/09` §五）、"保留窗 30 天"、"人离开 24 小时"。
**一个把时间当辅助字段（`ontology.json`："at 只作辅助"）的世界，
无法表达"这件事过期了""这个授权失效了""这个判据移动了"——而这三件事是它全部理论的地基。**

### B. 怎么把它丰富起来？—— 四条**能证伪的检验**（不给安慰性建议）

**检验 B-1 ·「外部语义侵入」——用来证伪"本体在承担意义"。**
请一个非作者的人（或另一个与被测 agent 无共享上下文的 agent），
用现有本体表达 **3 个他不熟悉的领域的真实任务**（例：报销一张发票／预约一次门诊／
退回一件商品）。判据：**必须新增的能力名数量 = 0**。
每新增一个记一次本体缺口。**今天预测：≥ 6 个（三个任务各约 2 个）。**
这个检验直接打击攻击 3。

**检验 B-2 ·「同 uid 对抗」——用来证伪"门禁不可绕过"。**
以与 `world-core` 相同 uid、与 agent 相同 uid 两种身份，各做三件事：
① 直写账本；② 改 `policy.json`；③ 换 `cap.d`。

**检验 B-3 ·「三年加速」——用来证伪"语义事件唯一真相"的运行代价。**

### C. 外部现有系统为什么不好用？—— 先承认它们好在哪，再说它们为什么仍不够

**先反着答：外部系统在下列方面**明确地比这个项目好**，而且这些优点不是运气，是设计。**

| 方面 | 外部系统为什么更好 | 具体证据 |
|---|---|---|
| **成熟与容错** | Linux 的权限、cgroup、namespace、seccomp、Landlock 是**几十年对手攻击下成型**的；文件系统的崩溃一致性经过无数次掉电考验。这个项目的账本有一条自承认的边界："整本重写**检不出**"（`系统全景图.md` §五 ⚠️ 第 7 项，用例名 `c18_chain_cannot_detect_a_full_rewrite`） | 对比：`00-总纲.md` §6「载」自己写"需接受一个能力天花板：**吊销不能即时生效**"——外部系统至少把**能做的**做到了极致 |
| **生态** | MCP/D-Bus/varlink/LSP 的"生态"不是指人多，是指**接口不用重新发明**：现成的客户端、调试器、日志工具、语言绑定。项目自订的第一条纪律就是"协议的命名空间里**不出现** `browser.*`/`varlink`/`mcp` 字样"（`00-总纲.md` §11 动作 3） | 这意味着**每一个工具都要为它重写一次** |
| **性能** | Kafka/NATS/Redis 的事件吞吐是数百万/秒量级；而这个项目**每条事件一次 fsync**（`src/ledger.rs:67`）且**打开即全量重放**（`src/ledger.rs:268-299`）。`2-依据/13` §三.3 引用 Kafka 的"重运维"作为不采用的理由——但**不采用它的运维，也就没有得到它的吞吐** | 项目在 `tests/perf.rs:335` 自己写"耗时旁证（**非判据**）" |
| **可雇人维护** | Rust/Linux/systemd/JSON 是**招得到人的技能**；而"一个自定义语义本体 + 一套自定义能力表 + 九册接口契约 + 76 件受控文档"是**招不到人的技能**。`00-总纲.md` §8「存/传/管/显」的理由栏只有四个字："**没有供应商**"——这句话是双向的：**没有供应商，也没有维护者** | —— |
| **诚实** | 成熟系统的边界是**用血写下来的且众所周知的**（"POSIX 不保证这个""Kafka 不保证那个"）。而这个项目的边界写在 4.7 MB 里，而且**同一份需求件的两条约束互相排斥**（`DR-07` 30 天 vs `DR-11` 不设保留窗） | 对手攻击一个已知边界清晰的系统，比攻击一个边界散落在 75 份文档里的系统难得多 |

**然后：这些优点，在"语义"这件事上为什么最终仍不够？**

**不够的地方只有一处，但它是真的**——而这处不够**不是**项目以为的那处：

> **外部系统能证明"谁在何时做了什么"（可问责性），没有任何一件能证明"这件事是什么意思"。**
> 而"意思"恰恰是**监管、赔偿、追责**真正要的东西。

举例（**这是我的推断，但每一步都可由项目自己的材料支持**）：
一份 MCP 工具调用日志可以证明"agent 13:04 调用了 `delete_file('/x')`"。
它**不能**证明"这次调用是在'把 X 做到 Y'这个目标下、由谁授权、不可逆性几级"——
因为 MCP 规范自己说 "protocol itself cannot enforce these security principles at the protocol level"
（`2-依据/13` §三.1 引用 MCP 原文）。
D-Bus 的授权边界原文更直白："the dbus-daemon's policy language is **not well-suited to
finer-grained policies**… expressed in terms of D-Bus interfaces and method names,
**not higher-level domain-specific concepts**"（`2-依据/13` §三.2 引用 D-Bus 原文）。
**这两段原文是这个项目最有力的外部依据，而且是它自己找到的。**

**但请注意这句话的准确形状**：外部系统不够的地方是
**"缺少一层把动作与意图、授权、不可逆性绑在一起的公共记录"**——
这正是项目说的"可问责性"。**而项目宣称自己多做了"意义"这一层。**
两者的差别是全部胜负所在：
- 前者（可问责层）**有外部先例**（审计系统、SIEM、区块链账本、Kubernetes 的审计日志 +
  Admission Control），**且项目能真的做出来**；
- 后者（意义层）**没有外部先例**，而 §二 攻击 3 的实测显示**项目也没有做出来**
  （`concepts` 无人读取、校验只有形状）。

**所以我的答案是**：外部系统不好用是真的，但它们不好用的地方，
**比这个项目自认为的窄得多**——窄到"审计 + 门禁 + 回放"这三个词就能说完。
项目在 `00-总纲.md` §8 用"没有供应商"四个字把这一层说成不可购买，
**但 Kubernetes 的 Admission Webhook、OpenTelemetry 的语义约定、OPA/Rego 的策略引擎、
Sigstore 的签名链，都是"可问责性"这一层的现成供应商**——
它们只是**没有把它叫"世界核心"**。
**这是我的推断**：项目最有价值的部分，恰好是它最不愿意承认自己是在重做的那部分；
而它最独特的部分（本体承担意义），是它唯一没有做出来的部分。

## 五、给项目负责人的三句话

**第一句（先做哪一件事）：先做一个"外人"，不要先做任何一行代码或一份文档。**
找一个人——不是 agent，不是另一个会话，是一个你不控制其结论的人——
给他 `00-总纲.md` §9 的起手式（一页纸本体 + 手工推演一个任务），
**记录他在哪一步说"我看不懂这个动词是什么意思"**。
`2-依据/08` §五 自首 3 已经把话说到了："**不兼容路线的历史胜率极低，需明确'这次为何不同'**"——
而"这次为何不同"的答案不可能从内部产生。**在这件事做完之前，其余一切都是在为一个
尚未确认存在需求的语言编写语法书。**

**第二句（先砍哪一件事）：先砍掉"过程文档"的继续生产，只保留"会红的清单"。**
实测：75 份文档 4.71 MB 对 25 个文件 361 KB 源码；R0 单件 1.26 MB；
而四件被宣布"已落地"的交付物（`LICENSE`、`docs/证据/`、30 天保留窗、动作 8 判据）
当场对账为**未落地**。**这四件不是"文档写得不够"，是"文档写得太好"。**
砍掉它们的**写法**：每一份新的评审件只允许有一个产出——
**一份机械可核的、今天为红的清单**。`WC-RV-R5-001` §4.2 已经做出了正确的样子
（"全库 76 件受控文档，通过 75 件、失败 2 处"，**并且不顺手修，只登记**）——
**把那个形态复制到全部宣布项上，然后停止新增件。**

**第三句（先验哪一个假设）：先验「语义」这个假设，不要先验账本。**
账本已经写好了，它不会告诉你这个项目能不能活。
**要验的假设是**：`ontology.json` 那 1 928 字节（其中 `concepts` 只定义了
`notice.muted: bool` 与 `job.status: enum(todo,doing,done)`，且**没有任何生产代码读它**）
**能不能表达一个真实的人真正想做的事**。
验法就是检验 B-1：请非作者用现有本体表达 3 个他不熟悉的领域的真实任务，
**要求新增能力名数量 = 0**。
**如果这个数字大于 3，那么"世界的本体"就只是一个人给自己设备起的别名**——
那么 `00-总纲.md` §2.2 里那句"常识是在**应用层**做，这里要求在**本体层**做"，
与 `2-依据/14` 的"语义事件是唯一真相"，都需要被重写成它们真实的强度：
**"信封层 + 能力名册 + 审计账本"。**
那仍然是一个值得做的东西——**但它不是世界核心，它是一份很好的审计与门禁件。**
把名字改对，比把文档写厚，重要得多。
