## 一、评审结论

**一句话**：这套理论的哲学骨架在"从概念到工程"的路线上是罕见的清醒，但它最硬的三条主张——**监督衰减**、**行动/事件二分**、**预案分级**——分别犯了"经验命题冒充分析命题""描述层次混淆""规范权威自我授予"三类错误，其中一条已被它**自己的工程设计反向证伪**。

要点：

1. **§三"依赖与监督互斥"是把一条经验相关式说成了准分析命题**，而它自己承认的"工程补偿"恰恰是这条命题的反例（见 §二·4）。
2. **§5.2/§5.3 的"行动 = 有意向的事件"混用了描述层次（Anscombe）与事件本体（Davidson）**，并把"只有行动者才能被归责"这个未经论证的实质前提偷渡成定义（见 §二·2）。
3. **工程落地已经违反了理论自己的核心判据**：`policy.json` 按**主体身份**（`irreversible_actors`）而不是按**动作类别**划定不可逆性，而唯一被免检的主体（`world://user`）恰好是唯一有权限执行全部三个不可逆能力的那个（见 §二·2 与 §三·新问题 3）。这是全套理论最严重的一处 **theory–implementation gap**。
4. **§10.2 的判据测的是形式分布而非实际权力**，四种规避方式即可通过，而判据自身的版本化与解释权留在建造者手里（见 §二·5）。
5. **§10.4 不是理论结论而是云适配的权宜之计**，代价是切断了本项目"积累经验"的能力——而它本可以用"账本 + 模型行为"三分来救（见 §二·6）。

## 二、逐条检验

### 主张 1｜"Agent = 责任结构未定型的拟受托造物"，本体层是"可替换流水线"，边界层"可替换是本质属性"

**原文引用**

- `00-理论定稿.md` §1.1：「**本体**｜软件制品：**可替换流水线**（模型 + 工具 + 状态），每次会话实例化，零件分属不同所有者」；「**边界**｜无物质边界，只有功能边界——"它" = 此刻正替这次任务运转的那条流水线；**可替换是本质属性，不是事故**」。
- `00-理论定稿.md` §5.3：「归责 = 落在**把事件组织成行动形状的人**」，「落在**设计意图的植入者（厂商）**与**任务的发起者（使用者）**」。
- `00-理论定稿.md` §10.3：「共同致错**总是落在单桶里**，不需要比例切分」。

**它成立吗：** 作为**法律—制度**主张勉强成立；作为**形而上学**主张不成立。二者被该文混用，这才是问题所在。

**论证**

1. **"可替换"与"承担者"能共存，但只在放弃意向性主张之后。** 我的推断是：只要把责任理解为**严格责任 / 替代责任 / 产品责任**式的、附着于 **角色与许可** 而非 **意志** 的规范关系，"分属不同所有者的可替换零件"完全可以有责任承担者。公司法上的替代责任（respondeat superior）几百年来就是这么运作的。所以主张 1 本身没错。它错在**同时**主张 §5.2 的意向性形而上学——那套形而上学要求的责任承担者必须有意志，而可替换流水线没有。**两条主张不能同时为真**，而文本同时要。
2. **"那个人"到底是哪一个？** 按 §5.3 自己的判据（"把事件组织成行动形状的人"），在一条真实执行链上（模型权重 → 厂商策略 → 系统提示 → 使用者目标 → 当次输入 → 工具调用 → 载体执行），符合"组织成行动形状"的主体**至少有三个**：厂商（设定目标函数与禁止空间）、使用者（设定目标与授权）、以及**建造者**（提供本体、词表、门禁，即"什么叫合法形状"本身）。**这是我的推断**：文本只承认前两个，第三个被漏掉——而漏掉第三个有直接的利益相关性，因为 §1.3 自己说「本理论工作也是一股定型力量」。
3. **"单数的那个人"在强依赖情形下没有指称对象。** 文本自己在 §三说监督衰减、在 §四说「人必须先监督才能知道哪里需要监督」，即承认使用者的控制是残缺的。若使用者的控制残缺，"发起者的有效控制"就不成立；此时真正组织行动的**是厂商**（默认配置、能力清单、风险分级都出自它）。文本对此没有交代。
4. **§10.3 的两步法在法理上是错的。** 「合理可预见的使用范围」与「充分告知」是**侵权法**概念，与"把事件组织成行动形状"毫无关系——即 §5.2 的形而上学在这里一次也没被用到。而「共同致错总是落在单桶里」被**比较过失（comparative negligence）、共同过失（contributory negligence）、市场份额责任（market-share liability）**直接反驳，这些都是常规法律工具，不是例外情形。文本把"合理可预见"的二值判断当成能切开连续归责的技术，并且在它失效时（新技术首次出事）立刻推给保险池——这正是最需要它的时候最不管用。

**若采纳，改法**

- 把 §5.2 的意向性形而上学**降级**为描述层次问题（见主张 2 的改法），把归责标准从「贡献度分摊」换成 **否决点—补救成本** 双判据：
  - **否决点地图**：对每一个不希望的后果，列出在**事前（规则设定）/ 事中（阻断）/ 事后（补救）** 三个阶段各自**实际**持有有效否决权的主体（不是名义上的，是能单方面阻止或逆转的）。
  - **补救成本归属**：责任落在**有能力以最低成本补救该后果**的一方（这是 Caldor–Hicks 式的效率论据，须显式声明它引入了福利标准，而不是"贡献度"这种无法度量的东西——`03-规范地基.md` §六 自己承认「贡献度如何度量，未给出可操作标准」）。
- **把"建造者"作为第四归责主体写进 §5.3 的表**，并给它与厂商同一档的举证责任。不写这一条，§1.3 的自我认罪就是无效的。
- **删掉"总是落在单桶里"的"总是"**，改为"在判例成型后**多数**落在单桶；成型前一律按保险池处理"。

### 主张 2｜"行动 = 有意向的事件；事件 = 单纯发生"，Agent 的 exec"结构上有意向的形状，来源上无意向的地位"

**原文引用**

- `00-理论定稿.md` §5.2：「**行动** = 有意向的事件（可归责于行动者）；**事件** = 单纯发生（只能追因）」；「Agent 的 exec：**结构上有意向的形状**（有目标指向），**来源上无意向的地位**（目标是植入的）」；「对应物是工具的"倾向"（刀"想要"切割，是拟人说法）」。
- `03-规范地基.md` §5.2 同文。

**它成立吗：不成立。** 这是**全套理论最薄弱的一环**，我把它列为"最危险的主张"（见 §五）。

**论证**

1. **对 Anscombe 的检验。** Anscombe（*Intention*, 1957, §§5–9）的判据不是"事件里有没有意向"，而是**"为什么不？"这个问题是否在该描述下适用**（the question "Why?" in the sense that requires a reason），其适用条件是三条：行动者知道自己在做什么、这个知道**不是**基于观察、且该问题的回答**不是**一个因果解释。**关键后果**：行动性是**描述相关的（under a description）**。同一个物理事件可以是"我伸手""我打翻了花瓶""我打碎了祖母的遗物"——意向性归于**描述**，不归于**事件**。因此行动的**反面不是"事件"，而是"非行动的描述"**（事故、反射、被推动）。
2. **对 Davidson 的检验。** Davidson（*Essays on Actions and Events*, 1980）的主要工作恰恰是**把行动还原为事件**（actions **are** events），再给"意向性"一个因果解释（pro-attitude + belief 作为原因）。所以 **Davidson 的结论与 §5.2 的结论方向相反**：Davidson 说"行动是事件"，不是"事件分两种"。我的推断是：§5.2 把"行动 vs 事件"当成**两类存在物**，这是把 Davidson 的结论反转过来用，并且**偷了他的权威**。
3. **Agent 的 exec 因此陷入两难。** §5.2 说它"结构上有意向的形状"——**结构**显然不是意向性，这是把**合目的性（teleonomy）**说成**意向性（intentionality）**。一个被设定的目标函数是目的论的，不是意向的：意向性要求**表征**且**表征的正确性对主体有意义**。若"有目标指向就能算有意向的形状"，那么恒温器、趋光细菌、导弹制导全都有"意向的形状"。文本显然不想要这个结论，但它没有给出任何能挡住恒温器的判据。**这是我的推断**：§5.2 的"结构/来源"二分不是区分（distinction），是一个**没有判据的措辞**。
4. **工具类比的论证方向是反的。** 「刀"想要"切割，是拟人说法」——这句话的作用是**用类比消灭顾虑**，而不是给出论证。刀之所以没有意向，是因为刀**是**功能种类，其功能外在于其物理构造。但 LLM 有**表征结构**（不是功能）。"它是被造物所以没有意向"这个论证形式同样适用于人类（人被生出来、被社会化），所以它是**无效论证**。**这是我的推断**：这段类比的真实功能是修辞性的——把 agent 放进"与刀的关系"里，从而不必回答意向性问题。
5. **"来源上无意向"这个条件对人也不成立。** 文本自己在 §三说监督衰减、在 §四说人「必须先监督才能知道哪里需要监督」、在 §10.4 说依赖加深。**如果这些成立，人的目标也在被塑造**（默认设置、界面框架、推荐）。所以"来源"条件若严到能排除 agent，也能排除处于强依赖中的人；若松到能纳入人，就纳不进它的排除力。**这是我的推断**：需要的是一个人的目标也满足、而 agent 不满足的判据——那是**回应性（answerability）**，不是**来源（source）**。

**如果经不起，整个归责方案塌在哪一步？**

**塌在第二步**：不是"意向性形而上学错了"这一步，而是它**到归责的过渡**。整套方案靠一条**未经论证的实质前提**运行——**"只有行动者才能被归责"**。这条前提在法哲学上是假的：严格责任、替代责任、产品责任都允许一个人为**不是自己行动**的事件负责。一旦承认这一点，"行动/事件"的区分对归责就**不再是必要的**，于是 §5.2 的全部形而上学工作变成**无用的**——它既没有证明 agent 不能被归责（法哲学早就允许了），也没有证明谁应该被归责（§5.3 用的是"组织形状"，那是规范性判断）。**结论：归责方案不需要 §5.2；§5.2 只是在给一个法律结论配一层形而上学的装饰。**

**若采纳，改法**

- **把"行动 vs 事件"重写为描述层次问题**：不问"exec 是不是行动"，只问"在**哪个描述**下、对**哪个主体**、exec 可以被要求给出理由"。这把形而上学换成了可操作的规范问题（Brandom 的"给出与索取理由的游戏"、Korsgaard 的"反思性认可"）。
- **把"来源"条件换成"回应性"条件**：一个主体可被归责，当且仅当它**能**被要求给出理由，**且**在理由不足时**能**改变行为（reason-responsiveness；Fischer & Ravizza, *Responsibility and Control*, 1998 的 guidance control）。这样人满足、恒温器不满足、LLM 的满足程度变成**经验问题**（而不是靠二分法一次掐死）——这是**进步**，因为经验问题可以做实验。
- **用"可控性"替代"意向性"**：agent 的错误更像**刹车失灵**（控制失效，不是有意图）而不是**打碎花瓶**（有意向的因果链）。刹车失灵的归责对象是设计者、维护者、批准上路的人——这已经在产品责任法的射程内，不需要新形而上学。
- **删掉"刀"的类比**。它给不出论证，只给态度。

### 主张 3｜"技术结构能承载程序，不能承载标准"；可问责性 vs 正当性的二分

**原文引用**

- `00-理论定稿.md` §六：「**技术结构能承载"程序"，不能承载"标准"**」；「**能**：证明"谁在何时做了什么、有没有越界"——这就是**可问责性**；**不能**：证明"这么做对不对"——那是**正当性**，只能由法律与制度给出」；「架构化责任的准确效力是：**把"不可追责"变成"可追责"，不把"不该做"变成"不做"**」。

**它划得准不准：不准。三大遗漏。**

**论证**

1. **它把"能力"与"权威"混在一个轴上然后又混在一个二分里。** "技术结构能承载什么"是**能力问题**；"正当性只能由法律与制度给出"是**权威问题**。两者不同轴。技术做不到**为什么是对的**（why-justification），这与"正当性只能由法律给出"是两回事——后者是关于正当性的**来源**的主张，且它是错的：正当性的来源不只有法律与制度，还有实践（practice）、惯例、共同承诺（Scanlon, *What We Owe to Each Other*, 1998；Rawls 的 reflective equilibrium）。**这是我的推断**：这一句是为了压住"技术僭越"的质疑而写的**边界口号**，不是论证。
2. **二分过粗，遗漏了至少三个独立的规范要求。** 我要提的第三种可能是**三重的**，不是一个：

| 规范要求 | 技术能否承载 | 内容与代表文献 |
|---|---|---|
| **可问责性** accountability | ✅ 能 | 谁在何时做了什么、有无越界 |
| **程序性正当** procedural due process | ✅ 能（部分） | 决定须经**规定程序**、须**给出理由**、须**可复核**。行政法里正当程序本身就有规范力：Citron, *Technological Due Process*（2008）；Kroll et al., *Accountable Algorithms*（2017） |
| **可争议性** contestability | ✅ 能（部分，且**部分正在被履行**） | 结果须能被**质疑**并触发**重新审议**。Bobbio 的程序正义论；Pettit 的 contestatory 共和主义；Alvin Roth 的 *contestability*；Citron 的 *technological due process* |
| **可救济性** redressability | ❌ **不能** | 救济要**独立于**评价者，技术无法自证独立 |
| **实质正当性** substantive justification | ❌ 不能 | 为什么这么做**是**对的 |
| **惩罚的相称性** proportionality | ⚠️ 半能 | 审计系统其实**能**计算相称性（"过罚相当"），比文本承认的多 |

3. **可争议性不是"正当性"的一半，它是正当性的独立构成项。** 如果决定不可争议（没有申诉通道、没有重新审议的触发机制），那么决定即便是**实质正确的**，也是**支配（domination）**而非**治理**——这是 Pettit 的核心论点。**这是我基于实证的推断**：我在 `1-理论与哲学/` 全目录 grep 了 `可争议|申诉|异议|抗辩|听证`，**零命中**。整套理论**没有任何一处为"争议"留位置**。这是一个由**理论**（而不是由技术上限）造成的空缺。
4. **它低估了自己，同时高估了自己。** 低估：合法性与程序正义**有规范力**，"我不同意决定但我认同过程"是一种真实的规范态度。高估：它说能"消灭'查无此人'"——但这里有两个漏洞：(a) 只消灭了**系统内部**的"查无此人"，**被影响者**（`02-Agent定义论.md` §三 的角色 2）在系统外仍然无权查询；(b) 更严重的：**审计本身成为新的权力**。谁掌握审计的密钥、格式、解释与保留窗，谁就掌握"事实"的最终版本——**这是一种所有理论都没处理的私人秩序（private ordering）权力**。文本只把审计当交付物，没把它当权力现象。

**若采纳，改法**

- **把二分替换为上面的六层矩阵**，每层标注"技术能力 / 制度前提"。特别是：**可救济性**必须点名"技术不能提供"——这样才接得上 §四关心的不可逆性（可救济性对不可逆最要紧，因为**不可逆 = 不可救济**）。
- **把"可争议性"写成架构要求**（这是全套理论中最便宜、收益最大的一处补丁）：
  - 每个事件必须能被**任何**受影响者（不只是使用者）**质疑**，质疑本身落账本；
  - 门禁的每一项规则必须能回答"**在哪个事件里被设定、被谁**"（把"规则的历史"也变成可审计事件，而不是 `policy.json` 里的一次性常量）；
  - 提供**重新审议的触发条件**，且触发条件不能由被质疑方单独设定。
- **把架构化责任的效力上限改写成**：「**把"不可追责"变成"可追责"，把"不可争议"变成"可争议"；但既不把"不该做"变成"不做"，也不把"做错了"变成"改正"。**」——第三句是现在缺的，而且它正是最要紧的一句。

### 主张 4｜"监督必要但不充分且在衰减"；"依赖与监督互斥"；"批准即背书"

**原文引用**

- `00-理论定稿.md` §三：「这是全套理论最硬的一条」；「**不充分**：监督能力随依赖增长而**衰减**——**依赖与监督互斥**」；「**反噬**：监督行为本身改变责任结构——**批准即背书**，人批准过的事故反而锁死追责」。

**它真的被证明了吗：没有。它被断言了，而且被一个"经验规律"的语法伪装成了"结构性互斥"。**

**论证**

1. **反例是存在的，而且是最制度化、最成熟的四个高危行业。**
   - **民航**：飞行员对自动飞行（自动油门、自动驾驶、FMS）的依赖**极深**，而监督**强**——机型资格与定期复训、标准操作程序（SOP）、驾驶舱资源管理（CRM）、飞行数据监控（FOQA）、**强制报告制度**（ASRS）、双人交叉检查（cross-check）。没有 FOQA，现代商业航空的安全记录解释不了。
   - **核电**：对自动保护系统（反应堆保护系统）依赖最深、不可逆性最高，监督也**最强**——主控室人因工程、持照运行人员与再培训、安全文化、**冗余监督**、独立于运营方的监管。
   - **外科**：依赖仪器与麻醉机，监督被**制度化**——手术安全清单（WHO Surgical Safety Checklist）、三方核对、术前暂停（time-out）、同行评议（M&M 会）。
   - **金融清算**：依赖自动化程度极高，监督由**外部制度**提供——中央对手方、清算所、**双人原则**、日间盯市。
   **我的推断（以此作为反驳的核）**：这些机构的处理方式不是"消除依赖"，而是**把监督从"操作者"迁移到"第三方与记录"**。
2. **所以"互斥"这个命题的措辞是错的，正确的措辞是"监督的形态被迫迁移"。** 依赖确实削弱**盯守式监督（vigilance）**——依赖深的人的警觉会退化（Bainbridge 的自动化ironies、Parasuraman & Riley 的 use/misuse/disuse、Endsley 的情境意识）。但**监督（supervision）**作为一个制度变量并没有下降。**这是我的推断**：文本把 `supervision` 与 `vigilance` 当成同一件事，所以把"注意力退化"（一条有实证支撑的心理学规律）升格成了"监督与依赖的结构性互斥"（一条假的结构性规律）。
3. **理论自己的"工程补偿"就是这个命题的反例。** §三直接推出的工程要求是：「协作机制必须**补偿**衰减——把监督从"注意力问题"变成"架构问题"（预定检查点、事件推送、完工铃、结构化审计）」。既然可以补偿，那就是**依赖与"盯守"互斥**，不是**依赖与"监督"互斥**。而理论在 §三用后者（强版本）的语法，去支撑一个只有前者（弱版本）才需要的结论——**这是最硬的一条上最大的偷换**。
4. **代价是具体的**：强版本排除了民航/核电/外科这一整类**制度性监督**的可能性，于是把问题**私有化**为"使用者与 agent 的二元关系"，这就是 `08-总纲.md` §12 自首第 4 条所说的"单机视角"的复现。**这是我的推断**：这是整个项目最深的方法论因果——它需要"外部制度无效或太慢"这个前提，才能推出"只有基础设施是建造者自己能动的"（§10.1）。而这一前提，正由 §三 的夸强版本提供。
5. **"批准即背书"制造了一个循环而文本没有察觉。** 若「批准过的事故反而锁死追责」，那么理性的人**会拒绝批准**；但监督又是"必要的"。于是理论陷入矛盾：**唯一的纠错点（事前/事中介入）恰恰是破坏追责的那个动作**。**这是我的推断**：解法的方向是把监督的对象从"结果"换成"信息条件"——即监督不是"批准这个动作"，而是"保证做出判断时信息是充分的"。文本其实摸到了边（§四最后一条：「审计必须区分"人批准"与"人被信息胁迫后批准"（记录批准的语境）」），但没有把它推成结论。
6. **修正"批准即背书"的判据是"可回滚窗口"而不是"批准与否"**：批准**且**事后可回滚 ⇒ 不构成背书；批准**且**不可回滚 ⇒ 构成背书。这把该命题重新接回 §四 的可逆性（正确的接法），并使它**可工程化**（每个不可逆动作必须声明一个回滚窗口，无窗口者不许批准）。

**若采纳，改法**

- **改写 §三 第 2 条为**：「监督能力随依赖增长而**形态迁移**：盯守式监督衰减（有实证），制度式监督**可以增长**（民航/核电/外科为证）。依赖与**盯守**互斥，与**监督**不互斥。」
- **加一条可检验的命题**（替代模糊的"互斥"）：「**监督强度 = f(事故成本不可逆性 × 监督机构的独立性 × 责任可追溯性)**，不依赖于依赖深度。」——这条既可以证伪，也直接指出工程该优化什么（独立性、可追溯性），而不是徒劳地"对抗依赖"。
- **把"批准"重定义为信息条件**，并把§四的"记录批准的语境"具体化为可测字段：批准前必须呈现**哪三项信息**、批准是否**可拒绝而不受惩罚**、批准后是否**有回滚窗口**。这三项都能进协议。
- **删掉"整套理论最硬的一条"这个自我评级**——按上面的修正，它是最**薄**的一条。**这是我的推断**：这个自我评级本身是理论的自欺机制之一（把最需要论证的地方标为已论证，从而避免再动它）。

### 主张 5｜§10.2 "定义即参战"的自我豁免与死亡判据："判据 = 它最终把机制交到谁手里"

**原文引用**

- `00-理论定稿.md` §10.2：「唯一不自欺的做法是**预先立判据**——**判据 = 它最终把机制交到谁手里**」；「**失效条件（同时是本项目的死亡判据）**：一旦审计集中到厂商、或世界状态不可导出，这条判据**立刻判它输**」。

**它足够吗：不够，而且可被轻易规避。**

**论证**

1. **它测的是"机制的形式分布"，不是"实际权力"。** 四种规避方式都能通过：
   - **(a) 本地部署 + 专有格式**：机制名义上在使用者手里（"我本地部署"），但格式、词表、生态全是厂商的；使用者**能运行却不能重建**——"我本地部署、但格式与生态全是我的"正是提问里那一例，且**完全通过**判据。
   - **(b) 名义可导出**："可导出"只测**形式能力**，不测**有效能力**：导出一堆无法被任何其他系统读取的事件，形式上满足、实质上锁死。
   - **(c) 审计集中但不叫集中**：审计可由**第三方**持有（云、SaaS 稽核），形式上不是"厂商"，但使用者仍然无法独立验证。
   - **(d) 期权式开放**："本判据"是**结果主义且幂等**的——它只看某个时点的机制分布，不看过程。"先把机制集中起来，再承诺将来开放"在每个检查点上都可能"通过"，而护城河已经建成。**这是我的推断**：这也是所有大厂"开放"策略的标准手法。
2. **更根本的自欺：判据由被判者起草并解释。** 文本在 §10.2 说"接受判决"，但**判据的版本化、引用方式、解释权仍在建造者手里**（`00-总纲.md` 铁律四只说"本体公开且版本化"，没说**判据**公开且版本化）。一个自设标准、自任法官、自颁豁免的检查，不是检查。**我的推断**：文本其实已经知道正确答案——`08-总纲.md` §11「**反自我豁免条款**：每条判据必须**由脚本执行，或由非作者的人执行**——作者自己说"通过了"不算通过」——但它**没有**把这条款用到 §10.2 的判据上。这是全套理论中**最刺眼的执行失败**：它已经写出了工具，却没用在自己身上。

**更严格的判据（我的替代方案）**

把结果主义的分布判据，换成**四类可执行测试 + 一张否决点地图**：

| 测试 | 操作 | 判输条件 |
|---|---|---|
| **① 退出测试** | 原方**全部消失**（厂商破产、模型撤下、API 改版、审计密钥更换）后，使用者能否**独立重建**世界并继续工作 | 哪怕一次完整功能需要原方参与 ⇒ 输 |
| **② 冲突测试** | 人为制造一次真实利益冲突（厂商想推一个使用者反对的能力），记录**谁最终拍板** | 拍板权在原方 ⇒ 输。**这是最强的测试**，因为它测的是权力而非形式 |
| **③ 迁移测试** | 把世界的账本与本体迁到**竞争实现**；再反向迁回 | 迁移需要原方配合、或需重写本体/门禁 ⇒ 输 |
| **④ 重写测试** | 篡改账本、换上外部锚点的审计日志（不是自建哈希链） | 整本重写**不可检出** ⇒ 不能声称可问责性。**并且**：构建系统、构建本体、构建判据的三者**不得同属一人**；判据代码与词表必须托管在项目**之外**、可被第三方复算 |
| **⑤ 否决点地图** | 对**审计 / 授权 / 状态解释 / 恢复**四类机制，逐项列出**实际**控制者与**有效**否决点 | 四类机制的实际控制者是同一个主体 ⇒ 输，不论它叫"厂商""第三方"还是"使用者代表" |

**关键区别**：把判据从"**它最终把机制交到谁手里**"改为"**当使用者、厂商、第三方冲突时，谁拥有有效否决权**"。前者是结果主义的（测余额），后者是关系性的（测权力结构）——后者才挡得住"本地部署 + 专有格式"。

### 主张 6｜§10.4 "会话内的结论有效；跨会话的结论一律重算"

**原文引用**

- `00-理论定稿.md` §10.4：「单机理想的真实假设有三条：跨会话记忆连续、**模型行为在两次调用之间稳定**、状态不被第三方可见。云模型让第二条不成立——**厂商可以在会话之间改策略**」；「**结论域划分**：**会话内的结论有效；跨会话的结论一律重算**」；「**失效条件**：若模型行为在会话之间被证明稳定（例如本地模型），偏离归零，单机结论**全域有效**」。

**它是理论结论还是权宜之计：是权宜之计，而且是一个会自我挫败的权宜之计。**

**论证**

1. **它不是从理论内部推出的，是针对"云"这个外部事实的时间切分。** 三条假设中只有"模型行为稳定"是跨会话变量；另外两条（记忆连续、状态隐私）与"域"无关。**这是我的推断**：把一条变量的失效上升为"全部结论的域划分"，是**过度反应**——正确的做法是给每条结论标注它**依赖哪个变量**，而不是按会话边界一刀切。
2. **"重算"要求"会话间稳定"，但你刚说它不稳定。** 这是核心自相矛盾：如果模型行为在会话之间变化，"重算"得到的是**不同的答案**——那么"重算"不是**保证**，只是**把不确定性从结论层推到执行层**。结论域划分**没有解决**它自己指出的问题，只是把它**改名**了。
3. **它对"用这套系统积累经验"是根本限制——但只在它现在的写法下。** 现在的写法意味着：
   - ❌ 关于 agent 行为的一般化（"它在这种任务上可靠"）不能积累；
   - ❌ 关于监督策略的一般化（"哪一级风险需要几个人批"）也不能积累（§10.4 明确把"纠错点在执行前"和"监督按不可逆性定价"都判为**会话内有效**）；
   - ✅ 只有关于**具体事件**的记录能积累（账本）。
   而**这是在否定这个项目本身**：它的卖点是"把监督从注意力问题变成架构问题"，而架构化监督的必要性论证（§三、§四）恰恰依赖"哪些动作不可逆、需要几个人批"这种跨会话判断——文本把它全部判为"会话内有效"，等于承认**架构化监督无法从经验中学习**。
4. **本可以救，而且工具已经在手里。** 理论已采用**纯事件溯源**（`00-总纲.md` §1/§2.2/§2.3 的三处修订标注：**事件是唯一真相，状态是它的投影**）。账本就是一个**会话之外的不变量**，可以充当经验的**跨会话锚点**。**这是我的推断**：因此正确的划分是**三分**，不是二分：

| 依赖什么 | 域 | 判据 |
|---|---|---|
| 依赖**模型行为**的结论（"它明天还是这样"） | **会话内**（且每次会话须重新校准） | 该结论的证成链里出现了"模型的倾向" |
| 依赖**账本内容**的结论（"这个能力从没人批准过""这条路径上次回滚过"） | **跨会话有效**，但须在每次会话开始时**重新验证**（因为账本可能被改） | 该结论完全可由事件推出 |
| 依赖**制度**的结论（"批两级审批够了"） | **域外**——它在账本里没有真值，是**人**定的 | 该结论不是算出来的，是被决定的 |

5. **最深的自我挫败**：如果"厂商可以在会话之间改策略"是**真**的，那么**本项目的"厂商可以改世界"也是真的**——因为 `policy.json`、门禁规则、能力清单全在**厂商/建造者**手里（`00-总纲.md` 铁律4 只承诺"本体公开且版本化"）。于是 §10.4 所描述的风险，**正是本项目自身的形态**。文本把这条风险说成"云模型的"，从而**豁免了自己**。

**若采纳，改法**

- **把二分改为上面的三分**，并要求每条结论在文档里带上它与哪个变量绑定的标注（这是可机械检查的：看证成链里有没有出现模型倾向）。
- **把"重算"改成"校准"**：对模型行为依赖的结论，不是"重算"（假设稳定），而是"每次会话前用一组**金标准任务（golden set）**测量该会话的模型行为漂移，并把漂移量落账本"。这一步把"跨会话不稳定"从**致命的**变成**可测量的**——这是把 §10.4 从权宜之计升级为理论结论的唯一途径。
- **加一条自我适用条款**：「若厂商/建造者可在会话之间改变门禁规则，则本理论对 agent 的一切结论同样降级为会话内有效」——这才是对 §10.4 的诚实执行。

## 三、你发现的、我没问到的问题（优先指出理论的自欺之处）

**1. 「未定型」是修辞性庇护——它把「被定型为分布式无责」保护起来不受批评。**
§1.1 规范层说 Agent 是「三股定型力量争夺的**战场**」、§二说「**僵局不会自己破**」。但"战场"预设三方**势均力敌**，而事实是：厂商掌握模型、策略、格式、产品周期；使用者只有**退出**（Hirschman 意义上的 exit，本来就有，锤子也有——`02-Agent定义论.md` §六 条件 4 自己承认）；建造者同时掌握**本体、门禁、词表、判据的版本化**。**这是我的推断**：把这种极度不对称的分布称为"僵局/战场"，等于用平等化的修辞**掩盖厂商已经赢了大半**这个事实。更要紧的是："**未定型**"是一个**不可证伪**的标签——任何批评都可以被回以"还没有定型，所以你说的问题不成立"，任何现状都可以被描述为"争夺中"。而实际上，**现状已经是定型的一种**（定型为"分布式无责 + 厂商掌握审计"）。**建议**：删掉"未定型"，改为明确命名现状——"**已被定型为分布式无责，且该定型正由厂商的基础设施优势加固**"。这个改写会让 §10.1 的"破局点"分析**更准确**（你在对抗一个已经存在的定型，而不是在争夺一个开放的未来）。

**2. §10.2 对"定义即参战"的处理，在你已经有的方法下是不合格的。**
`08-总纲.md` §11 写着「**反自我豁免条款**：每条判据必须**由脚本执行，或由非作者的人执行**」。但 §10.2 这条**同时是死亡判据**的判据，既没有脚本、也没有非作者的执行者，且其版本化与解释权留在建造者手里。**我的推断**：这不是疏忽，是**结构性利益**——它是唯一一条能判决项目**失败**的判据，而它被写成了"一旦 X 就判输"的形式，其中 X（"审计集中到厂商"、"状态不可导出"）在**本项目自己就是建造者**的情况下几乎不可能由自己触发。**建议**：把这条判据托管到项目之外（第三方复算 + 版本化在外部），或至少由非作者执行一次；这是 §三·主张 5 里那四类测试的用途。

**3. 理论假设了"那个真正的组织者"存在，但没有给判据。而强依赖情形下它不存在。**
§5.3 的"把事件组织成行动形状的人"预设了一个"真正在做组织的人"。但 §三自己承认监督衰减、§四承认「人必须先监督才能知道哪里需要监督」（判断能力已让渡）。于是在强依赖情形下，**使用者可能根本不是在组织行动**——他只是按了"继续"。此时单数主词"那个人"**没有指称对象**。文本在 §5.3 只承认厂商与使用者两个候选，**漏掉了建造者**——而 §1.3 自己说「本理论工作也是一股定型力量」。**建议**：把"建造者"写进 §5.3 的归责表，并承担与厂商同档的举证责任；把"组织者"从**单一主词**改为**否决点分布**（见 §二·主张 1 的改法）。

**4. 理论宣称"最硬的一条"在工程落地时被换掉了变量，而且换反了——这是全套理论最严重的一处 theory–implementation gap。**
`00-理论定稿.md` §四说：「**不可逆性不由当次判断，由预案分级制度化**（如手术分级：术前按类别定级，非术中现场判断）→ 循环由此打破。工程对应物：能力声明里的 `risk` 字段」。但落地实现（`world-core/policy.json`）里，不可逆性**不是按动作类别**判定的，而是**按主体身份**判定的：

- `"irreversible_actors": ["world://user"]`——唯一被允许执行不可逆动作的主体是 **`world://user`（人本身）**，agent 一律收到 `AwaitApproval`；
- 但 `"writes": { "world://user": ["world://*"] }`——人**可以写任何主体**，而 agent **不能写任何主体**；
- `capabilities` 里三个 `reversible: false` 的能力是 `ledger.compact` / `world.rekey` / `world.migrate`——**而人执行它们不需要过任何摩擦**。

**由此三点，都要写进评审记录：**
- (a) **摩擦加在身份上，不加在不可逆性上**。一个 agent 请求可逆动作（`job.start`）被过滤；一个人执行 `world.rekey`（不可逆）零摩擦。这**违反 §四"摩擦按不可逆性定价"**，也违反 §六「技术结构能承载程序」的整个辩护（程序承载的前提是**分类**，而这里的分类变量不是类别）。
- (b) **唯一能执行全部三个不可逆能力的主体，恰好是唯一完全免检的主体**。也就是说，按 §三 自己的论证（不可逆 × 不可归责 = 事后无任何机制能恢复或追索），**最大的风险面在架构上是敞开的**——因为它的持有者被假定为"世界的主人"。
- (c) **`risk` 字段在实现里不存在**。我 grep 了 `world-core/policy.json`：能力项只有 `reversible: true/false`，**没有 `risk` 等级**；`0` 处按动作类别的分级。**所以 §四 的"工程对应物：能力声明里的 `risk` 字段"是一个尚未兑现的声称**（对比 `系统全景图.md` §五 诚实列出的 8 条"没有的东西"——这一条**没有出现在那里**）。

**建议**：① 把不可逆性判定从**主体身份**改为**动作类别 + 情境**（`reversible=false` 的能力对人同样要摩擦）；② 建立 `risk` 等级的**定级权归属**规则——请求方只能**声明**，定级权属于能力提供者，现场只能**升级不能降级**，定级与改级都落账本；③ 把这条 theory–implementation gap 登记进 `系统全景图.md` §五 的"明说的边界"表（那里已经有 8 条同类 honesty，这条是第 9 条，且比多数更严重）。

**5. 全部工程结论都被脱域压缩进了 §5 四条铁律，而 §十的失效条件与 §10.4 的结论域没有一起下去。**
`08-总纲.md` §5 明确：「工程决策只引用这四条；其余哲学内容…**保留但不再参与决策**」。压缩后：铁律 3 =「监督按不可逆性定价…分级由预案决定，不由当次判断」——**保住了结论，丢掉了它的域限定与失效条件**。于是工程侧（铁律 3）读到的是**无条件**的结论，而理论侧的限定（§10.4：这类结论只在会话内有效）**在工程不读的那一半里**。**我的推断**：这正是 §10.4 所警告的错误（在错误结论域里使用结论）在**本项目内部**的实例。**建议**：铁律必须随附其**失效条件**与**结论域**，否则"降为背景"会变成"降为不受限的前提"。

**6. 理论全篇没有为"争议"留任何位置。**
我 grep 了 `1-理论与哲学/`：`可争议|申诉|异议|抗辩|听证` **零命中**。整套理论在论证"规范性是结构性的"，却**没有给规范的争议任何位置**——没有申诉通道、没有重新审议的触发机制、没有被影响者的请求权。这是**由理论造成的空缺**（技术完全可以承载它，见 §二·主张 3）。**建议**：把"争议"作为**一等对象**写进本体（质疑是一条事件），并把"可争议性"加进 §7.2 的四条高效判据（或替换掉最弱的一条）。**这是全套理论里最便宜、收益最大的一处补丁。**

## 四、总问题 A / B / C

### A. 这个理念还缺什么？（哲学层面缺的概念、区分、论证）

1. **缺一个描述层次学说。** 现在有"行动 vs 事件"（两类存在物），缺"同一事件在不同描述下"（Anscombe）。没有它，agent 的行为要么被过度归责要么被完全免责，没有中间地带。
2. **缺回应性/可归责性的判据。** 现在用的是"来源条件"（目标是不是自己生的），缺"能否被要求给理由并作出回应"（Brandom、Korsgaard、Fischer & Ravizza）。这是把形而上学问题转成**可做实验的经验问题**的唯一通道。
3. **缺元层控制（meta-level control）的区分。** 人保留"改目标、改规则、要求理由"的能力（Frankfurt 的二阶意愿、Bratman 的意图层级）；agent 没有。这个区分比"有没有意向性"更结实，也直接对应工程（谁能改 `policy.json`）。
4. **缺"监督"的形态学。** 现在把 supervision 与 vigilance 当一件事。需要的是监督的**种类学**（盯守式 / 制度式 / 同行式 / 记录式 / 外部式）与**迁移规律**——而且是**跨会话、跨机构**的，不是单机的。
5. **缺"可争议性"作为独立规范维度。**（Pettit 的 contestatory republicanism、Bobbio 的程序正义、Citron 的 technological due process。）现在只有"可问责 / 正当"两格。
6. **缺"规范性来源"的多元论。** 现在假定"正当性只能由法律与制度给出"（§六）。但实践、惯例、共同承诺也能给出规范性（Scanlon、Rawls）——这一条限制**主动放弃了**理论本来能拿的东西（例如：审查清单作为行业实践本身就有规范力）。
7. **缺"权力"的第一等地位。** 理论有"争夺""战场"的语汇，但缺**权力的分析工具**（Hirschman 的 exit/voice/loyalty；Pettit 的无支配；Lessig 的 code is law；Pistor 的 code of capital）。**这是我的推断**：因为没有这套工具，它才把极度不对称的分布写成"僵局"。
8. **缺"审计权即权力"这一认识。** 审计格式、密钥、保留窗、解释权都是权力，不是交付物。
9. **缺"规范性"的三层区分与三处不能混用。** 文本自己在 `04-总纲.md` §4.2（病根）与 `00-理论定稿.md` §1.2 都立过这条纪律（「描述事实的词与宣告制度的词不得混用」），但在 §5.2/§5.3/§6 里**自己反复违反**（把法律概念当形而上学证据用，把技术能力当规范权威用）。需要的是**逐条标注该陈述属于哪一层**（规范的 / 概念的 / 经验的）的写作纪律，并且**由非作者核对**。
10. **缺一条论证：不可逆性判据的定级权归属。** §四说"由预案分级制度化"，但**没说谁定预案**。我在实现里看到的答案是：建造者（`policy.json` 是构建者写的，且 `world://user` 被免检）。这就把 §四 自己指出的那个循环（"人必须先监督才能知道哪里需要监督"）**从判断层面搬到了规则层面**，没有解决它——只是把它藏起来了。

### B. 怎么把它丰富起来？（可执行建议：需补的概念工具 + 需引入的既有理论）

**必读清单（按对现有论述的杀伤力排序）**

| 方向 | 必须引入 | 会改掉什么 |
|---|---|---|
| 行动理论 | Anscombe, *Intention* (1957) §§5–9；Davidson, *Essays on Actions and Events* (1980)；Bratman, *Intention, Plans, and Practical Reason* (1987) | **改掉 §5.2** —— 行动性属描述层次，不属事件本体 |
| 归责与回应性 | Fischer & Ravizza, *Responsibility and Control* (1998)；Brandom, *Making It Explicit* (1994)；Korsgaard, *Self-Constitution* (2009) | **改掉 §5.3 的判据** —— 从"来源"换成"回应性" |
| 正当程序与算法问责 | Citron, *Technological Due Process* (2008)；Kroll et al., *Accountable Algorithms* (2017)；Pasquale, *The Black Box Society* (2015) | **补上程序性正当**（现在只有可问责性） |

| 规范性的来源 | Scanlon, *What We Owe to Each Other* (1998)；Rawls, *A Theory of Justice* (1971) 的 reflective equilibrium | **改掉"正当性只能由法律与制度给出"** |

| 保险与责任 | Shavell；Abraham & Rabin 编 *The Liability Century* 相关文献 | **修正 §10.5**，处理"保费定价粗化"，见下 |

**具体动作（可直接落笔）**

1. **改写 §5.2**：删除"行动 = 有意向的事件 / 事件 = 单纯发生"的本体二分，代之以"**同一事件在不同描述下**"＋"**exec 可被要求给出理由**"。保留"agent 与工具的倾向"那段作为**认识论**结论（它确实学的是"人怎么说"），不作为**本体论**结论。
2. **改写 §5.3**：判据从"贡献度分摊"改为「**否决点 + 补救成本**」双判据；把"建造者"写进归责表。
3. **改写 §三第 2 条**（见 §二·主张 4 的改法），并**撤销"全套理论最硬的一条"这个自我评级**。
4. **把 §六 的二分为六层矩阵**，明确"可救济性技术不能提供"——这样才能接上不可逆性。
5. **给本体加三个字段**：`contest`（质疑事件）、`rule_provenance`（每一项门禁规则在哪条事件里被谁设定）、`redress_path`（救济通道及其独立性声明）。三者都是可机械检查的。
6. **给每条工程结论加随附的失效条件与结论域**（回应 §三·新问题 5）。
7. **在 §5.1 的产权三档里修两处**：(a) 开源协议与许可**不是惯例与互惠**，是**有强制力的许可**（GPL/CC 是著作权许可，违反可诉）；(b) 个人信息保护法对"公开数据"**有管辖**，"谁都够不着"是错的；(c) 补第四档：**许可约束下的可取用**（"能取用，但取用方式受许可证约束"）——现在的三档把"许可证"和"公共数据"混在"无业主区"，而门禁需要**可判定**的越界标准，"惯例"作为判据是不可判定的，工程上无法担保。
8. **修正 §10.5**：现在的结论是"保险对不可逆只作用于事前（保费定价改变行为）"，失效条件是"风险池被拉平"。但实际车险的主要事前机制是**强制 + 无赔款优待（bonus-malus）+ 法定下限 + 强制投保**，**不是纯定价**。**这是我的推断**：应补一条——保险的事前有效性依赖**强制投保**，而强制需要法律；于是 §10.5 的"保险作用于事前"反而**加强了法律路径的必要性**，削弱了"只有基础设施是建造者自己能动的"（§10.1）。
9. **建立"三层陈述标注"的写作纪律**（规范的 / 概念的 / 经验的），并规定**由非作者核对**（`04-总纲.md` §11 的反自我豁免条款应扩展到全部理论篇，不只验收判据）。
10. **把建造者自己纳入被审计范围**：技术上已经做了（`00-总纲.md` 铁律 4"建造者与 agent 同一条门禁"），但**建造者持有门禁的规则本身**——这一条没有对应机制。建议：`policy.json` 的每一次变更都必须落账本、且变更的**批准者不得是提出者**。

### C. 外部现有系统为什么不好用？——从哲学角度看，今天的规范性工具为什么是坏的

**要点名的具体形态（六种）**

| 形态 | 它宣称 | 它在规范性上的实际失败 |
|---|---|---|
| **权限弹窗**（OS/移动端/浏览器权限对话框） | "你同意了" | **同意空壳**：选项被设成"同意 / 稍后"（不是"拒绝"），且**不可协商**、**不可部分同意** |
| **使用条款 / 服务协议**（ToS） | "你缔结了契约" | **同意空壳 + 时间错位**：一次性点击＝对未来一切用途的无限授权；且**内容可单方修改**（继续使用视为同意） |
| **隐私政策** | "你知情了" | **伪透明的规模失败**：以其篇幅与变动频率，**没有任何实际读者**能知情（Solove 的 privacy self-management 批判；O'Neill 对知情同意作为**仪式**的批判） |
| **Agent 免责声明**（"AI 可能出错 / 不构成建议 / 请自行核实"） | "风险已披露" | **责任倒置**：把风险移给**最不能控制它的人**；且**披露不改变概率**，只改变责任，这一步是**规范性的偷换** |
| **"我同意"按钮背后的默认配置** | "你可自选" | **默认即定制**：默认值是**选择架构**的设计者单方设定的规范（Thaler & Sunstein），而它被伪装成中立的技术默认 |
| **企业侧的"负责任 AI 原则 / 伦理委员会"** | "我们自我约束" | **自我豁免**：原则的起草者、解释者、执行者与被约束者是同一主体（与 §10.2 的病同型） |

**它们在规范性上到底失败在哪里（四个层次）**

1. **同意理论层——同意的能力被高估，范围被偷扩。**
   洛克式的同意只能授权**有限、可撤回、可理解**的让渡。今天的工具体系用同意做了一件它做不到的事：**生产对未来的无限授权**。哲学上这不是"同意不充分"，是"**同意不是那个能产生这种规范效果的东西**"——就像你不能通过同意把自己卖为奴隶（不可让渡性），你也不能通过点击 ToS 授权厂商影响**未来还不存在的人**。
2. **规范主体层——主体错位。**
   点击的**我**，不等于被影响的**我们**。我同意 ≠ 我可以授权你去影响第三人。这与 `02-Agent定义论.md` §三 的"四个角色"直接相关（角色 2：被影响者"互不知晓"），而现有的规范工具**完全没有为角色 2 留任何位置**——这**正是**你理论里已经识别出的问题，但**外部工具一个都没解决**。
3. **程序层——不可争议 = 非正当。**
   这些工具**没有申诉通道、没有重新审议的触发机制、不给出理由**（"你的账号被限制"，没有理由）。按 Pettit 的判据，这就不是治理，是**支配**。技术上，"给出理由"完全可以做到（事件账本里就有），不做是**选择**。
4. **责任层——把免责的方向搞反了。**
   健康的规范结构是"**向上负责**"（对受影响者负责）；现在的工具体系是"**向下免责**"（对使用者免责）。**这是我的推断**：这是"规范性工具"坏掉了的**根本病灶**——它们不是**规范**，是**责任转移装置**。而理论 §1.2 第 1 条自己写过这条纪律：「**描述事实的词与宣告制度的词不得混用**」。免责声明正是这句话的**教科书案例**：「输出不构成建议」是**描述性**的（说这个输出是什么），却被用来取得**制度性**的效果（不承担责任）。它**用描述来规避宣告**。

**替代方向（三句，可直接作为设计原则写进本项目）**

- **同意必须可撤回、有范围、不约束第三人。** 拒绝必须与同意同样便宜（拒绝成本不得高于同意成本）。
- **可争议性必须被造进架构，且救济权独立于评价者。** 质疑是一条事件，能触发重新审议；解释权不能与被解释者同一。
- **规范工具的成果不应是"同意"或"免责"，而是"可追溯的语境记录"。** 它应如实回答"当时世界知道什么、谁在何时决定了什么、谁本可以否决"——**只承载可问责性与可争议性，回避正当性的宣告**。这不是谦让（§六 的定位是对的）——是因为**所有坏掉的规范工具都犯同一个罪：把一个描述事实的句子伪装成一个宣告制度的句子。**

> **最后一句与 §六 的呼应**：§六 说"技术结构能承载程序，不能承载标准"。我要给它的修正不是反驳，是**延长**——**技术结构不仅能承载程序，还能承载"程序里必须有争议"这件事**；而后者，恰恰是今天的权限弹窗、ToS、隐私政策与免责声明**全部不做**的那一件事。

## 五、你必须指出的一处"最危险的主张"

**我选主张 2：§5.2「行动 = 有意向的事件；事件 = 单纯发生」，以及由此推出的"exec 结构上有意向的形状，来源上无意向的地位"。**

六条里它**错得最厉害、代价最大**，理由四条：

1. **它是错的，而且是可被证伪地错。** 与 Anscombe 的描述层次学说**方向相反**、与 Davidson 的核心结论（行动**是**事件）**方向相反**。这不是解释分歧，是把一个已确立的立场**读反了**，且读反的方向**恰好对本项目有利**——它一次性取消了 agent 的行动性，从而取消了 agent 的责任。**这是我的推断**：这个"恰好"是问题所在。
2. **它承担着过量的重量。** §5.3 的归责推论（"归责不落在 Agent"）、§六的架构化责任定位（"可问责 ≠ 正确"）、§八铁律 2、以及 §1.2 第 2 条的"塑形 ≠ 守诺"——**全部**踩在这条区分上。它一塌，**四分之一个理论塌**。
3. **它产生一个"恒温器反例"且它挡不住。** 若"结构上有意向的形状"（有目标指向）足以构成意向性，则恒温器、导弹、趋光细菌全都有意向性——荒谬；若不足以构成，则 §5.2 的"形状/来源"二分**不是判据，是措辞**。文本没有给出任何能挡住恒温器的第三选项。
4. **代价最大的一条在这里：它把一个法律结论伪装成形而上学结论，从而**关闭了**本可以走的路。** 因为"只有行动者才能被归责"这条前提是**假**的（严格责任、替代责任、产品责任都允许为非行动负责），所以整套 §5.2 的形而上学不但没帮助，还**主动排除了**更有力的路径：**对 agent 系统施加严格责任**（不问意志、不问意向、只问控制的分布）。**这是我的推断**：真正需要的形而上学不是"exec 有没有意向"，而是"**谁有能力控制这个风险**"——后者是可操作的，前者是不可操作的。选择前者，等于选择了一个**什么都证明不了、却什么都拦得住**的工具。

**为什么不是主张 4（监督衰减）？** 因为它虽然**错**，但**代价可控**——工程侧的"补偿"（预定检查点、事件推送、完工铃、结构化审计）**恰好是它的修正形态**，也就是说，实践上它是**自我修复**的。它的危害主要在**理论上**（把单机视角合法化，从而削弱外部制度路径的可见性），而这不至于让整个方案坍塌。

**为什么不是主张 5（自设判据）？** 因为它**已经有解**——`04-总纲.md` §11 的反自我豁免条款（"由脚本执行，或由非作者的人执行"）**就在文本里**，只是没被用到 §10.2。它的病是**执行失败**，不是**概念腐烂**。

**主张 2 不同：它没有解，只有替换。** 而替换它需要的哲学工具（Anscombe 的描述层次、Fischer & Ravizza 的 guidance control、产品责任的严格责任传统）**全都不在文本里**。这是唯一一条**必须重建**的柱子——其它五条都只需修正。
