> **本件是什么**：**序**。它不描述工程、不写模块、不给判据表。
> 它只负责把**最高层次的理论认知**写成一份可被核对的说法——因为如果连"我们要造什么、为什么造它、它在什么条件下不成立"都说不到一处，后面所有工程都是在各自脑补。

>

> 3. **它今天带着一批红项**：在可预见的范围内**没有独立可验者**，这批条目**是红项，不是"中性·待定"**（§7.3）。

## 一、没统一的是**语义**，不是语法

**先把不是什么事说清楚**，因为这一句搞错，后面全错：

> **"语法"早就在很大程度上统一了。** 状态码、JSON、时间格式、唯一标识、传输层安全——这些是几十年的成果。
> 说"到处都要现翻一遍"是**夸大**，一条反例就能把整篇带走。

**反例清算（本序的靶子到底在哪一层）**：

| 已经不需要翻译的东西          | 它解决了哪一层           | 它**没有**解决哪一层                  |
| ------------------- | ----------------- | ----------------------------- |
| HTTP 方法／状态码         | 动作与结果的**粗糙分类**    | "这次变更改了什么、前值是什么"              |
| JSON／CBOR           | 字节怎么解析成结构         | 结构里**每个字段是什么意思**              |
| ISO 8601／RFC 3339   | 时刻怎么写、能否比大小       | **一件事排在第几位**（全序与因果）           |
| UUID／内容 hash        | 身份与完整性            | **谁**有权做这件事                   |
| TLS／X.509           | 双方从不相识也能互信        | 信任建立之后**发生了什么**               |
| SQL                 | 人、程序、优化器各取所需      | **跨主体**的变更语义与归责               |
| Git                 | 一次写入、只追加、不可变、内容寻址 | **语义字段**（改了哪个业务字段）、**授权与可逆性** |
| OpenAPI／JSON Schema | 接口的机器可读描述         | **运行期**这次调用在业务上意味着什么          |

> **结论一句**：**语法已经统一了，语义没有。**
> **这句断言的适用域必须同时说**：它说的是"**跨主体的变更语义**（改了什么、前值、因果、授权）没有统一"；
> 它**不**主张"三方不能协作"——本序不否认 HTTP、Git、SQL 让三方协作得很好（见 §4.3）。

**"重新协商"的准确形态**：不是"没有说法"，而是——

> **三方各自都有说法，也能交互；但每一处"这件事是什么意思"都要在当场重谈一遍，谈完不留下任何一份三方都认的底稿。**

**问题不是"没有说法"，是"有三份互不承认的说法"**：

| 谁的          | 它记着的那一份           | 谁认为它算数   |
| ----------- | ----------------- | -------- |
| 数据库／文件系统    | 数据和它的影子（日志、备份）    | 只有那个系统自己 |
| 每个软件        | 自己那份状态、自己那套错误码    | 只有它自己    |
| 每个 agent 会话 | 对话记录（可编辑、可截断、可摘要） | 只有那次会话   |

**于是：同一件事，三方各有一份说法，没有一处能说"以我为准"。** 这才是缺口。

**而这个缺口的代价，就是"只能两两翻译"**：底下没有一份共同的说法可以对齐，于是**每一对交界都得各谈一次**——
N 方就有 N² 份约定，而"这句话到底是什么意思"**没有任何一处负责回答**。**这就是 §三 要破坏的那条路由。**

**两处必须先说准，否则这一节会被读成另一句话**：

1. **"三方"是能力档位，不是三类人。** 同一时间点上，一个人可以同时占三个位置（他自己在操作、他用的 agent 在请求、他家的设备在写）。
   ⇒ 本序下文一律用"**各方**"；"三方"只在指**能力档位**（能读会写的人／能读会写的程序／只会读写的设备）时使用。
2. **对齐的对象是结构条件，不是可理解性。** 各方只跟共同的东西对齐，是"各方都能懂"的**结构条件**；
   **可理解性本身尚未验证**——今天能证明的只有"各方读的是同一份输入"（§4.2 末）。

## 三、要破坏的那条路由，和两条不该被一起打掉的路

### 3.0 先把"要破坏什么"钉死（**三分，不是一分**）

> 这一节是全文最容易被打偏的一处：一份反对"翻译"的文字，会被读成"反对一切转译"——**而本序要的恰恰包含转译**。
> 所以先把三样东西分开：

| | 是什么 | 本序的立场 |
|---|---|---|
| **a. 两两路由翻译** | 每一对交界各写一份约定或翻译器；**份数随参与者平方增长**；**争执时没有一处能说"以我为准"** | **要破坏的，就是它** |
| **b. 同一份事实的多种表达（出口／投影）** | 从**同一份**真相出发、**单向**译成人看的样子、程序读的样子；译出来的东西**能拿回原始记录核对** | **要建的，就是它** |
| **c. 底层的一套共同说法** | 一套语义事件 ＋ 一本只追加的账——各方**都跟它对齐**，而不是互相谈 | **a 与 b 的分界就在它**：有 c，转译才是单向投影；没有 c，转译就只能是两两路由 |

> **一句话**：**要破坏的是"多份权威之间的两两翻译"，要建的是"从同一份真相出发的单向投影"。**
> 这两件事在中文里都能叫"翻译"——**本序此后不用"翻译"指代 b，一律叫"投影／出口"。**
>
> **统一底层的利益也正在这里**：底下一套共同的说法（语义事件 ＋ 一本账），上面各自用自己最合适的那一份（投影）。
> **不是让大家都改用同一种界面，而是让大家都对齐同一份事实。**

**这个三分有原文依据，不是本序新造的框架**（v0.6 补；出处逐字）：

| 三分的哪一格 | 出处（逐字） |
|---|---|
| **a 两两路由翻译**（要破坏） | `00-理论定稿` §7.3：**"损耗：从『三方两两互译』降为『底座 → 人的投影』"** |
| **b 单向投影**（要建设） | 同句后半：**"翻译只发生在一个方向上，且从同一真相出发"** |
| **c 底层共同说法**（分界） | 同节现行结构图首行：**"真相层：语义总线（一份数据：状态 / 动作 / 事件）"**；以及同节 **"中间点是求交集，交集必然小于全集"** |
| **三者不是"对等三方"** | 同节：**"平等 vs 不对称（三方对等 vs 机器直连、唯人配随行翻译）"** |

> **一句话读法**：**既有定稿早就把 a 降为 b、并指明"唯一方向 + 同一真相"；本序 §3.0 只是把这三样分开命名，并说明"缺了 c，b 就退化成 a"。**

### 3.1 两两直连翻译（**要反的是它**）

```text
   人  ←→  翻译  ←→  agent  ←→  翻译  ←→  机器
```

| #     | 它缺什么                                                                                                                                                                                  |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1** | **数量随参与者平方增长**。三方 3 条；十方 45 条。每加一个参与者，**不是加一条，是加一列**。<br>**限定**：这条**只对"没有中间标准"的裸点对点成立**；一旦约定一个中间标准，增长就**降为线性**（见 §3.2）                                                                |
| **2** | **翻译会丢东西**——丢得最狠的**不是名字**，是**对方压根没有那一格**（某方系统里没有"前值"这个概念，你怎么翻？）                                                                                                                       |
| **3** | **它让权威变成三份**。同一句话经两条路径可能得到两个结果，**而没有任何一处能说"以我为准"**                                                                                                                                    |
| **4** | **它把问题搬个地方**：翻译规则谁改、谁批、改了之后旧记录还读不读得懂——**一条不少，只是搬进了翻译器里**。<br>**自指检验**：这一条**对本序同样成立**（词表的修订规则谁定、旧记录还读不读得懂）。<br>**而且它不能当反驳用**：一条能原样反弹回自己身上的话，**不构成对对方的反驳**——故本序不把它当理由，只当**共同待解的问题**列在此处 |

### 3.2 约定中间标准（**这条是真的竞争方案，本序必须正面比**）

现实中人们并不两两写翻译器，而是**约定一个中间标准**：HTTP 头、JSON、ISO 8601、SMTP、`Content-Type`、OAuth、OpenAPI、Protobuf。
参与者从 3 增到 10，**新增的是适配器（线性），不是互译对（平方）**。**它们确实管用**——这必须承认，否则就是自欺。

**它们共同的天花板是：只能表达"谁都能表达的那一层"。**

| 标准管得了     | 标准管不了                        |
| --------- | ---------------------------- |
| 这一段字节怎么解析 | **这段话是"要做什么"还是"做完了"**        |
| 时间怎么写     | **这次改动改的是哪个语义字段、前值是什么**      |
| 标识符长什么样   | **这件事因为哪一条上游事件才发生、谁批准、可不可逆** |

**所以本序与"标准 + 领域 schema（OpenAPI／AsyncAPI／Protobuf）"的差别，必须说成可证伪的样子**：

> **给 Git 加三样东西试试**：① 这次改动改的是**哪个业务字段**、② **前值**是什么、③ **谁批准、可不可逆**。
> 你会发现它**给不出**——而**不是**它不能协作。
> ⇒ **本序的增量不是"能交互"，是"可归责的变更语义"。** 这个增量存在与否，**今天就能验**（§7.2 检验 B-2、B-7）。

### 3.3 那要怎么办

**不要求"没有翻译"，要求"翻译出来的东西能被独立核对"。**

**翻译不是被消灭的，而是被降级为"单向的、且可核对的"**——出口可以把同一份事实译成人看的样子、或程序读的样子，
但**译出来的东西，必须能被人拿回原始记录去核对**。

> **反的是"多份权威之间的两两翻译"，不是"把同一份真相译成两种样子"。**
> 用 §3.0 的三分说：**破坏 a、建设 b、靠 c 分界**——三者缺了 c，b 就退化成 a。
> **（v0.4 在这里写的是"反的是'多处权威'，不是'翻译'这个动作"——那句话把 a 和 b 混在一个"翻译"里，读起来像本序放弃了打击对象。v0.5 按三分改正。）**

## 四、那"共同的东西"是什么

### 4.0 先把三个名字定下来：**语义世界 · 语义系统 · 语义事件**

> **v0.5 新增，v0.6 订正**。此前**只有 v0.1 用过一次"语义世界"**（在它的 §二），**v0.2–v0.4 三版把它丢了**——
> 而它正是本书要造的那个东西的名字。一份最高层的文件把自己的对象名字弄丢三版，读者就会各自给它起名（"总线""底座""平台"），然后各说各的。

| 名字 | 指什么 | 一句话 |
|---|---|---|
| **语义事件** | **最小单位**：一条"发生过的变更"，自描述到 §4.5 的七项（主体／字段／前值后值／因果／全序／授权与可逆性／单位量纲） | **各方之间唯一的通货** |
| **语义世界** | **要造的那个东西**：一套语义事件 ＋ **一本只追加的账** ＋ 从它出发的**若干出口**；世界里发生的一切**只有一种写法** | **本项目的对象** |
| **语义系统** | **以语义事件为接口的那些软件系统**：AI agent、设备驱动／适配器、人用的客户端——它们**说的是语义事件，不是自己的方言** | **对齐者，不是被造物** |

> **"语义系统"是本序新造的词**（全仓库此前的文档里零命中）；**"人"不算语义系统**——
> 人经出口读、经他用的那个语义系统写；这样 §一 的"三方＝能力档位"与 §6.2 的分层才不打架。
> **关系一句话**：**语义系统之间不互相谈，各自跟语义世界对齐；对齐用的通货是语义事件。**
> 因此"**统一底层**"的准确含义是：**统一到语义世界这一层**——
> 底下一套共同的说法，上面各自用自己最合适的那一份（投影／直连，见 §3.0 三分与 §6.2）。

### 4.1 它不是什么

**不是"一种三方都懂的新中间语言"**——那又回到 §3.2 的天花板（求交集 ⇒ 只剩最弱那一层）。
（此判断在本项目既有理论里已立：**中间点是求交集，交集必然小于全集**。）

### 4.2 "共同"的确切含义：**三条判据**

> 一个东西算不算"三方共同的说法"，看它是否同时满足：
> 
> | #     | 判据       | 一句话                                     |
> | ----- | -------- | --------------------------------------- |
> | **1** | **唯一权威** | 有争执时，各方都必须认**同一处**说了算（不是"我这份也差不多"）      |
> | **2** | **可核对**  | 第三方（不是写的人、也不是读的人）能**独立地**从那里查出**同一件事**  |
> | **3** | **多方可达** | 能力强弱不同的各方，能**各自取到自己能用的那一份**，而不必为了迁就别人降级 |

**检验动作（可执行，公开可复核）**：

> **任取一方说出的一件事，另外两方都能在"不问它"的情况下，从同一份记录里找出同一件事。**

**但"能跑这个动作"不等于"判定是机械的"**——这两件事 v0.3 混在一起写，v0.4 分开：

| 项                       | 今天的实际状态                                             |
| ----------------------- | --------------------------------------------------- |
| **检验动作**                | **可执行**：读两份出口、按第 2 条判据人工核对（本项目已有同源核对命令）             |
| **判定程序**（"两条记录何时算同一件事"） | **尚未定义**：今天的同源核对**只比首行四项**，所以**一个出口少渲染一半主体，核对照样全绿** |
| ⇒ 因此在本序里                | **"共同"一词的含义是「同一份输入 + 一致的投影核对」，不含「语义等价」**            |

> **这是本序第一款待补的判据，不是可以绕过的细节**（见 §4.6、§7.1 边界 D1、§7.2 检验 B-4）。

### 4.3 共同的东西 ＝ 三件**互不代替**的事

> **v0.2 在这里说"缺一不可"，v0.3 收回**：那是**宣告**，不是论证。
> 本节**只主张三件互不代替**；**不主张三件合起来已经充分**，也**不主张它们是必要的全部**。

| #     | 是什么                             | 它解决 §4.2 的哪一条 | **缺了它，你会观察到**                                                              |
| ----- | ------------------------------- | ------------- | -------------------------------------------------------------------------- |
| **1** | **一套语义事件**（发生过的每一件事，**只有一种写法**） | 判据 1、2        | 同一个动作在两处**记成两个样子**，核对时对不上；于是没有一处能说"以我为准"                                   |
| **2** | **一本账**（这种写法**只追加地记在一处**）       | 判据 1          | 出现**两条互斥的当前状态**，且**没有任何程序能判定哪一条是真的**；冲突只能靠人吵                               |
| **3** | **若干出口**（同一份东西，**各按各自最优的方式取**）  | 判据 3          | 某一方为了拿到自己需要的一格，**在出口之外自己补一段代码**——那就是翻译器，而它**没有登记处**（触发条件与限定见 §4.6）（见 §4.6） |

> **三件的地位并不相等**：①是真正承重的，②是①的部署形态，③是①的读取策略。
> 把三件并列成"缺一不可"，实际是把一个论点（**要自描述**）包装成三个论点。**本节不再这样做。**

**"为什么不是两件、不是四件"——本节不回答**：能不能有**第四件必要之物**，以及"三件是否充分"，
**由全书的"本体与命名规则"那一章承担**（v0.2 有此句，v0.3 误删，v0.4 补回）。**本节只做对上一条的引用闭合。**

**必须正面处理的八个对象**（§一 表里的全部对象，不止三个）：

| 对象                  | 它有没有"唯一权威账本"           | 为什么它仍然可以是"共同说法"，以及本序凭什么还算有增量                                                                           |
| ------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------ |
| HTTP／状态码            | 没有                     | 它统一的是**动作分类**；跨主体的"改了什么、谁批"不在它的语义里                                                                     |
| JSON／CBOR           | 没有                     | 它统一的是**解析**；字段含义与单位不在它的语义里                                                                             |
| ISO 8601            | 没有                     | 它统一的是**时刻写法**；"排第几位"（全序）不在它的语义里                                                                        |
| UUID／hash           | 没有                     | 它统一的是**身份与完整性**；授权不在它的语义里                                                                              |
| TLS／X.509           | 没有                     | 它统一的是**信任建立**；建立之后发生了什么不在它的语义里                                                                         |
| **SQL**             | **没有**（每个实例／副本各一份当前状态） | **副本不是"两条互斥的当前状态"**：它们属于**不同的世界**（不同信任域），冲突由复制协议而非语义层裁决。本序主张的是"**一个世界一份状态**"，**不是"全局唯一"**——故 SQL 不构成反例 |
| **Git**             | **没有**（每个克隆各一份）        | 同上：克隆是**世界的复制**，不是同一个世界里的第二真相。**而 Git 给不出的是"哪个业务字段、前值、谁批准、可不可逆"**——这正是本序的增量                            |
| OpenAPI／JSON Schema | 没有                     | 它描述**接口形状**；运行期这次调用的业务含义不在它的语义里                                                                        |

> **因此本序不主张"没有账本就没有共同说法"——那是假的。**
> 本序只主张：**要拿到"改了哪个语义字段／前值是什么／因为哪一条／谁批准、可不可逆"这五样，必须有账本。**
> 这是本序与它们之间**可证伪的差别**；差别不成立，本序就没有存在理由。

### 4.3b 为什么这件事必须由"共同的东西"承担（**"没有脑子"已删**）

> **v0.2 这里写的是"它服务的对象没有脑子，所以意义必须由它自己承担"。v0.3 删去**——"有没有脑子"**不可判定**，
> 用一个不可判定的谓词去支撑一个存在性结论，是全文最弱的一环。换成一个**可判定的能力差**：

| 谁          | 它被保证的是什么                                        |
| ---------- | ----------------------------------------------- |
| 系统服务所服务的程序 | **由编译器保证**其类型与调用约定——符号的意义**在它之外已经被固定**          |
| 本序所服务的对象   | **不保证**携带可核验的语义标注——**没有任何机制保证"这次变更是什么意思"被写下来过** |

> ⇒ 所以**不是"它更聪明"，而是"它不得不自己承担"**：在所服务的对象之外，**没有各方都承认的解释者**。
> **准确说法**：世界核心**承载并强制意义的形状**；**它不"懂"意义**——判定仍由写词表的人完成。
> **谁是意义的作者**：词表每一格**由人写、由人批**，治理规则见 §7.1 边界 C1。**这是选择，不是天命。**

### 4.4 为什么是这三件：与五种方案逐一对表

| 方案                          | 能否独立核对             | 谁裁定冲突 | 规模成本        | 被哪条边界限制                              |
| --------------------------- | ------------------ | ----- | ----------- | ------------------------------------ |
| ① 三方直连、各写各的                 | ❌ 不能               | 没有一处  | 每条边一份工作量    | 判据 1、2 全失                            |
| ② 统一中间语言                    | ⚠️ 只能核对"最弱那一层"     | 语言规范  | 低（表达力被压到下限） | §4.2 判据 3                            |
| ③ 共享词汇表 + 局部翻译 + 各自保留真相     | ⚠️ 局部可核、全局不可核      | 各处自己  | 边缘数 × 局部工作量 | 判据 1（权威仍多份）                          |
| ④ 单一事件流，但无出口                | ✅ 能                | 那一份流  | 低           | 判据 3（各方被迫用同一种表达）                     |
| ⑤ **本方案**：单一账本 + 一种写法 + 多出口 | ✅ **判据待补**（§4.2 末） | 那本账   | 与参与者数无关     | 需要有人写驱动（§六）；**排序权集中于写者**（§7.1 边界 E1） |

### 4.5 "语义"的确切含义（**七项，可逐条判真假**）

| #     | 项                           | 没有它会怎样                       |
| ----- | --------------------------- | ---------------------------- |
| **1** | **主体是谁**（稳定身份，不是进程号／用户号）    | 无法回答"谁做的"                    |
| **2** | **改了哪个对象的哪个字段**             | 无法回答"改了什么"（只知道某个文件变了）        |
| **3** | **从什么变成什么**（**前值必带**）       | **回不去**——没有前值就没有撤销的依据        |
| **4** | **因为哪一条**（因果）               | 只能给时间线，给不出"为什么"              |
| **5** | **全序与时间基准**（它排在第几位、以什么时钟为准） | **"账本""只追加""因为哪一条"三件事全部要求它** |
| **6** | **谁授权、可不可逆**                | 无法按不可逆性给它加摩擦                 |
| **7** | **单位与量纲**                   | "120"是元还是分、"3"是秒还是分钟，只能靠猜    |

> **"不读文档也能懂"是目标，不是判据**——它描述读者效果，**无法判定**。可判定的是上面这七项**是否齐备**。
> **第 2 项与第 6 项今天没有执行者**：谁负责在写入时校验"字段"与"授权"两格齐备，本序**未指派**（§7.3 红项）。

### 4.6 出口的完备性（**这一节的两个要求必须有主语**）

§4.3 第 3 件说"若干出口"，但**没说几件，也没规定何时算完备**。后果是**静默的**：

> **没有任何一方能观察到"本来应该有一格、而出口没给"**——缺格不报错。
> 那么某一方**就会**在出口之外自己补一段代码（本项目已登记的实现反证里，这一形态确实出现过），**局部翻译器就是这样长回来的**。
> **限定**：这是**触发条件下的后果**，不是"处处必然发生"——只要 D1 做到（缺格报错），这条通路就被堵住；今天它没做到，所以通路是开的。

**因此本节要求两条，并写明"谁做"**（v0.3 只写"本序要求"，没有主语；**一个被诊断为"没人负责发现"的问题，不能用两条同样没人负责的要求来处置**）：

| #      | 要求                                                           | **谁做**              | 现状                           |
| ------ | ------------------------------------------------------------ | ------------------- | ---------------------------- |
| **D1** | **出口漏渲染必须能被机械核对**：每个**已在词表里声明**的概念字段，至少有一个出口可读；缺格**报错**，不得静默 | 出口（投影）的作者实现，词表维护者核对 | **未实现**（§7.2 检验 B-3）⇒ **红项** |
| **D2** | **词表漏定义**（"本来应该有这一格"本身没被定义过）**不可由任何机械核对发现**                  | **无承担者**            | **不可判定**——如实登记，不假装有办法        |

> **D2 是这一节真正的洞**：D1 只能防住"出口漏渲染"，防不住"词表漏定义"；
> 而"少渲一半主体、同源核对照样全绿"这个已登记的实现反证，**形态上属于 D2**。

## 五、由此推出一条要求

> **若要做到"各方各取自己最优的一份、且争执时认同一处"，那么"发生过的每一件事都被写下来、而且只有一种写法"是必须的。**

**（v0.3 这里写的是"只有当……才可能……"，一句全称必要条件句——而 §4.3 刚刚声明不主张充分、也不主张必要。v0.4 把强度改回与 §4.3 一致：它是一条**有条件的必要性主张**，不是一条关于世界的规律。）**

由此**推出来**的四条纪律（它们**服务于**上面那条，不是目的本身）：

| 纪律          | 保住的是哪一点                         | 它的代价                               | **当前强制力**（据 §7.2 B-6 实测）                         |
| ----------- | ------------------------------- | ---------------------------------- | ------------------------------------------------ |
| **状态是算出来的** | 否则"状态"就有 N 份 ⇒ **N 个世界**        | 读性能与存储（本项目已有实测缺口）                  | 由代码路径强制；**同身份可直接改账本，但摘要链会检出**                    |
| **历史只追加**   | 否则"同一件事"可以被事后改写 ⇒ **共同的东西失去权威** | 撤销只能靠**追加补偿**                      | 同上；**无密钥的链挡不住"整文件重算"**（本项目已有测试钉住这个极限）            |
| **回滚是再加一条** | 否则"撤销"会变成对共同说法的**直接篡改**         | 读者必须自己折叠补偿链                        | 同上                                               |
| **一个写入口**   | 否则"谁说的"无从判定                     | **排序权集中**：因果序 = 写者的调度序（§7.1 边界 E1） | **CLI 路径的身份是命令行参数**——同 uid 可自称最高权主体（§7.2 B-6 实测） |

## 六、一次交互里，各方各做什么（**含"谁出力、谁可以不接受"**）

| 谁                  | 写什么／做什么                                                                              | 读哪一份         | 入场成本                               |
| ------------------ | ------------------------------------------------------------------------------------ | ------------ | ---------------------------------- |
| **东西的主人（人）**       | **人的位置不是"agent 的前端"**：他自己**也在写事件**（他要做什么、他批准了什么、他**否决**了什么）；他在界面上操作时**不需要知道"字段"是什么** | **给人看的那一份**  | **0**（只要有人把出口做出来）                  |
| **AI agent**       | "请你做什么" + 它的结果                                                                       | **给程序读的那一份** | 低：可先**只读接入**（§7.0）                 |
| **机器／设备**          | 由**驱动**代它写"我做了什么"                                                                    | "要我做什么"      | **中**：需要一个驱动作者                     |
| **驱动／适配器的作者**      | 把一件事翻译成"一种写法"                                                                        | 同一份记录        | **这是一切的前提**——没人写它，账本是空的            |
| **出口（投影）的作者**      | 把同一份事实渲染成给人看／给程序读的两份                                                                 | ——           | 中；**这是"人"唯一的入口**；**D1 的实现者**       |
| **词表的维护者**         | 定义"世界里有什么、字段叫什么、单位是什么"                                                               | ——           | **持续成本**；且**治理规则必须先定**（§7.1 边界 C1） |
| **读账的人（监管／审计／争议）** | 一般不写；只读、只核                                                                           | 原始记录与核对结果    | **0**，但**必须有可读的核对入口**——否则账本只是自述    |

**一条可验收的要求**（替代 v0.1 那句"三方不互相聊"的禁令）：

> **他们之间的任何一次对齐，都必须能在账上被指出是哪一条事件。没有账上的那一条，就没有发生过。**

### 6.2 「直连」的确切含义（**这个词有两个所指，必须先分开**）

> **v0.6 重写**。v0.5 把"机器"写成"经驱动＋投影、不算直连"——**这与既有原文不符**（见下）。
> 而"直连"在既有文档里**有两个不同的所指**，混用会把这一节读反：

| 所指 | 出处（逐字） | 意思 |
|---|---|---|
| **① 各方之间不直连** | `2-依据/15-世界核心的组成与职责.md` §六：**"三方之间没有直连：它们只跟账本对齐，不互相聊。"** | **不许两两谈**（要破坏的那条路由，见 §3.0 a） |
| **② 跟共同的东西直连** | `1-理论与哲学/00-理论定稿.md` §7.3 现行结构图：**"├── 直连：Agent 原生读写（它本来就说结构化）／└── 直连：Computer 原生执行（它本来就要指令）"** | **可以直接跟语义世界打交道**（不必为每对交界各谈一份） |

> **两者不矛盾，而且合起来正是本序的完整主张**：**各方之间不直连（①），但可以直接跟语义世界打交道（②）。**
> **①要破坏的是路由，②要建立的是对齐。** v0.5 把它们混成一个"直连"，于是把原文里明明是直连的"机器"写成了经投影。

**现行结构（照既有定稿的图，不改一个字）**：

```text
真相层：语义事件 ＋ 一本账（一份数据：状态 / 动作 / 事件）
   ├── 投影 1：自然语言（人对话时用）
   ├── 投影 2：图形界面（人看状态时用）
   ├── 投影 3…N：其它出口（留位；新增出口必须同源）
   ├── 直连：Agent 原生读写（它本来就说结构化）
   └── 直连：Computer 原生执行（它本来就要指令）
```

| 谁 | 怎么跟语义世界打交道 | 属于①还是② |
|---|---|---|
| **AI agent／语义系统** | **直连**：它**说的就是语义事件**（不是自己的方言）；**写**经唯一写入口裁决后落账，**读**经给程序读的那一份出口 | **②**（且**不**与任何一方两两直连） |
| **机器／Computer** | **直连**：**原生执行**——它本来要的就是指令，不需要为它临时翻一份 | **②**（同上） |
| **人** | **经投影**：读自然语言／图形界面那两份出口 | **既不①也不②**：人是**唯一配"随行翻译"的一方** |

> **必须写明的两条限定**（都出自既有原文，不是本序新加）：
> 1. **这个结构是不对称的**——既有定稿写得很直白：**"平等 vs 不对称（三方对等 vs 机器直连、唯人配随行翻译）"**。
>    本序**不主张"三方对等"**；人这一侧**天然要经过出口**——这既是代价，也是保护（人不必读结构化的东西）。
> 2. **②不违反既有的"投影之间不交互"**——`15` §7.3：**"投影之间不交互——这就是『同源』的定义。"**
>    "直连"说的是**对齐对象**，不是**出口互相聊天**：各方各读自己那一份，**出口之间不互相调用**。

> **所以"统一底层"的意思不是"大家都改用同一种界面"，而是**：
> **底下一套共同的说法（语义事件 ＋ 一本账），上面各自用自己最合适的那一份（投影／直连）。**
> **三者对齐的是同一份事实——不是同一张界面。**
