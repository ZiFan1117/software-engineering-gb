# 语义世界 · 序

## 一、缺的是"说法"这一层

数据一直在流，接口每天都在调。这两件事都没有坏，缺的是另一层东西。

机器里有的，是**资源的抽象**——进程、内存、文件、设备、权限。它回答"谁能用、用多少、能不能用"，不回答"这句话是什么意思"。于是"意思"只能由参与者各自承担：人靠自己的理解，机器靠写死的协议，agent 靠它被训练出来的经验。三类来源互不相同，也互不担保。

一个例子就够了：两台机器之间传一句"配额 = 5"。一台读成 5 元，一台读成 5 分。两台都没读错，说的却不是同一件事。

问题出在两个缺口上，它们常被混成一句：

- **承载缺口**：同一件事是什么意思，没有一个由各方共同依赖的位置——它只存在于各方的文档、协议和理解里；
- **判定缺口**：起了分歧的时候，没有任何一处能裁定"我们说的到底是不是同一件事"。

上面那个"配额 = 5"的例子，证明的是**判定缺口**。这份序首先要处理**承载缺口**：把"说法"放到一个各方共同依赖的位置上。

## 二、为什么这一层不能由参与方自己承担

**前提**：多方同时在场，且各方只需要向对方交代"这件事是什么意思"。

**命题**：这种时候，"同一件事是什么意思"不能由各参与方各自承担，只能由它们共同依赖的那一层承担。

**理由**：任何一方能承担的意思，都只到自己的边界为止。跨过边界，它没有资格替对方裁定"你理解错了"，没有能力只凭自己拿出一样对方也认的凭据，也没有任何一处可以说"以我为准"。

**失效条件**：如果各方本来就共享同一套来源——同一份规范、同一批人、同一个出厂设定——这一层就不必要。本项目不适用于那种情况。

于是每一次交汇都只能现谈一次；凡是需要意思的地方，都得各自补一遍；而且散场就完：没有任何一处记着"谁还没被告知"。

## 三、主张：这一层由世界承担

由上面的命题，得到两条要求。

**第一**：必须有一个各方共同依赖的层，由它承担"说法"。

**第二**：这个层必须在所有参与者之下。它不能是一个库，不能是一个协议，不能是一个应用——**这就是它属于系统层、不属于应用层的原因**。

计算机的历史上做过一次同样的事：把"资源"从各家程序手里收上来，交给一个共同依赖的层，程序才不必各自去谈硬件。这里把对象从"资源"换成"说法"。

这个层叫**世界**；里面每一条消息叫**语义事件**；以语义事件为接口的那些软件系统叫**语义系统**。它是**极小核心**——只规定"这件事是什么"这一层里最小的那一套，领域自己的概念往上长。它也不是把各方的说法取个交集：像"这件事因为哪一条才发生"这一格，各方本来都没有，它比任何一方都多。

## 四、这一层给的是什么

**它给每一件事一个说法。** 一件事被写下来，要能回答七个问题：谁做的、对什么做的、从什么变成什么、因为什么才发生、排在第几位、谁允许的、什么单位。今天这七格没有都落到实处：有两格（"因为什么才发生""谁允许的"）写下来没有人校验，有一格（"什么单位"）还没有位置可填，其余四格有位置。规格是把七格补齐。答不齐，这件事就有一处说不清；答齐了，这七格谁拿到都看得到。

**它能装的话有三类。** 发生了变更；请你做什么、做完了还是做不到；发生了一件事。三类用同一种形式写。任何一方拿到这三类里的任何一类，都按同一个形式解析，不必先跟对方谈一遍。

**写完还得送到。** 每条消息都有序号；谁该知道，就通知谁。通知可以漏，序号不会漏——漏了补看就行，不必重来。

**最后一条边界**：它不"懂"你的意思，它只把**意思的形式**固定下来。理解仍在各方那里。形式固定之后，大家说的是同一份东西。

这些是手段，不是目的本身。

## 五、一句话

我们要做的只有一件事：**把"说什么"放进世界，让底下这一层讲同一种话。**

以后不管谁接进来——设备、agent、人，还是眼下还没想到的东西——不必先读某一家的文档，也不必先跟谁谈一遍，就能按同一个形式解析对方说的是哪一类事，也能回话，而且知道谁会收到。

对家里的人来说，这件事有一个最要紧的形态：不管是谁——人、agent、还是设备——动了你的东西，你事后都能看见是谁、改了什么、从什么变成什么，而且这条记录不归任何厂商。（这是它要做到的样子。今天能证明的还只是"各方读的是同一份输入"；"从什么变成什么"里的前值，还没有出现在任何一份出口上。）变更只是三类话里的一类；请求与结果、通告，同样有据可查。

我们不要任何人先相信我们。我们只要求：等你看到那条记录时，你能自己去核。
