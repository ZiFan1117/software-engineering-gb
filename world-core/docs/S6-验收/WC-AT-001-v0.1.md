# WC-AT-001 验收测试

> 这份文档管**"凭什么说这一版可以交"**：验收面有哪些、准出判据是什么、验收记录落在哪。
> 它**不重复测试怎么跑**（那在 `WC-ST-001`），**不重复规格条文**（那在 `openspec/specs/`）。

## 一、验收与测试的分工

| | 谁 | 回答什么 |
|---|---|---|
| **测试**（`WC-ST-001`） | 机器 | "这些用例过没过" |
| **验收**（本档） | 机器 ＋ **人** | "**对照书与规格，这一版够不够格交**" |

**人在环里**：评审席由人担任、结论由人签（本仓 `review.md` 的批准人栏**不许代签**）。

## 三、准出判据（**哪些必须绿、哪些红是允许的**）

**必须全绿**：①–⑧ 与 ⑨ 的**判定器自证**（`--self-test` 必须 rc=0——"每条判据都造得出反例"）。
**允许如实红**：⑨ 的**正跑**——当且仅当红项落在**已登记的真缺陷**上、且逐条能在册（清单见 `openspec/BOOK/冲突总账.md`）。
**★ 今天没有如实红项**：每步都过——**读数以 `bash check.sh` 的输出为准，本节不复述数字**（复述的数会过期，而这份文档自己 §五 就写着"不复述读数"）。"允许如实红"这条**口径仍然保留**——它是**规则**，不是"今天有红项"的记帐；但**不许把"今天全绿"读成"以后不会红"**。

**判定规则（不许含糊）**：
1. 一条红**要么**已登记真缺陷（给出登记处与处置）**要么**是缺陷——**不许"红着不管"**；
2. **不许**为了让门禁变绿而放宽判据、删反例、或把读数改小（本项目为此判过"假勾"，并在台账里留痕）；
3. 验收**不是"rc=0"**：**rc=0 且每一步的红绿都能逐条解释**，才算验收。

## 四、验收记录落在哪

| 记录 | 位置 |
|---|---|
| 单次改动的评审与准出 | `openspec/changes/<change>/review.md`（结论／批准人／日期三栏**由人签**） |
| 已归档的评审 | `openspec/changes/archive/<日期>-<change>/review.md` |
| 逐轮的判词、必改、撤回与留痕 | `openspec/BOOK/冲突总账.md` |
| 数值与它们的复算命令 | `openspec/BRIDGE.md` §七（**现算**） |

## 五、这份文档不覆盖的

- **不写"本次验收通过"**——那是**逐次的**结论，写在对应的 `review.md` 里，由人签；
- **不复述读数**（见 `WC-ST-001` §四）；
- **不定义产品行为**——那在规格树与 `WC-IC-001`。
