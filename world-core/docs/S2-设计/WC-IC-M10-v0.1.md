# `WC-IC-M10-v0.1` · **模块接口契约（载体适配器（Carrier Adapter））**

> **本册是什么**：`载体适配器（Carrier Adapter）` 的**模块接口契约分册**（S2 交付物，属 `framework/v0.1` 框架基线）。
> **形态**：**骨架要点册**（要点齐备、正文从简）；**生效即冻结**——本册在其指向的冻结提交上生效。
> **与总则册的关系**：接口编号、信封与错误码契约的**总则**见 `WC-IC-001-v0.1`（该件已**并入分册**，作为本阶段历史总则册保留）。

## §1 本册范围
- 模块号：**`M10`**；模块名：**载体适配器（Carrier Adapter）**
- 承载接口：**`IF-011`**（编号与需求侧同源，见 `WC-IRS-001-v0.1`；本册为该编号的**首次落成**）
- 源码位置与依赖：见 `WC-MODREG-001-v0.1` §2（依赖：`M05` 只请求裁决、`M09` 经通道提交请求）

## §2 接口契约要点（逐项非空）
| 项 | 内容 |
|---|---|
| 提供者 | `M10` |
| 输入 | **执行清单**（`cap.d/*.json`：能力名／执行器／动词表／风险／撤销策略／确认策略／沙箱参数）+ **一次调用**（能力名、动词、请求号、参数）；**不接受未在清单中列明的能力或动词** |
| 输出 | 结构化结果（`result` 三态 ＋ 退出码 ＋ 明细 ＋ 可选的**载体撤销内容引用**）；**输出为纯文本或结构化值，不含二进制序列化** |
| 异常与错误码 | 失败必 **fail loud**：`ext.world.` 前缀 ＋ 明确的"拒绝"与"失败"之分——**拒绝 = 一次都没动**，失败 = 试过了没成 |
| 不变量 | ① **只执行、不裁决**：本模块**永远不能放行**（可以拒绝，不可以放行）；② **对账本零写权限**：它写世界的唯一通道是经 `M09` 向 `M04` 提交请求；③ 连不上内核 ⇒ **拒绝执行**（不做本地降级、不排队）；④ 需要撤销点而做不成 ⇒ **拒绝动手**；⑤ 结果必须带**因果**（`trace` 指向意图事件的 `id`），且与意图**同请求号** |
| 判据（可机械核对） | 见 `WC-IRS-001-v0.1` 中 `IF-011` 的「验收判据」与「应当失败的反例」两列；系统级实测见 `tools/carrier_acceptance.sh`（22 项断言，含 4 条"应当失败"的反例） |

## §4 进程边界（**权限边界**；2026-09-27 新增）
| 项 | 内容 |
|---|---|
| 本模块所在进程 | **载体执行器进程**（与被管者同身份） |
| 本模块对账本的权限 | **无权限**（它不持有账本描述符；见 `WC-MODREG-001-v0.1` §2.4 的进程表） |
| 接口形态 | **跨进程线协议**（行分隔、纯文本、一行一帧）：它对内核的每一次提交都走 `M09` 的通道 |
| 跨进程时的身份 | **由套接字的属主与权限决定**；请求体里自称别的身份一律拒绝 |

## §5 与"另一个快照"的区分（本册特有）
| 名字 | 谁做 | 撤的是什么 | 地位 |
|---|---|---|---|
| **载体撤销** | 本模块 | 文件系统的字节 | **不是世界状态**；只作工程兜底，**不得**用于满足"坏了能回滚" |
| 检查点 | `M08` | 什么都不撤（只是重放加速） | 缓存，不是真相 |
| 补偿事件 | `M04` | **世界状态** | 这才是"回滚"的正身 |

**载体撤销的产物进账本的方式**：以**内容引用**的形式作为**事件里的一个字段值**出现，而不是"另一份真相"。
