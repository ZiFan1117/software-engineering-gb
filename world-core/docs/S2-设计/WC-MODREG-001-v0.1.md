## §1 目的与范围

1. **目的**：把 `world-core` 的模块划分、模块号及其与源码的对应关系**登记为可核对的事实**，使「某模块号是否真实存在」「某模块的职责与源码是否一致」两件事都有唯一判定面。
2. **范围（在）**：`world-core/src/` 的模块边界、模块号分配、每个模块的职责/源码路径/提供接口/依赖模块。
3. **范围（不在）**：接口的字段级契约（见 `WC-IC-001`）、需求条目（见 `WC-IRS-001`）、接口需求编号的同源核对（见 `WC-IRS-001` §3.1）、层（L1–L4）与实现顺序的完整论证（见附录 A §二）。
4. **登记粒度**：**一个源码模块文件 ↔ 一个模块号**，例外只有两处共同模块（`src/event.rs`、`src/project/mod.rs`），在 §2.1 逐条声明其不占号的理由。**`src/error.rs` 不属于任何模块号**，其归属缺口见 §2.1。
5. **编号口径**：接口一律三位 `IF-001`–`IF-010`（来源：`WC-IC-001` §一 接口清单，10 行）。**两位短号（`IF-1`/`IF-01`）视为无效引用**（来源：`WC-IC-001` §一末「接口编号规则」）。

## §2.4 进程边界（**权限边界**）与层的关系

**登记事实**：本表此前只有"层"（表达**依赖方向**），没有"进程"（表达**权限边界**）。两者是正交的，混在一列里会让读者把"同层"误读成"同进程"。本节补上第二列。

| 进程 | 装哪些模块 | 身份 | 对账本（L1·事实）的权限 | 依据 |
|---|---|---|---|---|
| **内核进程** | `M01`、`M02`、`M03`、`M04`、`M05`、`M09` | 世界核心 uid | **可写（唯一写者）** | 唯一写入口由"只有本进程持有账本可写描述符"实现 |
| **投影服务进程** | `M06`、`M07`（可选 `M08`） | 独立 uid | **只读** | 出口只读同一读模型；两块出口权限相同故可同进程 |
| **载体执行器进程** | `M10` | 被管者 uid（如 `agent`） | **无权限** | 它必须动载体，故必须与法律和真相分离 |

**两条口径**（本表新增，生效条件同 §2.2 的层）：

1. **进程边界画在权限变化处，不画在职责变化处**——权限相同的模块（如两块出口）同进程是合规的；权限不同的模块（如"只读出口"与"动载体的手"）必须分开，无论它们职责多相近；
2. **同一模块号可跨进程只有一种例外**：`M08` 检查点是纯缓存、无写权限，故既可留在内核进程，也可随投影服务进程（由部署方按需选择），**但不得因此获得任何写权限**。

**未采纳的切法与本表口径**：按"本体 / 账本 / 读模型各一个进程"切开**不予采纳**——三者写权限相同，切开只会把"事件已落账本、读模型未跟上"变成常态。门禁独立成进程在 v1 **不予采纳**——它在写路径的关键路径上。

**与层的关系**：层不变（`M10` 归 L3，理由见 §2.2 表）；进程是层的**进一步约束**——同层模块可以在不同进程里，不同层模块也可以在同一进程里（如 `M02` 与 `M03` 分属 L1/L2 却同在内核进程）。**"同进程"不构成"可以互相写"的许可。**

### 2.4.1 跨进程后"唯一写入口"的确切表述

> **账本只有一个写者，就是内核进程。** 其余任何进程都只能**请求**内核追加事件，**没有任何进程能自己写账本**。

单进程时那句话是"进程内只有一个函数能追加"；跨进程时它升级为"**全机只有一个进程能追加**"，且该事实可由部署侧直接核对（谁是账本属主、谁持有可写描述符）。

## §3 模块编号规则

| 规则 | 内容 |
|---|---|
| 书写 | `M` + 两位数字，**左补零**（写 `M01`，不写 `M1`） |
| 唯一 | 一经分配**永不复用**；模块废弃则号作废不回收 |
| 与源码的对应 | 一个 `.rs` 文件至多归属一个模块号；共同模块必须在 §2.1 显式声明「不占号 + 归谁」 |
| 接口列 | 每个模块**必须**至少有一条 `IF-00x`；缺失即登记不完整（回填历史见附录 A §五 #5） |
| 变更 | 新增/合并/拆分模块号属配置项变更，须走变更控制；触及契约者走 R5（口径见附录 A §四） |
| 校验 | 追溯矩阵里出现的每个模块号都必须能在 §2 找到；**本文件正文不得出现非本项目的模块号** |
| 层 | 层由 §2.2 表达，**不编码进模块号** |

### §4.2 循环依赖判定

**结论：无循环。** 判定面分两层——(a) 登记表的「依赖模块」列；(b) 源码面 `use crate::…` 实际边。

### 一、分配决定：**十个模块（M01–M10）**

> **为什么是十个**：本节原写「九个模块（M01–M09）」。`M10`（载体适配器）由**进程拓扑变更**引入并已登记进 §2 `:39`、§2.2 层表 `:62`、进程表 `:94`（**谁的指示**：该变更的裁定见 `WC-R4-DISP-001`；**谁批的**：项目负责人）。⇒ 本节标题随之更正为「十个模块（M01–M10）」，**其余九条的分配理由一字未改**。

**决定**：采用 **9 个模块**，而非 `07/4-计划/04` §一 的"六个模块"。

**理由**（三条，逐条可核）：

1. **两个投影是两件可独立替换的产物**，不是一件事的两个函数：
   语言投影给程序读、视觉投影给人看，各自的输出格式是**独立契约**
   （`src/project/language.rs` / `visual.rs` 头部即各自契约），
   各自有独立验收测试（`t14` / `t15`）。合成一个模块号会让
   "换掉视觉渲染器"看起来像"改了投影模块"，**掩盖变更的真实影响面**。
2. **检查点是独立关注点**：它是**带 `base_seq` 的缓存**（性能手段），
   与读模型（真相的派生）在语义上不同类——混在一个模块号里，
   将来"缓存变成了第二真相"这类事故就没有清晰的边界可查。
3. **通道是跨进程边界，与"装配与启动"不是一件事**：`M09` 通道负责"**一个套接字一个身份、权限即身份**"，它面对的是**本机其他进程**；
   `M04` 运行时负责进程内的装配与启动。合成一个模块号会让"放宽了套接字权限"看起来像"改了启动流程"，**掩盖安全边界的变更**。
4. `WC-FSR-001` §4.1 已按此拆分（原写 `M01`–`M08`，S2 增 `M09`），且 FSR 已声明
   "最终以 S2 模块清单为准"；本文档即那个"为准"。

#### 2.1 层（L1–L4）说明

> **关于"声明与源码是否一致"**：本表只写**声明**。"一致"**不由人自证**——它由 `world-core/tools/module_graph.py` 机核（A-1/A-4/A-2 三条判据）。该工具有**已知抽取缺口**（只认行首 `use`，不认行内全限定路径 `crate::…`，与它的文件头自述不符），所以它报的"声明了但代码里没有"可能是**工具缺口**而不是登记错误；**缺口本身已登记，未修**。

> "表现层 M01–M19 / 业务层 M20–M39 / …" 分层区间约定。那套约定是为

   M09 通道（跨进程入口）── 请求（文本行）──▶ 进入 `M04` 的唯一写入口

       ├ 只执行、不裁决：允不允许一律问 `M05`（经 `M04`）
       └ 对账本**零写权限**（它跑在被管者 uid 下）                    L3 治理与机制

> **`M09` 不得绕过 `M04`**：通道只做「身份 → 请求 → 应答配对」的搬运，**自己不写账本**（硬约束 ②）。
> **`M10` 不得绕过 `M04`/`M05`**：载体适配器只做「按执行清单调载体」，**自己不裁决、不写账本**（硬约束 ②＋⑤）。

**硬约束**（违反即设计级缺陷，见 `WC-SQAP-001` ST-10）：

1. **L2/L4 不得写 L1**：读模型与投影都不能改账本（`REQ-F-012` 已用测试锁死）；
2. **L3 是唯一写入通道**：`World::commit` 之外没有第二条写路径（`REQ-F-006`）；
3. **L4 之间不交互**：两个投影只接受 `(&State, world, vocab)`，无共享可变状态（`REQ-F-020`）；
4. **M05 不得依赖 L4**：门禁不关心"谁会看到"，只关心"能不能做"。
5. **M10 不得自行放行**（2026-09-27 新增）：载体适配器**只执行、不裁决**；它自己**没有"允不允许"的话语权**，必须经 `M04` 请求 `M05` 裁决。理由：执行清单里的风险等级是**载体侧执行策略**，不是世界的法律；若两处都能决定放行，就出现"两套法"。**它的不对称性**：可以**拒绝**（连不上内核即拒绝执行），永远不能**放行**。
6. **M10 对账本零写权限**（2026-09-27 新增）：它跑在被管者 uid 下，与法律和真相**分属不同属主**。这不是优化，是"门禁不可绕过"能否成立的前提。
