## 场景 A："WiFi 连不上，帮我修一下"

### 现状：agent + shell（逐步真实流程）

| 步 | 动作 | 花费 | 风险点 |
|---|---|---|---|
| 1 | LLM 推理 → 生成 `nmcli device wifi list` | ~2s / 600 token | — |
| 2 | 解析输出文本 | — | SSID 带 `**` 转义、中文 locale 字段错位 → **理解跑偏** |
| 3 | 生成 `nmcli device wifi connect HomeNet password ???` | — | **密码从哪来？** 卡住，或从聊天记录瞎猜 |
| 4 | 权限问题：要么全程 sudo（暴露面全开）要么卡在 sudo 密码 | — | **权限全有或全无** |
| 5 | 连接失败 → 重新推理 → 换 `ip link set wlan0 up` 再试 | ~2s | 和 NetworkManager **状态打架** |
| 6 | 终于连上（"看起来"成功） | — | 无结构化确认；NM 后台可能又改回配置 |
| 7 | 你问"修好了？" → agent 再跑一遍命令"确认" | ~2s | — |

**账单：4-6 次推理（约 3000 token）、4 个失败模式、全程 sudo、零审计、零回滚。**

### 目标架构：agent + agentd + varlink

| 步 | 动作 | 花费 | 风险点 |
|---|---|---|---|
| 1 | agent → agentd：`Request(network.wifi.diagnose)` | ~2s / 300 token | 能力在 cap.d 白名单内 ✅ |
| 2 | agentd 查授权 → varlink 调 `NetworkProvider.Diagnose()` | ~50ms | — |
| 3 | 返回**结构化诊断**：`{state:"auth_timeout", ap:"HomeNet", driver:"iwlwifi", last_error:"..."}` | — | 无解析歧义 |
| 4 | LLM 只做它擅长的事：判断"auth_timeout → 该重置密钥重连" → `Request(network.wifi.reconnect, {forget_key:true})` | ~2s / 300 token | risk=medium → **自动快照网络配置** |
| 5 | provider 执行 → journald 记录 → 返回 `{ok:true, state:"connected", ip:"192.168.1.34"}` | ~3s | — |

**账单：2 次推理（约 600 token）、0 文本解析、权限=1 个 capability、自动快照、全程审计。**

### 对比总表

| 维度 | 现状 | 目标架构 |
|---|---|---|
| LLM 推理次数 | 4-6 次 | **2 次**（省 60-80% token） |
| 文本解析失败面 | 每一步 | **0** |
| 权限暴露 | root / 全有全无 | **1 个 capability** |
| 可回滚 | 无 | **自动快照 + rollback** |
| 可审计 | 翻聊天记录 | **journald 结构化字段** |
| 出问题时你看到什么 | agent 道歉 | `journalctl -t agentd OUTCOME=failed` 一条定位 |

## 场景 B："程序崩了"（Omarchy 已有雏形 vs 完整版）

### Omarchy 现状（值得尊重的 0.5 版）

```
进程崩溃 → systemd-coredump 落盘
  → 桌面通知"Process crashed" → 【用户】点击
  → Omarchy 把 coredump 文本 + diagnose-crash skill 塞给 agent
  → agent 分析 → 给出"值得/不值得报上游"的建议
```

单向、一次性、要用户点击、agent 拿到的是"一份文本"。

### 完整版（agent 以系统服务身份订阅事件）

```
agentd 通过 varlink 订阅 io.systemd.CoreDump 事件（✅ systemd 已支持此协议）
  → 崩溃发生，agentd 自动收到事件（不用用户点）
  → 路由给默认 agent + 诊断上下文（coredump 元数据、最近日志、版本信息）
  → agent 分析 → 自动搜上游 issue → 起草报告存到 ~/Work
  → 桌面通知："已为你起草 bug 报告" + 【一键提交】
  → 全程 journald 审计
```

用户动作从"点一次"变"看一眼"。**Omarchy 与完整版的差距只在一点：
前者是"把文件塞给一个进程"，后者是"agent 作为一个系统组件订阅系统事件"。**

## 什么不会变（诚实清单）

1. **LLM 推理依然是最贵的一步**——架构优化省的是"管道浪费"（重复推理、解析失败重试），
   省不了单次思考的时间。所以收益以可靠性/安全/审计为主，速度为辅。
2. **长尾操作仍会 fallback 到 shell**。世界上的命令太多，不可能每个都有 provider。
   所以 agentd 保留一个兜底能力：

   ```yaml
   # /etc/agent/cap.d/shell.yaml
   capability: shell.sandboxed
   provider: builtin
   risk: medium
   sandbox: landlock-strict   # 兜底的 bash 也被 Landlock 锁着
   ```

   形态是：**主干结构化，长尾留逃生舱**——就像驱动模型里也总留着通用 HID 兜底。
3. 桌面（Hyprland/Quickshell）不需要重写——它只是 agent 的一类客户。
