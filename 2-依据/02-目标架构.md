## 1. agent.service —— 先给 agent 上"户口"

agent 不再是你在终端里随手敲的一个进程，而是系统管理的一个常驻服务：

```ini
# /etc/systemd/system/agent.service
[Unit]
Description=System agent runtime
After=multi-user.target

[Service]
ExecStart=/usr/bin/agentd --harness=opencode
User=agent                         # ✅ 专用用户，不是你
MemoryMax=4G                       # ✅ 内存上限：跑 build 也不拖死桌面
CPUQuota=200%                      # ✅ 最多吃 2 个核
TasksMax=512                       # ✅ 防 fork 炸弹
ProtectSystem=strict               # ✅ 文件系统默认只读
ReadWritePaths=/home/user/Work     # ✅ 唯一可写的工作目录
PrivateTmp=yes                     # ✅ 隔离的 /tmp
NoNewPrivileges=yes                # ✅ 永远拿不回 root
Restart=on-failure                 # ✅ agent 崩了自动重启

[Install]
WantedBy=multi-user.target
```

**全部 ✅——每一行都是 systemd 今天就支持的配置，零新代码。**
效果：agent 第一次成为"可被系统管理的组件"，和 sshd 地位相同：

```bash
systemctl status agent        # 活着没、吃了多少内存
journalctl -u agent -f        # 它正在干什么
systemctl stop agent          # 一键勒停（你试过"杀掉所有agent"吗？现在能了）
```

## 2. 能力声明 —— 把"驱动 probe"翻译过来

驱动模型和 agent 模型是**同一个模式**：

| 驱动世界 | agent 世界 |
|---|---|
| bus 匹配 device ↔ driver | 请求匹配 capability ↔ provider |
| 驱动注册 probe 函数 | provider 注册 varlink 接口 |
| 设备插上自动绑定 | 能力声明装上自动生效 |
| 驱动卸载不拖垮系统 | 能力吊销不拖垮 agent |

能力声明文件（格式 🆕 新造，但只是 YAML 配置）：

```yaml
# /etc/agent/cap.d/backlight.yaml   —— 低危能力
capability: brightness.set
provider: varlink:///run/agent/backlight.sock
verbs: [get, set]
risk: low
audit: always
snapshot: never
```

```yaml
# /etc/agent/cap.d/package.yaml     —— 高危能力
capability: package.install
provider: varlink:///run/agent/pacman.sock
risk: high
audit: always
snapshot: before-each        # 每次装包前自动快照！
require: confirm             # 需要用户点一下桌面通知确认
```

agent 发出的每个请求都长这样，由 agentd 路由：

```
Request(capability=package.install, args={pkg:"ripgrep"})
   → agentd 查 cap.d：✅有此能力、risk=high → 先快照 → 弹确认
   → 用户点"允许" → 转发给 pacman provider → journald 记录 → 返回结构化结果
```

**这就是你要的"agent 即插件"：能力即插拔，声明即授权，吊销即卸载。**

## 3. varlink 接口 —— 结构化的"命令行"

varlink 是 systemd 生态真实的接口定义格式（JSON），示例：

```json
{
  "ext.agent.Brightness": {
    "Get": "() -> (level: int, max: int)",
    "Set": "(level: int) -> (newlevel: int)",
    "error_Unsupported": []
  }
}
```

对比：

```bash
# 现状：调命令、猜文本
$ brightnessctl set 60
setting backlight to '60'      ← agent 要"读"这句人话

# 目标：RPC、拿字段
varlink call /run/agent/backlight.sock ext.agent.Brightness.Set '{"level":60}'
{"newlevel": 60}               ← 结构化，无歧义
```

错误也是类型化的（`ext.agent.Brightness.Unsupported`），LLM 不用从散文里猜失败原因。
✅ `varlinkctl` 今天就能用；过渡期可以先用 MCP server 顶着，协议语义等价。

## 4. 快照回滚 —— agent 的 Ctrl+Z

```
规则（agentd 内置）：
  risk=high 的调用前：  btrfs subvolume snapshot / /run/agent/.pre/<action-id>
  失败或用户反悔：      agentd rollback <action-id>
                       → 恢复快照 + 在审计日志里记一条 ROLLBACK
```

✅ btrfs 快照毫秒级、零拷贝，今天就能用。
NixOS 用户早已享受"任何系统改动一键回滚"——只是没人把它**接进 agent 的动作流**，
让 agent 敢无人值守地干活、你敢让它无人值守地干活。

## 5. 审计 —— journald 结构化字段

agent 的每个意图和动作写一条带字段的日志（✅ journald 支持，字段约定 🆕）：

```bash
$ journalctl -t agentd -o verbose
    INTENT        = package.install
    CAPABILITY    = package.install
    PARAMS        = {"pkg":"ripgrep"}
    SNAPSHOT      = /run/agent/.pre/a-173f
    GRANTED_BY    = user-consent-2026-09-22T10:00:03Z
    OUTCOME       = ok
    DURATION_MS   = 4211
```

你随时可以：

```bash
journalctl -t agentd --since today              # 今天 agent 干的一切
journalctl -t agentd OUTCOME=failed             # 所有失败动作
journalctl -t agentd CAPABILITY=package.install # 所有装包记录
```

**这是聊天记录永远给不了的可信度**：审计在 agent 之外、带结构化字段、不可被 agent 自己删改。

## 6. 自我限制 —— Landlock + seccomp

agentd 启动的第一件事：加载 Landlock 规则集把自己锁进白名单
（✅ 内核 5.13+，非特权可用，进程自我约束）：

```
允许读:  /usr        /etc（只读）    /proc
允许写:  /home/user/Work             /var/lib/agent
其余:    一概拒绝（内核强制，不是君子协定）
```

之后**哪怕 agent 被 prompt 注入攻击**（网页里藏一句"忽略之前的指令"），
它物理上碰不到 `~/Documents`、你的 SSH 私钥、浏览器的 cookie。
再叠一层 seccomp（禁 `ptrace`、禁内核模块加载），双保险。✅ 全部现成。

## 7. eBPF 的正确位置 —— 观测，不是操作

- agent 需要"看真相"时：生成一条 bpftrace 单行程序直接观测内核
  （`bpftrace -e 'tracepoint:syscalls:sys_enter_openat { ... }'`）——✅ 今天可行
- 数据面高性能任务（agent 写的过滤器跑在内核里）→ 还是 eBPF
- **不要**把 eBPF 当通用"操作接口"——那是给观测和特殊性能用的手术刀

---

## 8. 多 agent 调度 —— cgroup 的第二次胜利

- 每个 agent 实例 = 一个 systemd scope → cgroup 天然隔离，互不拖累
- agentd 维护一张互斥表：同一 capability 同时只授予一个 agent（谁也不能边上的 agent 改配置改一半时插手）
- 优先级：`systemctl set-property agent-A CPUQuota=50%` —— 用现成的 systemd 机制给 agent 分级

🔧 仅互斥表和等待队列是新造的，几百行。

## 9. 汇总：每个部件的工作量

| 部件 | 底层机制 | 状态 |
|---|---|---|
| agent.service（户口+资源限制） | systemd / cgroup | ✅ 机制全在，配置文件新写 |
| **agentd（能力路由器）** | 自研守护进程 | 🆕 **核心工作量，Go/Rust 约 2-3k 行** |
| 结构化接口 | varlink（或 MCP 过渡） | ✅ 协议在；各子系统 provider 要写 |
| 快照回滚 | btrfs | ✅ 在；钩子逻辑 🆕（很小） |
| 结构化审计 | journald | ✅ 在；字段约定 🆕 |
| 沙箱 | Landlock / seccomp | ✅ 在；默认策略 🆕 |
| 多 agent 互斥 | systemd scope | 🔧 等待队列 🆕（几百行） |

> **看不出来的重点：新造的代码总量不到 3k 行，其余全是给现成机制写配置。**
