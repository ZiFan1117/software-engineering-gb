# 13-总线与通道外部参考：走线与通道的现成答案（附亲验来源）

> 一句话：`传` 的**语义规格**我们已经有了（[11 篇](11-总线工程规格.md)），但**走线**没有——
> 分帧、寻址、序号、自省/发现、订阅回放、权限边界这六件事，外部有一批被反复验证过的答案。
> 本篇把它们逐件核实、逐条标注"该抄 / 不该抄"，并给出**总线 v0 的走线硬决定**。
> 结论中最承重的一条：**四类消息里的「引用（内容 hash）」五个 agent 协议全缺，必须自造**。
>
> 整理日期：2026-09-26。前置：[00-总纲](../00-总纲.md) §2.3（`传`）、§6–§7（能力与四道门）、
> §9 动作 3（写总线 v0）；[11 篇](11-总线工程规格.md) §八（三条待批判项，本篇逐条给出候选解）。
>
> **本篇性质是「对照」**：与 [12-内核选型对照.md](12-内核选型对照.md) 同档——**事实层与核实来源**，
> 不作决策。凡与总纲冲突，以总纲为准。
>
> **核实方式**：2026-09-26 三路并行检索（agent 侧协议 / 经典总线与 IPC / 状态与事件底座），
> 均**逐页打开官方规范正文**，不采信二手博客。本篇作者对本表打了两次独立抽查
> （D-Bus 授权边界原文、varlink 协议原文），**并更正了一处 URL 错误**（§八）。

> **修订标注（2026-09-26，据本会话裁决）**：本篇 §五 的"硬决定"里，凡**借用外部规范的
> 消息语义**——CloudEvents 四必需属性、AG-UI 的 snapshot/delta 三件套、DAP 的能力 flag 命名、
> varlink 的 `GetInterfaceDescription` 接口形状、ACP 的 `session/update` 变体表——
> **一律降级为"反面参照"，不得作为本世界的协议条款**。
> 理由：**这要的是一套全新的东西——总线与通道，两端都必须是世界核心（语义内核）**，
> 中间不设适配器、不设翻译层；**两个投影面同源，同样是世界核心的投影**。
> 判据沿用 [09 篇 §二](09-理论修正推导.md) 的**锚定 vs 依赖**与总纲 §2.3 原文：
> **"用别人的管道传自己的话，不算被锚定"**——即外部件只能在**管道层**（分帧、传输、游标实现、
> 哈希算法）被借用，且必须是**可替换的传输**；**schema、消息语义、身份、能力、不可逆分级、
> 投影规则、发现语义一律自造**。
>
> 由此，本篇的价值重排：**§六（红线/反面清单）与 §四（缺口量化矩阵）升为首要价值**——
> 它们证明"没人做过两端都是语义内核的总线"；§五 退为**管道层候选**，且仅在被判定为
> "换掉管道、世界语义一字不改"时才可采用。

## 三、逐件：该抄 / 不该抄

### 3.1 agent 侧协议（5 件）

**MCP**（[spec](https://modelcontextprotocol.io/specification/2025-06-18)）
- 已核实：JSON-RPC 2.0；`tools/call {name, arguments}` → `{content:[{type:"text",text}], isError}`；Tool 含 `inputSchema`/`outputSchema`/`annotations`；stdio 分帧原文 "Messages are delimited by newlines, and MUST NOT contain embedded newlines"。
- **抄**：能力协商 + 工具定义的 input/output schema → 对应我们②动作。
- **不抄**：resources 只有"读一次"语义，**没有任何状态快照/diff**，**无 seq**。规范自己承认 "protocol itself cannot enforce these security principles at the protocol level"——正好反证我们"门禁必须在协议之外有强制力"的立场（总纲 §2.4）。
- ⚠ 旧资料坑：**HTTP+SSE 传输已被 Streamable HTTP 取代**（2024-11-05 → 2025-06-18）。

**A2A**（[spec](https://a2a-protocol.org/latest/specification/)，规范源 `a2a.proto`）
- 已核实：`Task{id, context_id, status, artifacts[], history[]}`；`TaskState` 8 值；`Part` 是 oneof `{text, raw, url, data}`；流式事件只有 `TaskStatusUpdateEvent`、`TaskArtifactUpdateEvent{append, last_chunk}`；`AgentCard` 含 `supported_interfaces[]`/`capabilities`/`skills[]`/`signatures[]`。
- **抄**：`AgentCard` 作为**物种自描述卡**（"谁来读？人读的那一栏"）；`append`+`last_chunk` 的分块重组（我们④引用分片可用）。
- **不抄**：**"任务是一等公民"的模型**——我们的世界是**共享状态**，不是任务队列；无 seq 导致断线只能整块重连；治理是任务级授权，**不按不可逆性**。
- ⚠ 旧资料坑：v1 已移除 `kind` discriminator 与 `final` 字段（GitHub issue #1433）。

**ACP**（[spec](https://agentclientprotocol.com/protocol/v1/overview)，DSH 正在用）
- 已核实：`session/update` 通知有 **11 种变体**（`agent_message_chunk`/`tool_call`/`tool_call_update`/`plan`/`available_commands_update`/`current_mode_update`…），信封 `{jsonrpc, method:"session/update", params:{sessionId, update:{sessionUpdate:…}}}`。
- **抄**：①**discriminated union**（一个字段切变体，天然自描述）②**session modes**——五个协议里**唯一**接近我们"按能力治理"的设计。
- **不抄**：无状态快照/diff、无引用/hash；本质是"点对点请求响应 + 通知"，**不是总线事件广播**。
- ⚠ 坑：其 **Streamable HTTP 官方标注 draft**，别依赖。

**AG-UI**（[spec 1.0](https://docs.ag-ui.com/spec/1.0)，[schema.json](https://docs.ag-ui.com/spec/1.0/schema.json)）
- 已核实：`EventType` enum **31 个**，其中 `STATE_SNAPSHOT` / `STATE_DELTA` / `MESSAGES_SNAPSHOT` / `ACTIVITY_SNAPSHOT` / `ACTIVITY_DELTA`；`STATE_DELTA` 用 **RFC 6902 patch**（原子应用，失败保留旧值并 warn）；规则："patch 不适用时 producer SHOULD 重发 snapshot"。
- **抄（优先级最高）**：①的三件套（snapshot / delta / messages_snapshot）+ 那条恢复规则——**这是五个协议里唯一完整覆盖我们①状态的设计**；`ACTIVITY_*` 分族是"人看的界面投影与 agent 读的语言投影同源"的良好范例（对应我们 `显`）。
- **不抄**：31 个事件类型对我们**过细**；`RAW`/`CUSTOM` 逃生舱**会破坏自描述**。

**OpenAI Responses / Realtime**（平台文档 403，改核实官方 SDK 生成类型）
- 已核实 `ResponseTextDeltaEvent`：`{content_index, delta, item_id, output_index, **sequence_number:int**, type:"response.output_text.delta"}`；命名法 `response.<resource>.<action>` 三段式，整体对象出现一次 + 增量出现 N 次。
- **抄**：**`sequence_number`（五个协议里唯一可抄的顺序方案）**；三段式命名；"粗快照 + 细 delta"的配比。
- **不抄**：无治理、无发现；`delta` 是**裸字符串，单条不可独立理解**——违反我们"大模型不读文档也能读懂"的判据。

### 3.2 经典总线与 IPC（5 件）

**D-Bus**（[spec](https://dbus.freedesktop.org/doc/dbus-specification.html)，[dbus-daemon.1](https://dbus.freedesktop.org/doc/dbus-daemon.1.html)）——**本篇作者亲验**
- 消息类型 `METHOD_CALL=1/RETURN=2/ERROR=3/SIGNAL=4`；头签名 `"yyyyuua(yv)"`；serial "must not be zero"；字段含 `REPLY_SERIAL`/`DESTINATION`/`SENDER`/`SIGNATURE`；**未知字段必须接受并忽略，已知字段类型错即 corrupt**。
- **原文证实**：「D-Bus is first a library that provides one-to-one communication… dbus-daemon is an application that uses this library to implement a message bus daemon」→ **与"第一版无中心、将来加 busd"完全同构**（11 篇 §二 的架构决定有了外部先例）。
- **原文证实**（治理边界）：「the dbus-daemon's policy language is **not well-suited to finer-grained policies**… expressed in terms of D-Bus interfaces and method names, not higher-level domain-specific concepts」，故建议「services should normally **accept method call messages from all callers, then apply a sysadmin-controllable policy**」→ **"总线只判传输与名字，语义授权下沉服务"**，正是我们"治理非地基、agentd 挂了总线照跑"（总纲 §6 `管`）的外部依据。
- **抄**：①头字段"发送方控制 / 总线控制"的**显式归属表**；②`serial` + `REPLY_SERIAL` 配对；③`receive_*` 规则**对每个收件人逐一判决**。
- **不抄**：二进制头把地址与类型签名**硬绑在帧上——大模型不可读**，违我们"自描述"判据。

**varlink**（[varlink.org](https://varlink.org/)，Protocol 为页内锚点）——**本篇作者亲验**
- **原文证实**：「All messages are encoded as JSON objects and **terminated with a single `NUL` byte**」；「A service responds to requests **in the same order that they are received—messages are never multiplexed**」（但可 pipelining）。
- **原文证实**（自省）：「Every varlink service offers the `org.varlink.service` interface」「Everything can be documented by adding a comment immediately before it. **The documentation is provided to clients as structured data**」；`Monitor()` 示例即"状态变化就回一条"——
  **这就是"自描述到大模型能懂"的最佳现成形态**，也是 11 篇 §八-2"第五类发现消息"的直接答案。
- **原文证实**（将来的中心）：「Public varlink interfaces are registered system-wide… by default `/run/org.varlink.resolver`」「**Multiple services can implement and offer the same interface, but only one of the services is registered with the resolver**」。
- **抄**：①`NUL` 分帧；②`more`/`continues`（一次调用多次回复）；③`GetInterfaceDescription` + 注释即文档；④resolver 作为**可选的将来中心**。
- **不抄**：`upgrade` 交出连接后脱离协议控制（调试噩梦）；同名接口只能注册一个服务（**多投影会打架**）。

**LSP / DAP**（[LSP 3.17](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/)，[DAP](https://microsoft.github.io/debug-adapter-protocol/overview)）
- 分帧：头 + `\r\n\r\n` + **`Content-Length` 必需**（字节数）；头 ASCII、体 UTF-8；LSP 体是 JSON-RPC 2.0。
- **能力协商**（对我们最有用的一条）：LSP initialize 交换 capabilities，"Clients should ignore server capabilities they don't understand"；DAP 明确 **"absence of the flag always means the feature is not supported"**，且**永不引入版本号，只加 flag**，另有 `capabilities` 事件动态更新。
- **抄**：①`Content-Length` 分帧；②**能力 flag 永不升版本**（直接解我们"版本协商没有"这个缺口，也避免重演 varlink 自称→废止）；③请求/通知/事件三分 + `seq`；④`$/` 命名空间留给扩展。
- **不抄**：LSP 假设"一个 server 服务一个工具"，无多路复用与文档锁。

**NATS / JetStream**（[subjects](https://docs.nats.io/concepts/subjects)、[jetstream](https://docs.nats.io/concepts/jetstream)）
- subject 点号分层，`*` 匹配恰好一个 token、`>` 匹配一到多个。
- JetStream 原文：核心 NATS 是 at-most-once 且不重放；JetStream 提供 at-least-once，写入时 **"assigns it a sequence number"**；consumer 是**服务端有状态游标**，可从 beginning/latest/指定 seq/指定时间起读，未 ack 重投。
- **抄**：①subject 层级 + 通配（语义广播寻址）；②**服务端游标式 consumer**（对应"agent 重连后要回放"）；③inbox 式 request-reply；④stream 分配的 sequence 作为权威序号。
- **不抄**：**queue group 的随机且不感知负载的分发**（原文 "does not account for how busy a member is"）——我们有**不可逆动作，不能随机落到某个执行者**。

**CloudEvents**（[spec](https://github.com/cloudevents/spec/blob/main/cloudevents/spec.md)）
- 四条必需：`id`（`source`+`id` 必须唯一 → **天然去重语义**）、`source`、`specversion`、`type`；可选 `datacontenttype`/`dataschema`/`subject`/`time`。
- 关键机制原文：context attributes "can be serialized **independent of the event data**… inspected at the destination without having to deserialize the event data"；**中介 MUST 转发 ≤64 KiB，消费者 SHOULD 接受 ≥64 KiB**；安全章**鼓励事件里放链接而非内嵌大数据**，以便差异化访问控制与选择性披露。
- **抄**：①`id`+`source` 去重；②`subject` 供中间层过滤；③`dataschema` 声明；④**64 KiB 上限 + 大对象换引用外置**——这**直接支撑我们④引用类消息**，也支撑铁律 2"证据须不可否认"（引用即证据）。
- **不抄**：它**无序号、无订阅、无回放**——只当**信封的一层**，别当总线。

### 3.3 各一句：ZeroMQ / gRPC / Kafka

| 件 | 该用在 | 明确别用在 | 原文依据 |
|---|---|---|---|
| **ZeroMQ** | **通道层**（inproc/ipc/tcp 一套 API、自动重连、多段帧） | 当总线 | "ZeroMQ is **not a neutral carrier**: it imposes a framing on the transport protocols it uses"；PUB/SUB 无回话，"加入之前的一切都错过"、慢订阅者丢消息 |
| **gRPC** | **将来守护进程与外部语言的强类型边界** | 内部广播 | "gRPC guarantees message ordering **within an individual RPC call**"；是 RPC 不是 topic，无订阅/回放，proto 自描述弱于 JSON |
| **Kafka** | **事件日志与回放的持久层参照**（同 key 同分区保序） | 第一版 | "Events with the same event key are written to the same partition"；按保留期删除、可重复读；重运维，与"无中心起步"冲突 |

## 四、对四类消息的覆盖矩阵（本篇最承重的一张表）

| 我们的消息类 | MCP | A2A | ACP | AG-UI | OpenAI | D-Bus | varlink | 结论 |
|---|---|---|---|---|---|---|---|---|
| ①状态 快照+diff | 缺 | 部分（Task 快照，无 diff） | 缺 | **完整**（SNAPSHOT+DELTA+MESSAGES_SNAPSHOT） | 部分 | 可（SIGNAL+Properties） | 无内建 | **抄 AG-UI** |
| ②动作 请求/结果 | **完整**（tools/call） | 完整 | 完整 | 部分 | 缺 | 完整（METHOD_CALL/RETURN） | 完整 | 形态成熟 |
| ③事件 | 部分（notifications） | 部分 | **完整**（11 变体） | 完整 | 完整 | 完整（SIGNAL） | 部分 | **抄 ACP 的 discriminated union** |
| ④引用 内容 hash | **缺** | 缺（Artifact 无 hash） | 缺 | 缺 | 缺（`file_id` 不透明） | 缺 | 缺 | **全缺 → 必须自造** |
| 顺序/序号 | 无 | 无 | 无 | 无 | **有** | **有** | "同序" | **抄 DAP/OpenAI/D-Bus** |
| 按能力治理 | 无（推给 Host） | 无（任务级） | **最近**（session modes） | 部分 | 无 | 有但**按进程/用户** | 无 | **自造：能力 × 不可逆性** |
| 通道/总线分离 | 部分 | 部分（多 binding） | **是**（transport-agnostic） | 是 | 否 | 否 | 是 | **抄 ACP 的传输无关** |

**三点结论**：
1. **①③② 都有成熟形态可抄，④ 全缺**——所以四类消息不是"我们发明的怪东西"，而是"三抄一造"；
2. **顺序/序号与按能力治理，没有任何一件同时做好**——这两件是我们**真正的新增**（与 11 篇 §七"没人造的是同一个航站楼"一致，且现在有了量化依据）；
3. **自描述这一条，五个 agent 协议全部不满足**（都要"先协商能力再看数据"）——这是我们必须自造的第二个点，判据是**每条消息自带 schema 版本 + 语义类型 + 单位/量纲**。

## 五、总线 v0 的走线硬决定（本篇的交付物）

> 这五条是 `00-总纲 §9 动作 3`（写总线 v0）在"语义已定"之外**还缺的工程决定**。
> 每条都注明"抄谁 / 为什么不抄另一个"。

**1. 分帧：`Content-Length`（LSP/DAP 形态），不用 NUL、绝不用二进制头**
- 理由：可读、可流式、易调试；`NUL` 也可（varlink 更简），但**你们的通道里已经有 JSON 文本与 SSE 混流**，`Content-Length` 与现有生态（LSP/DAP/HTTP）同族，工具链现成。
- **现状必须改**：`agentd/internal/server/server.go` 的注释与实现不符（注释说行分隔，实现是 JSON 值流）。**先定死一种，再改注释**——这正是"文档被指出矛盾"那类报错的根源。

**2. 序号：每事件一个全局单增 `seq`，请求/响应各带配对 id**
- 抄 **DAP `seq` + `request_seq`**（同一份规范里两件事都给了），与 **D-Bus `serial` + `REPLY_SERIAL`** 同构；OpenAI 也证明"每事件必带 sequence_number"可落地。
- 顺带解掉 11 篇 §八-1：**各 surface 各自单调不够**，seq 必须由**世界核心**分配（无中心期由 agentd 代发并留升级位）。

**3. 发现与版本：自省接口（varlink 形态）+ 能力 flag 永不升版本（DAP 形态）**
- 自省：像 `org.varlink.service` 那样，**每个适配器/服务都必须能被问"你是什么、提供什么接口、怎么用"**，注释即文档、结构化下发 → 这就是"第五类消息"的答案（§八-2 结案）。
- 版本：**永不升版本号，只加 flag**；未知 flag 必须忽略（D-Bus 的"未知字段必须接受并忽略"同一条纪律）。这条直接防止重演"自称等价 varlink → 废止"。

**4. 订阅与回放：服务端游标，而不是"订阅那一刻起才有"**
- 抄 **JetStream 的 stream + consumer 游标**：可从指定 `seq` 起读、未 ack 重投。
- 理由：agent 断连/重启后必须能**补上错过的变化**（我们的"人离开 24 小时回来能答出发生过什么"那条常设验收，靠的就是回放能力）。
- **不抄** queue group 的随机派发（不可逆动作不能随机）。

**5. 信封与引用：CloudEvents 四必需 + 64 KiB 上限 + 大对象外置为内容 hash**
- 四条必需属性 + `subject`（中间层过滤）+ `dataschema`（payload 声明）。
- **大对象一律外置为引用**——同时满足：token 经济、差异化访问控制（CloudEvents 安全章的理由）、以及**铁律 2 的"证据不可否认"**（内容 hash 即证据，配合"哈希链定期封存别处"）。

**边界（不是决定，是纪律）**：**总线只判传输与名字，语义授权下沉服务。**——D-Bus 自己承认策略语言不适合细粒度语义授权，这条边界有原文背书，也正是我们 `管` 的设计（总纲 §6）。

## 六、红线：明确不抄（七条）

1. **不抄 D-Bus 二进制头**——地址与类型签名硬绑，**大模型读不了**，违"自描述"判据；
2. **不抄 NATS queue group 的随机派发**——不可逆动作不能随机落到某执行者；
3. **不抄 varlink `upgrade`**——连接交出后脱离协议控制；
4. **不抄 MCP / ACP 的"先协商能力再看数据"**——同样违"大模型不读文档也能懂"；
5. **不抄 AG-UI 的 31 事件类型与 `RAW`/`CUSTOM` 逃生舱**——过细 + 逃生舱会破坏自描述；
6. **不抄 A2A 的"任务是一等公民"**——我们是共享状态，不是任务队列；
7. **不抄旧资料**：MCP HTTP+SSE 已被 Streamable HTTP 取代（2025-06-18）；A2A 已移除 `kind`/`final`（且现属 Agentic AI Foundation）；ACP Streamable HTTP 仍是 draft。

## 七、为什么④「引用（内容 hash）」必须自造

- **五个 agent 协议全缺**（§四 表）；A2A 的 `Artifact` 无 hash，OpenAI 的 `file_id` 是不透明 ID，ACP 的 `fs/*` 只给路径。
- 而它对我们是**三处硬需求**：
  1. **token 经济**——大对象不进上下文（CloudEvents 安全章同款理由）；
  2. **铁律 2「证据须不可否认」**——内容 hash 是唯一可核验的证据形式（配合"哈希链定期封存别处"）；
  3. **通道与总线解耦**（11 篇 §五 机场比喻里的"货运跑道"）——**总线跑语义，通道跑字节，运单号 = hash**。
- 可抄的两个半成品：**git 的 blob/tree 对象模型**（内容寻址 + 不可变链，11 篇 §七 已列为参考）与 **A2A `append`/`last_chunk` 的分块重组**（大对象分片传输）；**AG-UI 的 patch 原子性**（失败保留旧值）可借来做"应用引用的失败语义"。
