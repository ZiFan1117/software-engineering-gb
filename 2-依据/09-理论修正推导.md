## 一、术语修正：三个"地基"共用一个名字（最高优先）

**问题（事实层）**：同一套文档里，"地基""内核""物理"三个词各指至少两个不同的东西：

| 出处 | 用词 | 实际所指 |
|---|---|---|
| [00.2-地基篇.md](../1-理论与哲学/03-规范地基.md) 全篇 | 地基 | **规范地基**——"应该保留监督"的论证（不可逆性） |
| [00.8-创世篇.md](08-创世路线论证.md) 第三节"地基决定" | 地基 = 内核 | **载体层**——硬件之上唯一仲裁者（调度/内存/文件/驱动/IPC/隔离） |
| [00.8-创世篇.md](08-创世路线论证.md) 阶段 A | 物理定律 | **本体层**——语义本体（实体/状态/动作/事件/引用） |
| [00.8-创世篇.md](08-创世路线论证.md) 阶段 B | **微内核** | **本体运行时**——语义树的存储与持久化（Smalltalk 式 image） |
| [06-多OS栈与单机社会.md](../3-备选路线/03-多OS栈与单机社会.md) 第二节 | OS 栈 | **另一种切法**——物理 OS / 社会 OS / 记忆 OS |
| [00.5-协作篇.md](../1-理论与哲学/06-协作与承载.md) §7.7 | 地基 | 明确否认治理是地基——但没给"地基"另立名 |

**为什么这不是咬文嚼字**：代价已经发生——"我需要一个内核，选一个内核作为地基"这个问题
问不出来，就是因为三样东西抢一个词。更贵的代价在后面：**把本体运行时的需求误当成内核需求**，
于是去讨论"要不要自己写内核""什么时候换 seL4"——而真正该造的东西（世界核心）被这个问题挤出了视野。

**立论**：三层命名，此后强制使用：

| 层 | 名字 | 是什么 | 谁提供 | 换不换 |
|---|---|---|---|---|
| 载体层 | **载体 / 机器内核** | 硬件之上的仲裁者，只提供秩序，只干六件事 | 外部（现在 Linux） | **可换（插座）** |
| 核心层 | **世界核心**（Ontology Runtime，原"微内核"） | 语义本体的存储与持久化 + 总线 + 投影注册 | **必须自建**（创世的全部内容） | 世界的宪法，**不换** |
| 治理层 | **治理**（agentd） | cap.d / 审计 / 快照 / 铃 | 自建（00.5：**服务，非地基**） | 可替换服务 |

**最强反驳**："名字不重要，重要的是内容，读者看得懂。"——对**已经知情**的读者成立；
但本仓库全部文档都靠"地基/内核"这两个词做章节标题与论证枢纽（00.2、00.8 第三节）。
一个被用作论证枢纽的词有歧义，等于论证有隐含前提。且 00.8 阶段 B 把世界核心命名为"微内核"，
直接引入了错误的联想集合——**微内核**意味着特权级、硬件信任、六个职责；而语义树的存储与
持久化**一条都不沾**。这是名词选择制造的概念污染，不是风格问题。

**幸存者写入**：
1. 此后"**内核**"只指载体层，"**地基**"只保留 00.2 的规范地基义（其他场合改用具体层名）；
2. 00.8 阶段 B 的"微内核"更名为"**世界核心**"，职责写死为三件：语义树的存储与持久化、
   总线（唯一 IPC）、投影注册；**世界核心不是内核**，它跑在载体之上，与内核两轴正交；
3. 加一条判据（供第八节与后续文档引用）：**凡出现"内核"二字，必须能回答"是载体层还是
   世界核心"；答不出来的句子，是没想清楚的句子。**
4. 三层命名描述**职责**，不预设**部署形态**：寄主期治理是宿主上的独立服务（agentd），
   进入自举后治理升为**世界核心内的一等角色**（00.8 §4：agentd 代码与测试直接迁移）。
   三层是"分清谁在干什么"，不是"必须三个进程"。

## 二、"不兼容"的判据：不是纯度，是锚定

**立论**：00.8 自首②（"算力外购=自足有豁口，纯度问题"）问错了问题。自足与否不看
"用了多少外部东西"，看**外部规范锚不锚得住世界**：

| | 定义 | 例子 | 判决 |
|---|---|---|---|
| **锚定** | 世界的本体或协议必须服从外部规范才能运转 | 读 DOM 才能活、本体用 MCP 方言表达、身份依赖某个厂商账号 | 必须拒绝（这是"不兼容"真正要砍的东西） |
| **依赖** | 世界消费一个**接口在自己手里**的可替换输入 | LLM 算力、硬件、电力 | 不算破坏自足（进口一台发动机，不改宪法） |

**推论一**：算力外购不破坏自足；**读 DOM 才能活的世界才是寄生**。
**推论二**（新要求）：既然算力是进口件，世界必须**自己定义算力端口**（不是让本体去适配某家 API）
——端口规范与"进口海关"同级，属于阶段 A 的产出。
**推论三**：这条判据同时解释了 00.8 该砍什么——DOM 转译层、MCP 方言、过渡桥全部命中"锚定"。

**最强反驳**："LLM 不是可替换输入，它是这个世界的生产力来源；一家断供，世界停摆。"
——部分成立，且是本判据的真实边界：可替换性不是自然事实，是**必须被工程保证**的性质。
故判据需补三条要求：① 端口规范自持（世界定接口，供应商实现）；② 至少两家可换；
③ **降级模式**（无 LLM 时世界仍在运转——07 篇 §4.2"脑干反射/断网=思考停"的诚实账升为设计项）。

**幸存者写入**：自足判据 = **锚定 vs 依赖**（替换"纯度"）；算力端口规范入阶段 A；
可替换性三要求（端口自持 / 两家可换 / 降级模式）入阶段 B 验收。

## 三、脐带：transferor 不是外设，是外部性入口（对 00.8 的实质修正）

**立论**：00.8 把 transferor 降为"阶段 D 的可选外设"（进口海关，想读旧网页才接）。
但两处已成立的结论合起来推翻了它：

1. 00.8 自认"新世界空无一物"，靠 agent 批量生成内容解决冷启动；
2. [00.1-Agent定义论.md](../1-理论与哲学/02-Agent定义论.md) 第六节条件 3 已证：agent 的目标函数由厂商设定，
   使用者利益只以**输入**身份出现——**agent 没有自身利益**。

一个没有自身利益的物种，**不可能是新世界的需求来源**。于是世界的价值输入只能来自旧世界。
**港口不是奢侈品，是脐带**——切断它，世界在出生时饿死。

**这也是 Smalltalk/Genera 历史败因的真实机制**（00.8 自首③要的"这次为何不同"的答案）：
它们不是败于"不兼容"，是败于**自足但空转**——没有外部性来源，优雅的世界里没有事可做。
创世路线若要在这一点上不同，差别不在"agent 是原住民"，而在**脐带是否接通**：
只要世界能持续从旧世界"进口任务"并出口价值，外部性就存在。

**最强反驳**："接上旧世界就是兼容，与 00.8 的不兼容承诺自相矛盾。"——不矛盾，且这正是
第二节判据的应用：**transferor 的输出是语义 IR（世界自己的语言），不是 DOM**。
它是翻译官，不是宪法。读旧世界的一个网页 ≠ 把本体锚定在 web 规范上。
判据一句话：**进口货物可以，进口法律不行。**

**幸存者写入**：
1. transferor 身份改为"**外部性入口（脐带）/ 进口海关**"，**必须在阶段 B 就通**，不是阶段 D 的选修；
2. 其 IR 输出必须用**世界本体 schema** 表达（不得把 web 的 schema 直接当本体）；
3. 连带处置：[00.6-总线工程篇.md](11-总线工程规格.md) §7 的动作决定（"transferor 增加 MCP 方言"）
   与 00.8"砍掉 MCP 方言"**直接冲突**，标注为**仅兼容备选路线有效**；
   [00.7-施工总表.md](../3-备选路线/01-施工总表.md) 阶段 3"transferor 服役至语义内核接棒"的时序作废；
4. 冷启动的答案随之改写：不是"agent 生成内容"，是"**agent 把旧世界的任务翻译进新世界**"
   ——生产力来自 agent，需求来自脐带。

## 四、缺失的阶段：寄主期（hosted phase）

**立论**：00.8 自首①（"阶段 B 的范围可能被低估"）不是量的问题，是**缺了一个阶段**。
自举（阶段 C）要求世界内能开发世界，而世界内开发工具的下限高于"两个内置应用"——
鸡生蛋。历史上的解法完全一致：**先寄主，后搬入**。Smalltalk-80 的 image 在宿主 OS 上跑了多年，
Oberon 也先在别的系统上交叉开发。

**修正**：阶段序列补一环——

```
A 定义物理（本体 spec）
B 垂直切片（世界作为宿主上的一个进程跑起来：世界核心 + 总线 + 朴素投影）
B.5 寄主期（新）  ← 世界在宿主内长大；用宿主编辑器/调试器开发世界；脐带供真流量
C 自举            ← 工具链搬进世界内，此后在世界内开发世界
D 向外表
```

**寄主期的三重作用**：① 解决鸡生蛋；② 让脐带在阶段 B 就有真流量（00.7 铁律 2"真流量先热"
的保留条款）；③ **把内核选型从"信念问题"变成"工程问题"**——寄主期要求载体层能跑常规
开发工具，这一条直接决定内核选型篇的结论。

**最强反驳**："寄主期会让世界永远长不大——寄生成瘾，永远不搬。"——这是路线风险，不是理论
错误，但可以立法防治：**给寄主期设退出条件**（世界内编辑器/调试器可用 + 两个内置应用
自举运行 = 搬入条件），写进阶段表的验收列，避免"开工条件永远不满足"的自我豁免
（00.7 自首②已警告过这个模式）。

**幸存者写入**：阶段序列改为 A→B→B.5→C→D；寄主期设退出条件（自举工具可用），
条件写死为可检验项。

## 五、本体最小集缺两项：版本/历史 与 可逆性标注

**立论**：00.8 阶段 A 的最小集 = 实体 / 状态 / 动作 / 事件 / 引用 + 身份 + 能力权限模型。
对照本仓库自己的理论，缺两项：

1. **版本 / 历史**（谁在何时改了哪个实体的哪个字段）。理由：00 篇的宪法四条里"出错有恢复"，
   若本体不记录前态，恢复只能靠载体的文件系统快照（粗粒度、跨世界、且换轨即失效——
   00 篇的快照靠 btrfs）。**恢复能力必须建在本体里**，这与 00.8"换载体只换插座"的承诺
   是同一个要求的两个面。
2. **可逆性标注**（这个动作/这个字段是否可逆、逆操作是什么）。理由：00.2 的整套监督理论
   建立在"不可逆性"上（摩擦按不可逆性定价），00.3 又指出"判据移动"（今天可逆的明天不可逆）。
   若本体不原生表示可逆性，cap.d 的 risk 只能是策略层静态标注，**同一动作在两个世界状态下
   不可逆性不同**这件事就无处安放。

**最强反驳**："per-object 全历史成本极高（存储、复杂度），Smalltalk 也没有。"——成立。
故**分级**：

| 级 | 内容 | 强制性 |
|---|---|---|
| 动作级历史 | 每次动作的记录：谁 / 何时 / 改哪个实体哪个字段 / 前值 | **必需**（本体原生） |
| 状态级检查点 | 世界状态的可命名快照点（回滚锚点） | **必需**（世界核心原生，不靠载体） |
| 对象级全历史 | 单对象的每一次变更序列 | 可选，由记忆器官提供 |

**幸存者写入**：最小集扩为 **实体 / 状态 / 动作 / 事件 / 引用 / 身份 / 能力权限 + 版本历史 + 可逆性标注**；
且明确分工：**可逆性等级由预案分级判定（00.3），本体只负责记录与执行逆操作，不负责判断**。

### 5.1 本体 schema 的可复用与须重写清单（来源：08 篇 11/12 审计）

08/11 的 UI-IR v0.1 已经是一份写好的 schema 草稿。必须分清**可直接升格**与**必须重写**：
前者省下阶段 A 的工作量，后者若照抄，会把 web 的假设偷渡进世界的物理。

| 可直接升入本体 schema | 依据 |
|---|---|
| 四类消息（状态 / 动作 / 事件 / 引用） | 与 00.8 阶段 A 最小集同构（11:125–133） |
| 动作**动词化 + 参数 schema** | 11:172；加权限位即接能力模型 |
| **事件即真相 + 订阅推送** + 行分隔 JSON-RPC | 11:175–176（与 00.5 §7.2 同构） |
| **seq + diff(added/removed/changed)** | 11:158/174——但**寻址须换**，见下表 |
| 语义级合并 / 去抖（不在页面里用定时器） | 11:177 |
| hash 内容寻址焊接（总线只放引用） | 11:66–70 |

| 必须重写（照抄即偷渡 web 假设） | 理由 |
|---|---|
| **ref（e12）会话内编号 → 持久身份** | 会话内编号随页面失效；与第五节"版本/历史"直接冲突——世界实体的引用必须持久、可跨会话、可版本化 |
| **surface 四面枚举 + 分面适配器** | 创世下只有"世界"与"进口面"两个面，不存在为存量界面各配一座桥 |
| **role 取 ARIA 控件词表** | 把**类型**与**可操作性（affordance）**混为一谈；本体应分开表达"是什么"与"能做什么" |
| **name / value 由 AOM 推断** | 推断是转译的病；本体里语义是**构造出来的**（12:23–27 自己已证），不是提取的 |
| **focus / 层级** | 渲染概念，属投影层，不进本体 |
| **事件命名空间 `browser.*`** | 世界的命名空间里不该出现载体或进口件的名字 |

**另一条判据级结论（来自 12 篇）**：因果反转论证在创世下的**有效域变宽**——"语义是本体、
渲染是投影"可以直接充当世界的物理定律，不必再为存量 web 让步；但它的**边界声明与
差异化用途变窄至消失**（不再需要 12 篇原文所说"一条总线、两面分治"式的让步设计）。
故 12 篇应作**正面依据**引用，其"边界"章节作废。

## 六、创世者的立宪问题：本仓库最大的自我豁免风险

**立论**：把三处已有结论连起来看——

- [00.4-定义辩证篇.md](../1-理论与哲学/05-定义辩证.md)："定义行为即参战行为""**谁握着审计、授权、恢复的机制，
  谁定型得快**"，且自首①已承认："'定义即参战'有自我豁免风险——本定义也可能只是又一股
  伪装中立的定型力量（需自证立场）"；
- [00.5-协作篇.md](../1-理论与哲学/06-协作与承载.md) §5 警示：协作机制必须中立化（用户主权），
  否则"高效 but 争夺不可见的协作，是最坏的协作"；
- 创世路线 = 建造者独占本体定义权 **+** 全部机制（本体、门禁、审计、恢复）。

**结论**：创世路线把 00.4 自认的风险放大到极致——一份主张"定义即参战"的理论，
正要做**最强的一次参战**（为世界立法），而文档里没有任何约束建造者自己的机制。
不写下来的约束等于没有约束。

**最强反驳**："个人项目谈立宪是过度设计，先做出来再说。"——两处反驳：
① 00.2 的不可逆性论证对建造者同样适用，而**创世本身就是最大的不可逆决定**（世界一旦被
人和 agent 用起来就回不去）；② 这四条的成本极低（公开、导出、不加特权、分级），
属于"设计时顺手做"而非"以后补做"——补做的代价才是真高（image 格式已固化后无法导出）。

**幸存者写入**：**立宪四条**进本体 spec 的元层：

| # | 条款 | 兑现方式（可检验） |
|---|---|---|
| 1 | **本体公开且版本化** | spec 与 image 格式公开；本体变更留历史 |
| 2 | **退出权 / 移植权** | 世界状态可导出、可带走——这是 00 篇"主权原则"的兑现，否则自足世界=不可退出的牢笼 |
| 3 | **建造者特权禁止** | 建造者不得拥有普通 agent 没有的能力；否则 00.8 的验收"同一块屏幕"是假的 |
| 4 | **世界级不可逆操作走最高预案** | 本体变更、大规模删除的级别高于任何 agent 能力（00.3 预案分级） |

## 七、验收标准升级：可见性 ≠ 监督补偿

**立论**：00.8 的唯一验收标准是"boot 进世界，人与 agent 同一份状态、同一块屏幕"。三处对不上：

1. 00.4 的核心动力学是"**监督位结构性衰减**"（依赖与监督互斥）；
2. 00.5 要求"协作机制必须**补偿**衰减（监督从注意力问题变成架构问题）"；
3. 而"同一块屏幕"只满足**可见性**，不满足**补偿**。

把"人只需投影"直接写进设计，等于**把 00.4 的预言当成了目标**（预言监督会衰减，
于是干脆设计成不需要监督）。这是理论被自己的诊断俘获。

**另一处必须写进验收的旧账**：00 篇攻击 4 指出"确定性是审计的产物"是**偷换**——
审计保证**可问责性**，不保证**正确性**。验收若只说"留痕完整"，容易被读成"所以它是对的"。

**幸存者写入**：验收加两条（都可执行）：

| 新增验收 | 检验方式 |
|---|---|
| **衰减补偿可验** | 人离开 24 小时后回来，能答出"发生过什么、哪些在等我批"——不靠人盯守（00.5 判据 2） |
| **只验可问责，不称正确性** | 验收报告只主张"可复盘"，不得主张"结果正确"；高危动作的确认语境被记录（00.3 反噬 2：区分"人批准"与"人被信息胁迫后批准"） |

### 7.1 投影不是两个：注册表应支持 N 个端口

**立论**：00.5 §7.2 把人的承载定为**两个投影**（自然语言 / 图形界面），但同一篇的
§7.8 待批判 1 已自首："'两个投影'假设人的需求只有对话与看状态两类（**听觉**/触觉/多设备场景未计）"；
08/14 §6 也已判定"语音浏览器非品类——**语音是投影**，不是外壳"。两处合起来说明：
**"两个"是二分法的产物，不是投影数的上限。**

在创世路线下这条更重要：00.10 第六节把**投影注册**列为世界核心的不可外购部件之一——
一个注册表天然是 N 端口的，写成两个就是把实现细节焊进本体。

**修正**：投影层的正确定义是 **N 个端口的注册表**，共享**同一份状态源**：

| 端口 | 承载 | 状态 |
|---|---|---|
| 视觉（图形界面） | 看状态 | 现有（对偶界面） |
| 语言（对话投影） | 交谈 | 现有（00.5 §7.2） |
| 听觉（语音） | 说/听 | **v1 不实现，但注册表须容得下** |
| 其他（多设备/触觉） | 待定 | 注册表预留 |

**最强反驳**："每加一个投影就多一份一致性维护成本——而'状态双投影的一致性'本来就是
最大工程风险（10 篇 §7：两个投影必须同源，否则比截图更危险）。N 投影放大该风险。"
——成立，故必须配一条硬约束：**任何新端口必须绑定同一状态源，禁止自带独立状态**
（违反者不是投影，是第二真相，直接违反"状态即真相"原则）。

**幸存者写入**：投影 = **同源状态上的 N 端口注册表**；
v1 只实现视觉 + 语言两个端口，听觉端口列入待做（不阻塞阶段 B）；
任何新增端口的准入条件是"同源"，不同源者不许接入。
