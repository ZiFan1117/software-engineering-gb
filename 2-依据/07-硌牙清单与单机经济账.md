# 07-硌牙清单与单机经济账：现有 OS 与单机形态的硌牙清单（原 07 · 不适用审计）

> 排序原则：**谁天天疼谁先修。**本文 = 开工后的避坑地图 + 排期依据。
> 约束：不改变电脑物理形态——一台普通 PC（CPU + GPU + RAM + SSD + 家庭网络）。
>
> **修订标注（2026-09-25，见 [00.9-理论修正篇](09-理论修正推导.md) 第八节）**：两处待修——
> ① 第 6 节"真要改内核的只有三件"是**向载体层提出的长期上游诉求**（不阻塞、不等于现在就改），
> 与 06 篇"Linux 一行不改"不矛盾，但须分时态表述（见内核选型篇）；
> ② 第 2 节 #3 承认"单机审计可篡改"，与 02 篇"不可被 agent 自己删改"的承诺自相矛盾，
> 须统一降为"**agent 之外 + 不可否认**（哈希链定期封存）"。
> 第 5 节的"登记簿持久化"是 00.9 第五节"世界核心原生持久化"的工程对应物，优先级上调。

## 1. 总判断

现有 OS 的进程模型是为两种住户设计的：**长期运行的服务**（sshd）和**交互的人**（桌面会话）。
数字生命是第三种东西：**长寿命 + 高频短任务 + 带状态移动**。机制层 80% 可直接用，
错配集中在下表。

## 2. 五处大疼

| # | 深奥版 | 人话版 | 对策 |
|---|---|---|---|
| 1 | 能力模型缺失 | 门锁只有"整串钥匙"或"没钥匙"，没有"只能进厨房"的钥匙 | agentd 做能力编译器：cap.d → 动态 Landlock/seccomp 规则集。天花板：吊销不能即时生效（seccomp 不可卸载），语义定为"吊销=勒停重建" |
| 2 | GPU 无配额计量 | 最贵的房间没电表没门禁 | 近期按进程分卡 + cgroup 兜底，计量自记；`drm.memory.max` 刚冒头、驱动覆盖差；最值得上游化 |
| 3 | 审计可篡改 | 仓库管理员自己能涂账本 | append-only + 定期哈希链封存别处（U 盘/异机）。真·不可篡改等联邦制互相保管 |
| 4 | 无休眠/搬家原语 | 人睡着了搬不走（CRIU 对 GPU 进程基本失效） | 不搬进程，搬"户籍+记忆"：新机重建身体（秒级）+ 海关带记忆 + 大脑重租。**"人格外置"设计在此兑现** |
| 5 | 事件总线碎片化 | 世界的声音散在七八个喇叭里；**完工不拉铃，agent 只能反复轮询** | agentd 事件网关缝合 coredump/udev/inotify/NM 各协议；**完工铃 = 第一优先**（10 分钟任务轮询 20 次推理 → 2 次） |

## 3. 四处小疼

1. **世界模板不可复现**：舱要秒级克隆"世界"，但"世界装了什么"无声明式标准 → 绑定 NixOS/mkosi；
2. **网络无身份感**："此 agent 只许访问这几个域名"内核做不到（iptables 仅 UID/cgroup 粒度）→ 强制走代理，代理层管；
3. **记忆条目级权限**：文件系统只有目录粒度 → 一条记忆一个目录，冗余但能用；
4. **旁路面**：io_uring/memfd 是安全规则经典绕过口（Google 生产已禁 io_uring）→ Landlock 规则集显式堵上。

## 4. 单机物理形态：不换电脑的前提下

### 4.1 照样成立（好消息）
户籍/法律/审计/团体/记忆分层/实验舱全是软件层，与形态无关；cgroup 经济在单机上反而更简单；
btrfs CoW 克隆世界毫秒级成立；完工铃、快照、海关通道全部成立。

### 4.2 要打折（经济账）
- **大脑基本租云端**：本地模型吃显存，一台 PC 养不起几个大脑。本地只留"脑干反射"小模型
  （完工铃的收尾解析、告警分级）。代价：**断网 = 思考停**——任务排队 + 反射兜底；
- **社会规模 = 小办公室**：3-10 个常驻公民 + 临时工，不是斯坦福 25 人小镇（那是研究集群玩的）；
- **实验舱以 nspawn 为主**（共享内核省内存），Firecracker 看内存余量；
- **SSD 写寿命要管**：舱数量配额 + 定期 balance（CoW 有写放大）。

### 4.3 单机做不到（需要"至少第二个地点"，但不改形态：加 U 盘或一台 VPS 即可）
- 真·不可篡改档案馆（单机 = 君子档案 + 定期封存）；
- 联邦制（单机"联邦"是假联邦）；
- 7×24 在线（**电脑关 = 社会睡**）。靠"干净睡眠"把重启变非致命：记忆在 state、审计在
  journald、户籍在 unit——开机即复城。

### 4.4 单机的额外红利
- 信任集中：单一内核、单人所有，法律无需多方共识，v1 最简；
- **试验场顺便测系统升级**：内核/systemd 更新先在舱里跑一周再落地；
- 隐私红利：**思考在云上，记忆在家里**——记忆OS 本地化与大脑云租恰好互补。

## 5. 开工新增待办

- **登记簿持久化**：job 表落盘，重启后能报告"上次那个活没跑完（机器断电）"——
  否则完工铃在断电场景变成哑铃；
- 脑干反射小模型选型（1-3B 本地，管告警分级与铃响收尾）。

## 6. 上游化短清单（真要改内核的只有三件，且全部符合"机制不策略"）

1. 能力委托原语（跨进程 capability delegation）；
2. GPU 配额与计量覆盖（drm.memory.max 全驱动化）；
3. 统一结构化事件总线。

> **归属裁决（2026-09-25，见 [../00-总纲.md](../00-总纲.md) §2.1 / §2.3）**：第 3 项**记错了归属**。
> "事件总线"不是内核的活——它是**用户态的世界核心**（`传`）的活；
> 内核只需要**暴露事件源**（netlink / inotify / perf / drm 等，今天已经在做）。
> 故第 3 项应改写为"**内核侧事件源的统一（可选、长期）**"，而不是"要改内核的第三件"。
> 理由：若把总线做进内核，等于把"世界的协议"锚定在载体的接口上——与"锚定 vs 依赖"判据冲突
> （[09-理论修正推导.md](09-理论修正推导.md) §二）。
> 第 1、2 项归属正确：能力委托原语是内核级的（也可先用用户态策略补足，见总纲 §8），
> GPU 计量是驱动与内核的事。
