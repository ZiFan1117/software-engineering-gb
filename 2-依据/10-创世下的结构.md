# 10-创世下的结构：载体、世界核心、投影（06 篇重写）（原 06.1-创世下的结构）

> 一句话：06 篇的三层 OS 栈（物理 / 社会 / 记忆）是"**寄生在旧世界之上**"的切法；创世路线下
> 必须重切为 **载体层 / 世界核心 / 投影层**——而 06 篇最有价值的那部分（户籍 / 法律 / 档案馆 /
> 经济 / 集会 / 记忆）**全部升格为世界核心内的一等对象**，不再是 systemd + 目录 + varlink 的胶水。

> 整理日期：2026-09-25。重写依据：[00.9-理论修正篇](09-理论修正推导.md) 第八节（06 篇判"待重写"）、
> 00.9 第一节（三层命名）；对照 [00.10-内核选型篇](12-内核选型对照.md)（载体层与自建部分的边界）。

## 一、原切法错在哪（保留直觉，换掉实现）

06 篇的三层是：物理 OS（Linux，一行不改）/ 社会 OS（agentd + varlink + journald）/
记忆 OS（state 目录 + 插件化记忆引擎）。三处错：

1. **把"社会"与"记忆"实现成宿主上的服务**——它们是**旧世界的器官**（systemd 的客户、
   目录的占有者），不是新世界的法律。世界的法律应当写在世界的本体里，而不是写在宿主的
   服务配置里；
2. **以 varlink / MCP / A2A 充当 OS 接口**（06 篇 §2 的对外接口行）——
   按 00.9 第二节的判据，这三样全是**锚定**（世界的接口服从外部规范），不是可替换的依赖；
3. **它默认世界长在别人的地上**——"物理 OS 一行不改"意味着世界的存在以宿主的持续合作为前提，
   这正是创世要摆脱的东西。

**但 06 篇的直觉是对的**，要保留：§2 给"为什么分三层"的理由——**资源不同 → 变更节奏不同 →
信任级别不同；捏成一个大 OS 的下场是记忆引擎每次升级、法律跟着重写**。这条理由在创世下
**更加成立**（世界核心一旦混入易变器官，本体就会被频繁改动，而立宪四条第 1 条要求本体变更留历史）。
错的不是"分三层"，是"这三层各由什么实现"。

## 二、重切后的三层

| 层 | 管什么 | 创世下的实现 | 与旧切法的差别 |
|---|---|---|---|
| **载体层** | 物质：CPU / 内存 / 盘 / 网络 | **外部采购**（今 Linux，长期候选见 00.10） | 从"一行不改的家"降为"**可换的插座**"（00.8 §3 的换轨承诺） |
| **世界核心** | **意义 + 秩序**：本体 / 持久化 / 总线 / 投影注册 / 能力表 | **自建，不可外购**（00.10 第六节的 8 项清单） | **吸收了旧"社会 OS"与"记忆 OS"的全部职责** |
| **投影层** | 人向端口 | **同源状态上的 N 端口注册表**（视觉 / 语言 / 听觉…） | 旧切法**没有这一层**——它把 UI 当外部消费者 |

一句话：**旧切法是"世界寄生在机器上，社会装在壳外"；新切法是"机器是插座，社会写进本体，
人从投影进来"。**

## 三、社会构件升格为世界内的一等对象（06 篇 §3–§5 的逐条重写）

| 06 篇的工程形态 | 创世下的身份 | 为什么必须升格 |
|---|---|---|
| 公民 = agent + 户籍（专用用户 + unit） | **世界内的实体**：身份 + 能力句柄 | 户籍若在 systemd 里，换载体即失效（00.9 §5 的同一个理由） |
| 法律 = cap.d 能力法 + 高危确认 | **本体内的能力模型**（cap.d 的声明形状升为本体 schema 的一部分） | 门禁的**声明**本来就属策略面（00.10 第三节），它不该住在宿主的文件里 |
| 档案馆 = journald 审计 | **本体的动作级历史**（00.9 §5：必需项） | 审计是"谁在何时改了哪个实体的哪个字段"——这是本体问题，不是日志问题 |
| 经济 = cgroup 配额 | **世界的资源账本**；载体配额只是它的执行机制 | 账本属于世界（可审计、可追溯），配额是实现细节 |
| 集会通讯 = A2A / varlink / MCP | **总线四类消息**（唯一 IPC） | 00.6 换轴：服务对象从进程换成物种 |
| 团体 = Unix 组模型 | **世界内的组实体**（成员 = 授权，边界 = 权限，历史 = 审计） | 06 篇 §6 铁律 2 原样保留——infra 仍不预设协同形态 |
| 记忆分层 = 私有 / 团体 / 广场 | **本体的可见性模型**（同一条记忆的三种投影范围） | 目录权限只有目录粒度（07 篇 §3 小疼 #3），本体可以有条目级 |
| 试验场 = btrfs 快照 + nspawn + overlay | **世界核心的 fork / checkpoint 原语** | 实验舱的语义（一次性世界、退出三协议）是本体级的，不该由三个载体机制现凑 |

**一句话**：旧切法把社会装在壳外，新切法把社会写进本体。**社会性是世界的属性，不是宿主的服务。**

## 四、原样保留的部分（06 篇的资产，不重写）

1. **OS 的定义**（独占稀缺资源 + 虚拟化成稳定接口 + 接口后强制执行策略）——但它描述的是
   **载体层**；世界核心不是 OS 的另一个实例，它是另一回事（00.9 第一节）；
2. **两条铁律**：启动上并列、约束上分层（锁的体系不能有互否）；**infra 不预设协同形态**
   （群聊制 / 层级制 / 联邦制全是上层协议，infra 只强制三条：成员 = 授权、边界 = 权限、历史 = 审计）；
3. **实验舱的退出三协议**（丢弃 / 带回 / 存档）——原样升格为本体级的 fork 语义，
   其中"带回走法定通道、高危照常确认"是创世下的**世界级不可逆操作**，适用立宪四条第 4 条；
4. **诚实难点四条**（共享记忆写污染 / 资源经济先做明文配额 / 能力转授做在策略面 /
   数字生命同一性依赖 state 与审计的持久性）——最后一条在创世下从"难点"升级为**设计前提**；
5. **单机规模判断**（3–10 个常驻公民，不是 25 人小镇）。

## 五、三处必须改写的判断

1. **"人格站在三个 OS 的交点上，不属于其中任何一个"（06 篇 §2 末）**——
   这是 06 篇最**创世**的一句话，但它当时无处安放。创世下它有了家：
   **人格是"世界内的实体"，载体与投影都不是它的家**。应升格为本体设计的出发点。
2. **"人在接口外侧组装"（06 篇 §2）**——方向对，位置要精确：人在**投影侧**，不在世界内。
   这与立宪四条第 3 条（建造者特权禁止）咬合：建造者也是从投影进入世界的。
3. **"物理 OS 万年不动"（06 篇 §2 表）**——改为"**载体极少变，但可换**"（00.10）。

## 六、与两个项目的新对位

```
载体层     Linux（今）→ Genode/Redox（候选，00.10）
              ↑ 五行合同：隔离 / 配额 / 持久化 / 承载 / 可开发
世界核心   本体 schema + image 持久化 + 总线 + 投影注册 + 能力表
              ↑ 脐带（transferor：把旧世界的任务翻译进来，用世界的 schema 表达）
投影层     N 端口注册表：视觉（对偶界面）/ 语言（对话）/ 听觉（语音，留位）
```

- **06 篇的"社会 OS"= 世界核心内部的一组一等对象**（身份 / 能力 / 历史 / 账本），
  不再是宿主上的 agentd 进程；寄主期它仍以 agentd 形态跑在宿主上，自举后迁入（00.9 §1.4）；
- **06 篇的"记忆 OS"= 本体的可见性模型 + 对象级历史**（可选部分由记忆器官提供，00.9 §5 分级）；
- **实验舱 = 世界核心的 fork 原语**（寄主期用 btrfs + nspawn 实现，是**实现**而非**定义**）。

## 七、待批判项（自首）

1. **"升格为一等对象"的代价未估**——每一项都要在世界核心里有 schema、有权限语义、有历史记录，
   这是阶段 A/B 的实打实工作量；本篇只论证了"应该"，没论证"先做哪个"；
2. **社会性与本体的耦合风险**——把社会构件写进本体，等于让**法律与记忆共享同一套变更机制**；
   06 篇分层的初衷正是"避免记忆引擎升级带着法律重写"，本篇的重切可能把这条好处削弱，
   需要用"本体元层不可随意变更"（立宪四条第 1、4 条）来补偿，但补偿是否足够未证；
3. **听觉端口的例子是待做的，不是需求**——00.9 §7.1 的 N 端口注册表在本篇被当作结构依据，
   但 v1 只实现两个端口，"听觉需要一等支持"尚无场景证据（08/14 §6 只判了语音是投影、不是品类）。
