# 11-总线工程规格：语义总线的搭建、与 D-Bus 的区别、概念表（原 00.6-总线工程篇）

> 一句话：语义总线 = 四类消息（状态/动作/事件/引用）+ 六个部件（协议/适配器/治理/
> 投影/订阅/通道），第一版点对点直连（无需中心 busd）；与 D-Bus 的区别是**换轴**——
> 服务对象从进程换成物种，于是消息必须自描述、必须有投影、治理必须语义级；
> 总线/通道/端口/协议用国际机场比喻一次锚定。
>

> 数据流实例中 ①⑤⑥ 已在 transferor 验证、③④已在 agentd 验证——本总线是两个
> 已完成部件之间"还差的一根线"，不是从零造。
>

## 一、总线上跑什么：四类消息

| 消息 | 例子 | 谁发 |
|---|---|---|
| 状态（快照/增量） | `{surface:"web", elements:[...], seq:4}` / diff | 适配器 |
| 动作请求/结果 | `{capability:"ui.web.fill", params:{...}}` → `{outcome:"ok"}` | agent（经 agentd） |
| 事件 | `state.changed` / 完工铃 / 页面报错 | 适配器 / agentd |
| 引用 | `{content:"sha256:ab3f..."}` | 任何方 |

## 二、部件清单与施工序

六样东西：**协议**（IR schema + 行分隔 JSON-RPC）→ **适配器**（每界面一座桥，
职责只有两个：界面→状态消息、动作请求→原生操作）→ **治理**（agentd：cap.d/
审计/快照/铃）→ **投影**（界面投影 + 语言投影）→ **订阅**（subscribe 后主动推送，
v0.2 已验证）→ **通道**（文件+hash 起步）。

**关键架构决定：第一版无中心**——点对点直连（agentd 充当 agent 汇接点，transferor
直连 agentd）；等"多适配器+多消费者同时在线"出现再引入 busd（surface 路由、订阅管理、
seq 全局分配）。先无中心后有中心，避免只有一盏灯就先造配电房。

> **修订标注（2026-09-26，见 [15 篇](15-世界核心的组成与职责.md) §5.4）**：上面这句里的
> "**无中心**"容易误导——真实拓扑是**星形**，**中心就是世界核心**（三方都只跟账本打交道）。
> 所谓"无中心"，实际意思是"**不额外引入一个 busd 中间件**"。
> **建议口径：无额外中间件；世界核心即汇接点。** 原文保留不改，读时以本条为准。

## 三、数据流实例（已验证机制的串联）

agent 在浏览器加一条任务：

```
① transferor 发布页面状态（e3=输入框, e4=按钮）          [状态]
② agent 读到，决定填表
③ agent → agentd：请求 ui.web.fill(e3,"买牛奶")           [动作请求]
④ agentd 查 cap.d → 记审计 → 转发 transferor             [治理]
⑤ transferor 执行 → 推 state.changed diff                [事件]
⑥ UI 投影更新（人看见）+ agentd 记录结果                  [投影+审计]
```

①⑤⑥ 在 transferor 跑通；③④ 在 agentd 跑通；②是 agent harness 的活。

## 四、与 systemd/D-Bus 的本质区别（形抄魂换）

| 维度 | D-Bus / systemd 总线 | 语义总线 |
|---|---|---|
| 服务对象 | 进程↔进程 | **人+agent+机器（两物种三方）** |
| 消息性质 | 调用合同（接口编译时定死） | 共同世界模型（接口运行时生长，三源合一动态合成） |
| 消息可读性 | 离开接口文档无法理解 | **必须自描述**（LLM 无文档直接读懂） |
| 世界模型 | 封闭世界（注册服务集合固定） | 开放世界（描述动态世界的当下状态） |
| 投影 | 无 | 两个投影（语言+界面）——人在车上带来的约束 |
| 治理 | polkit（进程/用户为单位） | agentd（能力+不可逆性为单位，语义级门禁） |
| 事件 | signal（通知） | 语义 diff + 完工铃（变化的可读描述） |

凝练：**D-Bus 是传话总线（我知道你要什么，替你转达）；语义总线是世界观总线（谁都不必
预先知道世界上有什么，上车就能读懂世界当前状态）。** 抄了骨架（方法/属性/信号 →
动作/状态/事件；自省 → cap.d），换了轴（进程 → 物种）。

## 五、概念表（国际机场比喻）

| 概念 | 机场对应 | 定义 | 关键性质 |
|---|---|---|---|
| 协议 | 广播话术标准 | 消息怎么写（IR+JSON-RPC） | 先定它 |
| 总线 | 航站楼广播系统 | 语义消息唯一公共通道 | 唯一真相，被动，不做决定 |
| 通道 | 货运跑道 | 字节运输轨 | 与总线并行不混载；运单号=hash |
| 端口 | 航显屏/值机柜台 | 人向端口=UI 投影；界面端口=适配器 | 无意志，只翻译 |
| 治理 | 海关 | agentd：agent 必检，人免检留痕 | 服务非地基，挂了总线照跑 |

既有资产归位：transferor=浏览器面的值机柜台；agentd=海关+记账台；`ui.web.fill`=标准
话术；diff=航班动态；demo 的浏览器窗口=航显屏。

## 七、GitHub 参考件对照（2026-09-25 检索+亲验）

| 部件 | 参考件 | 亲验 | 参考什么 |
|---|---|---|---|
| 协议 | modelcontextprotocol（官方 spec+SDK / servers） | ✅ | agent 侧端口协议最强参考：动作请求/结果+事件有对应物（tools/call、notifications）；缺状态快照/diff（resources 偏静态）——恰是我们的增量 |
| 治理 | Agent-Hellboy/mcp-runtime | ✅ | 声明式部署+注册+请求路径治理+审计（K8s operator 形态）——企业版 agentd；无语义级高危/快照/完工铃 |
| 总线守护 | nats-io/nats-server | ✅ | 中心 busd 的现成参考（subject 寻址/订阅/队列）；无语义无投影无治理——只是马路 |
| 浏览器面适配器 | browser-use / playwright-mcp / vercel agent-browser | ✅ 早前 | 11 篇已盘 |
| 桌面/终端面适配器 | CUA / SGCL | ✅ 早前 | 11 篇已盘 |
| 投影 | A2UI / CopilotKit+AG-UI | ✅ 早前 | 10 篇已盘 |
| 通道 | git（内容寻址）/ IPFS | git ✅ | hash 引用即证据的模式来源 |

企业界另有一层 MCP 网关（mcpservers.org 开源网关、WSO2、TrueFoundry 等——闭源未亲验）：
身份/授权/审计/路由已商品化——**业界事实上已把 MCP 当总线的 agent 端口，治理层商品化了。**

**缺口判断**：六件参考件各就各位，没人拼成"世界观总线"（自描述消息+双投影+语义级治理）
——马路（NATS）、海关（MCP 网关）、值机柜台（browser-use/CUA）、航显屏（A2UI）都有人造，
**没人造的是同一个航站楼**：同一 IR、同一条广播、同一份世界状态。

**由此的动作决定**：transferor 增加 MCP server 方言（snapshot/act/events 暴露为 MCP 工具），
直接吃 MCP 网关生态的现成治理；差异化（状态 diff、完工铃、不可逆分级、界面投影）作为
MCP 之上的扩展生长。
