# 15-世界核心的组成与职责：一等组件、本体、账本、主线与管道

> 一句话：**一等组件 = 内容相关的基础设施**。它包含三样东西——**本体（法律）、运行时（机制）、实例（数据）**；
> 对内它靠**主线（语义事件账本）**统一真相，靠**管道（通道）**搬字节与引用，对外它只开**出口（投影）**。
>
> **本篇回答的问题**（此前散在各处、需要反复重推的）：
> ① 一等组件里到底包含什么？② 它和"本体"是什么关系？③ 它像不像 systemd、只提供一连串基础设施？
> ④ 主线、管道、投影各连谁、各干什么？⑤ 两个投影之间靠什么保持一致？⑥ 什么条件下才算"世界起来了"？
>

> [12-内核选型对照](12-内核选型对照.md)、[14-总线词表v0](14-总线词表v0.md)。
> 性质：**规格**（与 11 篇同档），不是事实、不是立场。**凡与总纲冲突，以总纲为准。**

> **术语对齐（2026-09-26，防绕）**：本篇出现的这几个词，**有些是同一个东西的不同说法**：
>
> | 词 | 关系 |
> |---|---|
> | **总线 / 主线 / 语义事件账本 / 追加日志** | **同一个东西的四个说法**（功能 / 正式名 / 会计名 / 你们文档里的原名） |
> | **管道 / 通道** | 并行的**字节货运道**，**不需要全局一致** |
> | **本体 / 账本 / 读模型 / 运行时 / 门禁** | 世界核心**内部的模块**，**不是独立进程** |
> | **语言投影 / 视觉投影** | 世界核心开的**端口**；实现可以在核心内或核心外 |
>
> **一句话**：**总线是它的功能，账本是它的形态。**

## 一、先把三个问题分开（此前所有困惑都源于把这三件事混在一起）

| # | 问题 | 归哪个概念 | 答案 | 类比 |
|---|---|---|---|---|
| 1 | **世界住在哪里、谁依赖它** | `载` + **系统方式** | 一等组件 → 将来 PID 1 | 这栋**楼是谁的地、谁供电** |
| 2 | **世界里有什么、怎么组织** | `存` + **本体** | 一套极小核心本体 + 命名空间扩展 | 楼里**怎么划分房间、放什么家具** |
| 3 | **东西之间怎么说话** | `传` + **主线/管道** | 语义事件账本 + 字节通道 | 楼里的**走廊与门** |

**结论**：总线、命令行**不是**与"本体"并列的第三种东西——它们是**本体之间互动的路径**。
三者不冲突，是三层：**位置 → 内容 → 通路**。

## 二、一等组件是什么

### 2.1 两阶段（详见总纲 §1.1）

> **先做一个"一等组件"（系统开机就起它、别人依赖它）；成熟后做 PID 1。**

| 阶段 | 它站在哪里 | 对应站 |
|---|---|---|
| 一 | **载体上的一个一等组件**——载体对它的认知只有"启动它、给资源、给一条通道" | 寄主期 **B.5** |
| 二 | **世界的 init**；载体降为插座 | 自举 **C** → 换轨 **D** |

**硬前提**：**载体只知道"启动它"，不知道"它是什么"。**

### 2.2 它不是"插件"

| | **插件** | **一等组件** |
|---|---|---|
| 谁决定你怎么被装进去 | **宿主程序**定规矩（"你得实现我这几个函数"） | **系统**只知道"启动这个程序" |
| 换个宿主/载体 | 要照新宿主的规矩重写 | 照样能起 |
| 风险 | ⚠ 宿主定义你的边界 = **锚定** | ✅ 你自己定义自己 |

### 2.3 它包含三样东西——性质完全不同，必须分开

| # | 是什么 | 性质 | 生命周期 | 像 systemd 吗 |
|---|---|---|---|---|
| **1** | **本体**（词表/法律：世界里有什么、怎么说、什么算合法变更） | **法律** | 版本化、**内容寻址**、很少改，改了要留痕 | ❌ 不像（systemd 没有这种东西） |
| **2** | **本体运行时**（加载本体、管账本、算读模型、执行门禁、注册投影） | **机制 / 代码** | 你改它、升级它 | ✅ **这一部分最像 systemd** |
| **3** | **本体实例**（当前这个世界的对象图 + 事件账本） | **数据** | 只追加、可回滚 | ⚠ 有点像 journald |

**为什么必须分开**：不分开，就永远说不清"**是程序升级了，还是世界变了**"——而这正是"可复盘"要回答的。

**三者的角色一句话**：

- **本体是法律**（"什么算一次合法变更"）
- **运行时是法院和书记员**（按法律办事、记账）
- **实例是案卷**（这个世界具体发生过什么）

> **本体是"装起来的"吗？是**——但方式是"**运行时装起来 + 用内容寻址钉住版本**"，
> 而不是"把本体写进代码里"。任何人（人和 agent）都应能问：**"你现在跑的是哪一版本体？"**

### 2.4 内容无关 vs 内容相关（与 systemd 的确切分野）

| | **systemd / 载体** | **世界核心（一等组件）** |
|---|---|---|
| 它知道它管的东西是什么吗 | **不知道**——不管 unit 里跑的是 nginx 还是数据库 | **必须知道**——得懂"这条事件改的是哪个实体的哪个字段" |
| 因此它是 | **内容无关**的基础设施 | **内容相关**的基础设施 |
| 为什么 | 它服务的对象是"**程序**"，**程序自己懂自己的意义** | 它服务的对象是"**语义对象**"，**没有别人懂它们的意义——它必须自己懂** |

**这是本篇最承重的一句**：

> systemd 能只做基础设施，是因为**它服务的东西自己有脑子**。
> 世界核心服务的对象**没有脑子**——**所以"意义"必须由世界核心自己承担**。
> 这就是为什么它不能只做"一连串基础设施"：**它的内容就是世界。**

```

│
└─┬─ 世界核心（一等组件 → 将来的 PID 1）────────────── 内容相关的基础设施
  │
  │   ┌── 本体（法律）────── 极小核心词表 + 命名空间扩展（内容寻址、版本钉住）
  │   ├── 实例（数据）────── 对象图 + 事件账本
  │   └── 运行时（机制）──── 加载本体 / 管账本 / 算读模型 / 执行门禁 / 注册投影
  │
  │   ╔══════════════════════════════════════════════════════════╗
  │   ║  主线 = 语义事件账本（唯一交汇点，按 seq 只追加）           ║
  │   ╚═══════════════════════┬══════════════════════════════════╝
  │                           │ 派生（只读）
  │                           ▼
  │                     读模型（世界"现在"）
  │                      ┌────┴────┐
  │                      ▼         ▼
  │                 语言投影    视觉投影        ← 出口（叶子节点）
  │                      │         │
  └──────────────────────┼─────────┼──────────────
                         ▼         ▼
                      Agent 读    人看

  管道（通道）= 与主线并行的"货运道"：搬字节 / 大对象；主干道上只放 hash 引用

              └── 机器 / Agent / 人：三方都只"写事件"、都只"读投影"
```

## 四、各部分的职责（谁负责什么）

| 部件 | 负责什么 | 对应概念 | 现在有没有 |
|---|---|---|---|
| **载体** | 机器秩序：进程、内存、文件、IPC、隔离 | `载` | ✅ 有（VM 跑起来了） |
| **本体** | 定义"有什么、怎么说、什么算合法变更" | `存` 的一部分 | ⚠ 有草稿（14 篇），无实现 |
| **运行时** | 加载本体、管账本、算读模型、执行门禁、注册投影 | `存`/`传`/`管`/`显` | ⚠ 半个（`agentd` 有 `管`） |
| **实例（账本）** | 保管真相；按 `seq` 追加；可重放、可回滚 | `存` | ✅ 有（`world-core/src/ledger.rs`；`world-core check` 打印 `READY`、`read`／`state` 可用） |
| **主线** | **唯一交汇点**：所有交互都经过它 | `传` | ✅ 有（同上：追加只有 `World::commit` 一个入口；`channel` 也走它） |
| **管道** | 搬字节/大对象；主干道只放 hash 引用 | `传` | ❌ 无 |
| **语言投影** | 给 Agent 读的结构化视图 | `显` | ✅ 有（`world-core/src/project/language.rs`；出厂命令 `world-core project language`） |
| **视觉投影** | 给人的渲染视图（v1 实现 = web） | `显` | ⚠ 间接（`transferor` 是脐带件） |
| **门禁** | 按能力 + 不可逆性拦动作、留审计 | `管` | ✅ 有（`agentd`，测试全绿） |
| **脐带** | 把旧世界的任务翻译进来 | `进` | ✅ 有（`transferor`，12 测试全绿） |

> **"现在有没有"这一列的时点：2026-09-27（VM 实取）**。本列原写账本／主线／语言投影三者"❌ 无"，
> 那是本篇整理时的时点，落后于实物，已按现场更正（缺陷台账 **D-44**）。复算命令：
> `cd world-core && cargo build --locked && ./target/debug/world-core check`、`… project language`、
> `… state --json`。**第 137 行"运行时"那一格不在本次更正范围内**（它写的是 `agentd` 的 `管`，
> 未把 `world-core` 的运行时算进去）——本表其余各行仍是本篇原口径，读时请连同这一条时点一起读。
>
> **第 136 行"本体"那一格为什么不跟着改成"有"**：本篇指的是"**定义什么算合法变更**"这一层。
> 出厂本体（`world-core/ontology.json`）只是**一页出厂设置**，把**已知的三族信封 + 两个概念**（`notice`／`job`）写在里面；
> 而源码里**对 `concepts` 的读取是 0 处**——一个对象有哪些字段，今天**没有任何一处**照本体校验。
> 也就是说"事件的**形状**"由本体强制，"对象的**含义**"没有；该格因此维持"无实现"，与"账本已经有了"并读不矛盾。

## 五、主线与管道

### 5.1 主线 = 语义事件账本

- 世界的**唯一真相**，也是**唯一交汇点**；
- 只有一种操作：**按 `seq` 追加**。没有人（包括世界核心自己）可以改历史；
- **可复盘**（谁在何时改了哪个字段）= 读日志；**可回滚** = 追加补偿事件。

### 5.2 管道 = 字节货运道

- 搬字节、搬大对象；**主干道上只放 hash 引用**（11 篇 §五 的机场比喻：广播系统 vs 货运跑道）；
- 与主线**并行、不混载**：主线跑语义，管道跑字节，**运单号 = 内容 hash**。

### 5.3 为什么必须分工（不分开会怎样）

| 不分开 | 后果 |
|---|---|
| 大对象走主干道 | 上下文/带宽被字节挤爆；token 经济崩溃 |
| 字节流被当语义读 | 需要"翻译层"——**适配器又回来了**，与"两端都是语义内核"的裁决冲突 |

### 5.4 一处口径更正：不是"无中心"，是"无额外中间件"

[11 篇](11-总线工程规格.md) §二 写着"**第一版无中心**——点对点直连"。按本篇的拓扑，真实情况是：

> **星形拓扑，中心就是世界核心。**所谓"无中心"，实际意思是"**不额外引入一个 busd 中间件**"——
> 因为世界核心**本身就是那个汇接点**，那是它的职责，不是外加的中心。

**建议口径**：**"无额外中间件；世界核心即汇接点。"**
（否则以后读到"无中心"的人，会以为可以让两个投影自己对上——那正是要防的"两个世界"。）

## 六、三方：机器、Agent、人

| 谁 | 写什么事件 | 读什么投影 |
|---|---|---|
| **机器 / 设备** | "我做了什么"（`change` / `notice`）；执行结果 | "要我做什么"（`act`） |
| **Agent** | "请你做什么"（`act`）+ 它的结果 | **语言投影** |
| **人** | 在界面上操作 → 翻译成 `act` | **视觉投影** |

**三方之间没有直连**：它们**只跟账本对齐**，不互相聊。这正是"三方都能懂"成立的原因——**共同语言是账本给的，不是谈判谈出来的**。

### 例子："人让 agent 静音一条通知"穿过全景

| 步 | 谁 | 干什么 |
|---|---|---|
| 1 | 载体 | 给一块内存、一条 socket，把世界核心启动起来（**不知道"静音"是什么**） |
| 2 | 运行时 | 读**本体**：允许 `notice.mute` 吗？可逆吗？ |
| 3 | 视觉投影 | 把人的点击翻成一条 `act` 事件 → **写进主线** |
| 4 | 运行时 | 追加 `act` 事件；按门禁判可逆 → 执行 |
| 5 | 运行时 | 追加 `change` 事件（`before: false → after: true`） |
| 6 | 运行时 | 由账本**算出读模型** → 推给**两个投影** |
| 7 | 两个投影 | 人看到图标变；Agent 读到 `muted=true`（**各自只跟账本打交道**） |

## 七、两个投影

### 7.1 命名：语言投影 / 视觉投影

```
显 = N 端口注册表（全部同源，只许省略不许添加）
  ├─ 语言投影   ← 给 Agent 读（结构化，可直接进上下文）
  ├─ 视觉投影   ← 给人看；v1 的实现恰好是 web
  └─ 留位：听觉 等（总纲 §2.5 已写"听觉等留位"）
```

### 7.2 命名纪律：**"web"是实现，不是名字**

| 名字（进本体） | 实现（可换，属脐带/载体） |
|---|---|
| 语言投影 | 输出成文本 / 喂给模型 |
| **视觉投影** | **v1 = transferor 渲染到浏览器**；将来 = 桌面 / 终端 / Genode 原生 |

**三条反对"web 投影"这个名的纪律**（都是你们自己定的）：

| 出处 | 原文 |
|---|---|
| 总纲 **§2 切法规则** | "概念**按'要干的事'切，不按技术栈切**"——web 是技术栈 |
| 总纲 **§6 `进`** | "世界核心**不出现** DOM / web 字样" |
| 总纲 **§8** | "去掉 `surface` 四面枚举与 `browser.*` 命名空间……**渲染概念不进本体**" |

**顺带钉死 transferor 的定位**：它不是"web 投影"，它是"**视觉投影在 v1 的脐带件实现**"（属 `进`，不是 `显` 的本体部分）。

### 7.3 投影之间**不交互**——这就是"同源"的定义

- 投影是**出口（叶子节点）**，不是中继节点；
- 它们不需要交互，因为**它们只可能看到同一份东西**（同一份读模型、同一版词表）；
- "同源"不是靠**商量**达成的，是靠**结构**保证的。

### 7.4 同源怎么做到"可核验"

投影必须能出示"**我用的是哪一版词表**"（hash）——即 **词表本身也内容寻址**（[14 篇](14-总线词表v0.md) §4.2）。
拿两个投影声明的词表 hash 一比，就知道它们是不是同一套解释规则。
⚠ 外部教训：Solid 与 atproto 都只保证"读同一份**数据**"，**不保证"同一套解释规则"**。

### 7.5 漏水信号（设计自查清单）

只要出现下面任何一句，**就是真相分裂了**，必须停下来查：

- [ ] "投影 A 要通知投影 B"
- [ ] "让两个投影同步一下状态"
- [ ] "投影给投影发消息"
- [ ] "Agent 直接读界面的内容"（零截图、零坐标的判据在此）
- [ ] "这段状态存在投影里"（投影**不持有状态**，只持有渲染偏好）

## 八、账本规则（本篇提出，需总纲确认）

> **账本 = 语义事件；本体实例（对象/状态）= 它的投影。任何"直接改对象"的写入路径都不允许存在。**

**为什么必须立这条**：最糟的情况不是"选错账本"，而是**两本账**——对象存一份、事件存一份，两边各自演进 → **必然对不上，而且对不上时你不知道信谁**。

**先例（本会话核实）**：`AdaOS` 的设计就是 `primary_doc.direct_write: **false**`——技能不能直接写共享状态，必须经唯一的 `ProjectionService` 入口。

**一句话**：**一个写入口，一个账本。**

## 九、什么条件下才算"世界起来了"

| # | 条件 | 对应 |
|---|---|---|
| 1 | 运行时在跑 | `存`/`传`/`管` 机制就位 |
| 2 | **本体加载成功**（版本对得上） | 法律就位 |
| 3 | **账本能读能追加**（实例挂上） | 数据就位 |
| 4 | **投影已注册**，人和 Agent 能连上 | `显` 就位 |

**四条齐了，才叫 "boot 进世界"**——这正是总纲 §7 **B 门**的出门判据。

## 十、为什么这五条验收"只有本体能给"

| 你们的验收 | 靠什么实现 | 今天的 OS 能给吗 |
|---|---|---|
| **同一屏**（人和 agent 看同一份状态） | 同一份本体 + 两个投影 | ❌ 每个程序各画各的界面 |
| **留痕可复盘**（谁在何时改了哪个字段） | 本体里的**字段** + 事件账本 | ❌ 文件系统只存字节，**没有"字段"这个概念** |
| **坏了能回滚**（不用载体快照） | 本体的持久化 + 事件 | ❌ 只有文件系统快照 |
| **人离开 24 小时能答"发生过什么"** | 事件账本 | ❌ |
| **越界声明被拦下 + 流水人能读懂** | 能力 = 本体对象 + 门禁 | ⚠ 半能（uid/gid 太粗） |

**结论**：五条验收今天的 OS 一条都给不了，最承重的原因是——**它里面没有"本体"这一层**。
但**不是唯一原因**：另外三条结构性原因各自独立成立，缺了本体这一层也解释不掉它们——
① 某些安全机制**装上就卸不掉**（"吊销无法即时生效"因此是**内核原语**问题，不是缺一层声明）；
② **缺少跨进程的能力委托原语**（补它**要改内核**）；
③ 真·不可篡改**需要第二个地点**（是**物理**问题，不是层的缺失）。

> 出处：本篇原写"原因只有一个"，被 `WC-BOOK-001` §3.6.4（缺陷台账 **D-41**）判为**单因论**并逐字要求收回；
> 上面那三条即该书同节列出的另外三个独立原因。本处为依据件的落笔，不再重复全书的论证。

> 所以你们不是"**在** OS 之上加一个本体"，而是"**用本体重新定义 OS 该提供什么**"。

   - **本篇不给对照，"14 篇 §4.1"不是对照**（原写法是误引，登记为缺陷 **D-42**）：`14-总线词表v0.md` **全篇"权限"零命中**；
     它 §4.1（第 199 行起）的标题逐字是「自省**不是第四个家族**——它是读模型的一个 `subject`」，全节只讲自省与查询，
     与"权限"无关。
   - `14` 篇里唯一**形式**接近的一句是 §5.2 第 241 行的「`act` 结果作为事件追加 → **pending 读模型**由日志派生」——
     它讲的是"**待批集**"，不是"权限"。
   - 所以这一洞**今天没有对照**：可借用的只有"查询 = 读模型的一个 `subject`"（`14` 篇 §4.1）这个**形式上**的落点，

3. **账本保留窗**：保留多久、存哪、代价（对比：atproto 主动放弃全量历史；Nix 用代际）

6. **`trace` 因果链的长度与截断**
