## 一、外部生态对照表（按与 agentd 的相关度排序）

| 项目 | 亲验后它实际是什么 | 层级 | 与 agentd 的关系 |
|---|---|---|---|
| **Omarchy**（omacom） | Arch + Hyprland + Quickshell 发行版；IPC 面、2 个 agent 技能、崩溃闭环、snapper 快照、自研内核配方；已打包 CUA 驱动 | 发行版 | **我们要对接的对象**，不是对手（详见 08 篇） |
| **CUA**（trycua/cua） | computer-use 驱动：AT-SPI/UIA 可访问树 + 输入注入 + 合成光标；CLI/MCP/SDK 三接口；权限模式 standard/bounded/unrestricted；跨 macOS/Windows/Linux | GUI 操作层 | **互补**：CUA 回答"agent 怎么操作 GUI"，agentd 回答"agent 能碰什么"。Omarchy 已把 `cua-driver-bin` + `cua-hyprland-plugin` 收编进自家打包仓库 |
| **Dreamer**（原 /dev/agents，dreamer.com） | 商业云端 agent OS：个人代理 Sidekick、agent 应用市场、推送 agent 产出到已有 App。2024-11 露脸即 5600 万美元种子轮，Android 原班人马（David Singleton/Hugo Barra/Ficus Kirkpatrick） | 云端平台 | 同理念不同位面：它做"agent 的 Android"（云 + 多设备 + 平台经济），agentd 做"agent 的 systemd"（单机 + 发行版）。不冲突，但它若开源单机运行时，agentd 窗口会变小 |

## 二、重复度结论

- **概念重复：约 50%**。"agent OS" 已是拥挤口号，谁都在喊；但我们 01/02 篇主张的那句话——"agent 是 OS 里带权限、可审计、可回滚的组件，缺一个低于 harness 的能力门禁"——在亲验的仓库里没有第二个项目把它作为唯一命题来做。
- **实现重复：接近 0%**。没有人做"systemd 户口 + cap.d 声明即授权 + varlink 风格能力面 + journald 结构化审计 + btrfs/snapper 快照钩子"这条具体装配线。bashOS 借 OpenCode 的闸、CUA 做 GUI 注入、OpenOS 做云沙箱——都是相邻但不同的机制。
- **agentd 的三个差异化支点**：① 绑定发行版（Omarchy 的现成机制，而非发行版无关的自研栈）；② 门禁低于 harness；③ 不新造内核模块、不建云沙箱，只用 Linux 十五年攒下的现成零件（cgroup/btrfs/journald/Landlock）。

## 三、自查：我们自己重复了什么（两处，已在修正）

1. **崩溃诊断场景重复了 Omarchy 已交付的功能**。03 篇推演用"崩溃诊断"做场景，而 Omarchy 的 systemd-coredump → 通知 → agent 诊断闭环已经上线（08 篇判定 #10）。修正：03 篇场景保留作推演素材，但 agentd 不做诊断，只做审计钩子。
2. **裸 btrfs 快照重复了 snapper**。05 篇一日计划里的"btrfs 快照/回滚钩子"与 Omarchy 已装好的 snapper + limine-snapper-sync 重叠。修正：agentd 的快照组件改为编排 `snapper create`，不再自造（08 篇第五节已改）。

## 四、对 04 篇生态图的增补

04 篇生态位图建议补入四个坐标（更新时回填）：

- **Dreamer**——云端平台位（"agent 的 Android"）；
- **OpenOS**——容器 AOS 位（长跑工作负载）；
- **CUA**——GUI 操作层位（accessibility 注入，已被 Omarchy 收编）；
- **bashOS**——终端编排位（harness 内的权限闸，agentd 的反例）。

agentd 的位置不变：**单机系统服务层**。生态越热闹，这个位置越缺——因为云平台、容器 AOS、GUI 驱动都假设"下面有个可信的系统"，而这个"下面"今天还是裸的 sudo 或没有。

## 五、风险与窗口

- **最大变量是 Dreamer**：5600 万美元 + Android 原班人马，若转向开源单机运行时，agentd 的理念窗口会被挤压。但其云端平台商业模式与单机发行版集成不冲突，且短期内它需要的是"云上的 OS"，不是"你机器里的 systemd 服务"。
- **CUA 的权限模式值得跟踪**：standard/bounded/unrestricted 三档 + manifest 审阅，与 agentd 的 cap.d 声明即授权是同一问题域的两个答案。Omarchy 打包了 CUA，意味着"操作层已就位、门禁层仍空白"的组合格局成立——这正是 agentd 的入场位。
