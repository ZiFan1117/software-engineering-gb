# 语义世界 · 软件开发 skill

> 这份是我们**唯一**的工作方式。它从真实事故里长出来——每条规矩后面都有"为什么"和一个当时的实例，
> 因为没有实例的规矩没人会执行。

## 一、上位规则：**书 ＞ 规格 ＞ 流程**

书＝`world-core/docs/理论/语义世界-理论书-第一版-合订.md`（**唯一正件**）。

任何一次"不按上位来"的处置，**必须写全让路三要素**：**让的是哪一条**（`path:line` ＋逐字引文）／**为什么要让**／**谁批的**。
**半写＝不写**（有机器项盯着：`world-core/tools/spec_bridge.py` 判据⑦）。

## 二、文档集是**封闭**的：每个阶段就那么几份

**不许新增文档。不许把一份拆成几册。** 要加/要拆，先经作者批准。

| 阶段 | 就那么几份（固定） |
|---|---|
| **S0 立项** | `WC-FSR-001` 可行性｜`WC-SDP-001` 项目计划｜`WC-SQAP-001` 质量保证｜`WC-SCMP-001` 配置管理｜`WC-ATOM-001` 原子化约定 |
| **S1 需求** | `WC-SRS-001` 软件需求｜`WC-IRS-001` 接口需求｜`WC-UM-001` 用户手册 |
| **S2 设计** | `WC-ARCH-001` 架构｜`WC-HLD-001` 概要设计｜`WC-LLD-001` 详细设计｜**`WC-IC-001` 接口契约（全部模块在这一册里）**｜`WC-FMT-001` 形式规定 |
| **S3 骨架** | `WC-SK-001` 骨架 |
| **S4 实现** | `WC-GSOP-001` 编码规范｜`WC-UT-001` 单元测试｜`WC-COV-001` 覆盖率 |
| **S5 测试** | `WC-ST-001` 系统测试 |
| **S6 验收** | `WC-AT-001` 验收测试 |
| **S7 交付** | `WC-RN-001` 版本说明 |

**为什么**：文档散开以后，同一件事会有两个说法，读者不知道该信哪一份；维护的人也只改一份、漏另一份。
**实例**：接口契约曾按模块拆成 `WC-IC-M01`–`M10` **十一册**，要查一个接口得先猜它在哪一册。

**规格层不放这里**：规格在 `openspec/specs/`（一个能力一份 `spec.md`），change 在 `openspec/changes/`。
两者的分工只有一句话：**规格写"世界必须怎样"，流程文档写"这个项目怎么干"**。

## 三、文档里写什么、不写什么

**写**：这件事是什么、判据是什么、谁负责、什么算通过。**能自足的就写全，不要外引。**

**不写**（这是硬规矩）：

| 不写 | 为什么 | 那它去哪 |
|---|---|---|
| **修订记录／变更历史**（"V0.6 改了什么""本轮改后…"） | 正文是给读者用的，他要的是"现在是什么"，不是"我曾经写错什么"；掺在一起他就得在一堆括号里找那条规矩 | **git 提交历史**（提交信息写清"为什么改、依据哪一条"）。change 的来龙去脉写在该 change 自己的 `design.md`／`audit.md` |
| **"原写…现改为…"这类对照** | 同上；而且形态门禁会因此判 `Requirement text is very long`（实测 28 条 INFO 就是这么来的） | 同上 |
| **改因块、评审意见、席次判词** | 它们是**过程证据**，不是**规范** | change 的 `audit.md`／`review.md`；`world-core/docs/评审/` |
| **"参考某某文档 §x"的链式外引** | 链条一长就断（实测：退场一次产生 14 处悬空引用） | 真属于别处的，**一句写清是哪个编号的哪一节**，例如「见 `WC-SRS-001` §6.1」；**不要**"参见…另见…详见…"堆一串 |

**一条自检**：把这份文档单独打印出来，一个没读过别的东西的人能不能照着干活？**不能，就是外引太多了。**

## 四、不做"探针"这类额外件

**为什么**：探针是"为了检查而另造一个东西"——它自己就成了要维护、要声明、要评审的第三个对象。
**实例**：系统探针脚本曾往世界写未声明实体（`world://check/probe`），在"声明以外不许落账"这条校验立起来之后，
它们全部变成了红——**红得对**（世界不该接受未声明的东西），但代价是**为了检查而造的东西本身不合规矩**。

**规矩**：
- 要检查，就**在最靠近它的那条门禁脚本里就地检查**（`world-core/check.sh` 的某一步），**不另立探针文件**；
- 检查用的数据**必须是已声明的**（用 `ontology.json` 里真有的实体与字段），**不许为了测试往出厂本体里塞测试专用实体**；
- 已经存在、确有独立价值的工具（`spec_bridge.py`／`module_graph.py`／`trace_matrix.py` 这类）**不是探针**——它们是**门禁**，有判据、有反例、进版本控制。

## 五、每条判据都必须会红（否则它是装饰）

- **一判据一反例**：反例不变红 ⇒ **判该守卫是装饰，拒绝合入**。
- **★ 反例必须与"真实违规"同形态**（血泪）：某条"不许有修订记录"的判据只认带 `#` 的标题式，
  而实盘真违规**全是加粗式与表格式**（一行都不带 `#`）⇒ 判据永远绿，而它自带的 8 个反例**全"已红 OK"**。
  **自证通过 ≠ 判据有效**——**造完反例，去实盘跑一遍，看它到底抓到了什么**。
- **★ 判据不许"取文件里第一处字样"**（血泪）：某条判据取**第一处**"批准人"字样，
  于是正文里提一句"批准人"就把它带到错误位置、捕到空 ⇒ **误判**（把一份**已签**的评审记录判成"批准人栏是空的"）。
  ⇒ 判据要**认栏位形态**（`| **批准人** | 值 |`），并且**有几处就查几处**（"一处签了、另一处仍占位"正是要抓的）。
  **搜字样 ≠ 认结构**：凡是要判"某个字段填没填"，都按结构取，不按字符串第一次出现取。
- **★ 改了判据必须做反向验证**：把该字段清空/改坏 ⇒ **必须变红**；恢复 ⇒ 必须变绿。
  不做这一步，你无法区分"判据修好了"与"判据被改成永远绿"。
- **读数不许写死**：**读数现取**。同一个数在一轮之内就会变（实测判据条数 9→11、`validate` 项数 10→11），
  写死的读数**必然过期**，而过期的读数在评审席眼里**就是假话**（本项目为此被判过三次）。
  正确写法：**给命令 ＋「以该命令输出为准，本处不复述条数」**。
- **还要有正控**：把"不该红的"也钉住（`module_graph.py` 有 2 条"不应红"对照）。
- **反例不许互相污染**：夹具被前一个反例删掉，后面的反例就变成假绿（实测踩过）。

## 六、假证的四种形态（**都真的发生过**）

| 形态 | 长什么样 | 怎么破 |
|---|---|---|
| **脚本根本没跑** | 报"逐字节可复现"，其实生成器因路径错没执行 ⇒ 文件没变，hash 当然不变 | **用 mtime 证明它真跑了** ＋ **反向验证**（改一条输入，看输出是否随之变） |
| **相对路径解析到别处** | `[System.IO.File]::WriteAllText('openspec\x.py', …)` 写到了 `D:\Code\x.py`（.NET 的相对路径基准是进程 cwd，**不是 PowerShell 的位置**） | **一律绝对路径**；改完立刻回读 |
| **编码不符** | 子进程按 GBK 写、父进程按 UTF-8 解 ⇒ 六条读数全成 `—`，**看着有输出其实没读到** | 给子进程钉 `PYTHONIOENCODING=utf-8`；**正则匹配不到就当成失败**，不许当成"没有该项" |
| **命令不存在被当通过** | Windows 上 `openspec` 是 `.cmd/.ps1` 壳，`subprocess` 直调 `FileNotFoundError` | 解析 `shutil.which(name+'.cmd')`；**解析不到必须显式报错**，不许静默跳过 |

**通则**：**"没有输出"不等于"没有问题"。** 任何"检查通过"的结论，都要能说出它**为什么可能失败**。

## 七、不许把"没做到"写成"做到了"

- 还没有断言的条目：写 `- **证据（待补）**：…` 并给出落点。**不许**用「**证据**」这个标记而不给 token——那在形态上等于声称存在。
- 未实现的边界：**写真话**（"闸读不到风险等级"），不许写成"已防护"。
- 引用的东西必须真存在；**退场的件要给解析根**（`git show <退场前提交>:<原路径>`）。
- **不许**用"已并入别处"掩盖"它其实不在那儿"（实测：30 件来源材料**不在**合订本里）。

## 八、一个事实，只有一个权威载体；数值一律现算

别处**只引用、不复述**。数由生成器在生成时算，引用方给**复算命令**。
**读数必须带时点**：曾写"实测 5/5"，判据数一长到七条它就变成假证 ⇒ 改成"当时 5/0；现 6/1"。
**实例**：`BRIDGE.md` 的数值表写死过一次，在**建立它的那次提交上**就错了两个数（写 `133` 实测 `56`、写 `0 命中` 实测 `1`）。

## 九、生成物不许手编；生成链必须在仓内

`openspec/BRIDGE.md`、模块明细这类：**改输入、重跑生成器**，不许手改输出。
生成器与它的输入**必须在仓内**（实测：生成链原本在仓外，谁把输入退回旧版，判据④ 立刻红）。
**"闸在版本控制之外"等于没有闸。**

## 十、原子化（作者立的强制约定，`WC-ATOM-001`）

一个原子一件事：**单意图**（一句话说得清，出现"与／和／及"并列两事就拆）／**四件同夹**（契约＋实现＋测试＋生成物边车）／
**`deps == import` 且无环**／生成物不手编／UTF-8 无 BOM。机核：`world-core/tools/module_graph.py`。

## 十一、评审与签批

- **归档前必须有已签的评审**（结论 ∈ 批准／通过／有条件通过，且**批准人非空**）。CLI 的 `archive --yes` **不拦**（实测：缺 `review.md`、tasks 未勾，照样 rc=0 归档）⇒ 靠守卫判据①⑥。
- **结论枚举分档**：R4 ＝ 通过／有条件通过／退回；R5 ＝ 批准／驳回。**别混。**
- **不代签**：签字只在**评审通过之后**、按作者指示，并把作者原话**逐字**记在同栏。
- 评审记录必须写**"本档不能证明的事"**，否则读者会把它当万能背书。

## 十二、交付前自查（逐条过，不许跳）

1. 我说过的每个数，**现在**还能复现吗？命令与退出码抄了吗？（用 `openspec/tools/collect_evidence.py` 一次收齐四要素：时点／命令／原始输出／提交号）
2. 我新写的东西，**文档集里是不是多出来了一份**？正文里有没有掺修订记录、有没有堆外引？
3. 我新加的判据/断言，**有反例证明它会红**吗？有正控吗？
4. 有没有**把我没做的事写成了做过**？有没有**把"未定"写成"已定"**？
5. 我引用的文件/函数/节号**真的存在**吗？退场的件给解析根了吗？
6. 编码 UTF-8 无 BOM、行尾 LF 吗？（`git ls-files --eol` 查）
7. 生成物是**重跑生成器**得到的，还是我手改的？
8. 我碰了**不属于我**的文件吗？（并行作业时**独占文件**是硬边界）

## 十三、操作层的坑（省你半小时）

- **多行提交信息一律 `git commit -F <文件>`**。用 `-m "多行…"` 会被 PowerShell 拆坏：实测一次把消息里的 `--locked` 当成 git 选项、一次把后半段当成 pathspec。
- **PowerShell 不支持 heredoc**：命令里留一句 `<<'X'` 会让**整条命令解析失败**（实测踩过三次）。要么用 `-F <文件>`，要么写脚本文件。
- **PowerShell 变量名大小写不敏感**：`$b` 与 `$B` **是同一个变量**（曾因此静默毁掉一次对照循环）。
- **中文串里别用 ASCII 双引号**：Python 源码里写中文时用「」，否则不是语法错就是引号提前闭合。

### 读数环境三坑（**都不是被测对象的毛病，是"读数方式"的毛病——最容易产出假证**）

| 坑 | 长什么样 | 怎么破 |
|---|---|---|
| **管道改写编码** | `prog --json \| python -c "json.load(sys.stdin)"` ⇒ PowerShell 在管道里**重新编码**，Python 报 `Unexpected UTF-8 BOM` | **别用外壳管道传结构化输出**；**用单进程 Python**：`subprocess.run([...], capture_output=True)` 然后自己 `decode('utf-8')` |
| **`>` 换编码** | `prog --json > f.json` ⇒ PowerShell 的 `>` **默认写 UTF-16LE**，读回时 `0xff` 开头 | 用 `Out-File -Encoding utf8`（注意 5.1 会加 BOM）或**干脆不落盘**；要落盘就让**被调用的程序自己写** |
| **相对路径换基准** | `[System.IO.File]::WriteAllText('openspec\x.py', …)` 写到了 `D:\Code\x.py`（.NET 的相对路径基准是**进程 cwd**，不是 PowerShell 的位置） | **一律绝对路径**；改完立刻回读。（实测踩过 **3 次**，其中一次因此"反向验证"根本没跑成、差点把"判据改成永远绿"当成修好） |
| **`Get-Content -Raw` 按 GBK 解 UTF-8** | 主机 pwsh **5.1** 下，同一份文件用 `Get-Content` 数与用字节数**对不上** | 读文本一律走 **Python ＋ 显式 `encoding="utf-8"`** |
| **壳吃掉退出码** | 用 `python -c` 包装子进程时**忘了 `sys.exit(o.returncode)`** ⇒ 子进程 rc=1，包装进程 rc=0 ⇒ 报告里出现"**9 通过/2 失败**"却写 **rc=0** 的自相矛盾 | 包装脚本**必须把子进程退出码传出去**；**取证工具自己造假证，比被取证对象造假更坏** |
| （第五种）**命令不存在被当通过** | Windows 上 `openspec` 是 `.cmd/.ps1` 壳，`subprocess` 直调 `FileNotFoundError`；`openspec`（.ps1 shim）直调报 `WinError 193` | 解析 `shutil.which(name+'.cmd')` 或 `shell=True` 调 `.cmd`；**解析不到必须显式报错**，不许静默跳过 |

### 写作与编辑的坑（同族，都会让"我以为写进去了"变成假的）

- **多行提交信息一律 `git commit -F <文件>`**：用 `-m "多行…"` 会被 PowerShell 拆坏。
  实测两次：一次把消息里的 `--locked` 当成 git 选项、一次把 `` `--self-test` `` 当选项（`error: unknown option 'self-test'`）。
- **别在内联命令里写中文／转义**：`python -c "…中文…"` 与 `-replace '中文'` 实测**多次静默改坏或直接语法错**
  （`SyntaxError`、`unexpected character after line continuation character`）。
  ⇒ **要改文件就写脚本文件**（本仓外 `_fix.py` 亦可），别赌内联。
- **PowerShell 不支持 heredoc**：命令里留 `<<'X'` 会让**整条命令解析失败**（实测三次）。
- **PowerShell 变量名大小写不敏感**：`$b` 与 `$B` **是同一个变量**（曾因此静默毁掉一次对照循环）。
- **中文串里别用 ASCII 双引号**：Python 源码里写中文时用「」，否则不是语法错就是引号提前闭合。
- **Python 的 `b"…"` 里不许有非 ASCII**：`b"\xef\xbb\xbf# 带 BOM 的标题"` ⇒ `SyntaxError: bytes can only contain ASCII literal characters`。
- **`.ps1` 必须带 UTF-8 BOM**（本仓 `.gitattributes` 有这条；且 `edit` 工具写回时**会抹掉 BOM**）
  ⇒ **改完 `.ps1` 立刻验首 3 字节 `EF BB BF`**（实测违反 2 次）。


**通则**：**"没有输出"不等于"没有问题"**；**"读到的数"要先问一句"它是谁写的、用什么编码写的"**。
任何"检查通过"的结论，都要能说出它**为什么可能失败**。

### 另有两条与"跑门禁"有关

- **门禁工具的工作目录**：`trace_matrix.py`／`doc_integrity.py` 的缺省路径以 **`world-core/` 为根**（与 `check.sh` 同口径）。在仓根跑会报"输入缺失即未能校验"——**那是我跑错了，不是别人报假**。
- **长任务（编译、VM 测试）放后台**，别阻塞；但**报告前必须收结果**。

### 写"证据行"与改表格：两条**会被门禁当场抓**的形态（2026-09-28 实测）

| 形态 | 门禁怎么报 | 规矩 |
|---|---|---|
| `- **证据**：`那一行**没有反引号 token**（token 全放在子条目里） | `spec_bridge.py` 判据②：`证据行里没有反引号包起来的 token。**若本条尚无断言，请改用 `- **证据（待补）**：` 并写明落点**——用「证据」这个标记而不给 token，形态上等于声称存在`（守卫 11/0 → **10/1**） | **那一行自带 token**；像路径的 token（带 `/` 或 `.rs`／`.py`／`.sh`／`.md` 后缀或 `::`）**会被核存在性** ⇒ 只写真实存在的。真没有断言就用 `证据（待补）` |
| 改表格行时**改错列**、或把某格**"清空成空格"** | `table_width_audit.py`：`表块 N，行宽不符 1`（例：该行 **6 格 vs 表头 5 格**） | **按格重建**（`cells = 表头列数`）＋**改完立刻跑表格审计**。**空格在 markdown 里仍然算一格**——"清空"不等于"删掉" |

### ★ 文档"必然会烂"的一条根因（记住它，能省很多返工）

**文档重述了另一处的权威 ⇒ 那份权威一变，文档就成了假话。**
实测（`S5/S6/S7` 三份，隔十轮全过期）：`WC-ST-001` 的"测试文件清单"重述了**目录**（列 7 个、实有 9 个）；
`WC-AT-001`／`WC-RN-001` 重述了**命令输出**（写"⑨ 今天不满足"、"真环仍红"，而它们已转绿/已消）。

**处置口径（两档）**：
1. **优解**：**别重述**——写"以命令输出为准"＋给命令，或让门禁承担这条判据（"文档里的清单 ≡ 目录实际文件"做成会红的检查）；
2. **次优解**（今天没有那条判据时）：**清单照写，但标明"以命令为准、本表不权威"**，并把"**这份文档不自带门禁、会漂**"写成一句如实登记——
   **不许让读者以为文档里的数字是权威**。


### 变异／副本实验的三个坑（**都会产出假证**，2026-09-28 实测）

| 坑 | 症状 | 破法 |
|---|---|---|
| **`cargo test` 可能跑旧二进制 ⇒ 假绿** | 变异明明打上了，测试却 `ok`。根因：副本用 `tar` 复制会**保留 mtime**，而 cargo 的新鲜度判定是 **mtime 比较** ⇒ **不重建**，CLI 用例跑的是上一轮的二进制。**实测踩到两次。** | 每条变异先 **`find src tests -name '*.rs' -exec touch {} +`** ＋ `cargo build --locked --bin world-core`，**再**跑测试。凡测 `tests/cli.rs` 的工区都踩得到 |
| **共享临时目录被并行工区互踩** | `/tmp/mut`／`/tmp/tam`／`/tmp/ta` 是任务书里的**写死路径** ⇒ 一个工区把另一个正在用的副本**中途重拷**（于是出现上面那种假绿）；`/tmp`（tmpfs 3.9G）一度 93% 满、`cargo` 报 `No space left on device` | 每个工区用**带自己后缀的私有路径**（`/tmp/mut-<工区>`／`/tmp/t-<工区>`），用完清 |
| **`scp -r` 带过去的权限位会造"假红"** | Windows → VM 的 `scp -r` 把目录弄成 **705/707** ⇒ `cap.d` 触发**静态墙** ⇒ **全部用例一起红**（看着像"世界坏了"，其实是传输） | 传完 `chmod 755` 目录再跑。**`push-vm.ps1` 的 base64 ＋ `mkdir -p` 路径不保留 mode，故没有这个问题**——这也是"用仓内既有工具而不是随手 `scp`"的一个理由 |
| **★ 同步与工区落盘之间的竞态 ⇒ 假"编译失败"** | 并行工区**刚**新建 `src/*.rs`、又已在 `mod.rs` 里 `pub mod` 了它，而我的镜像同步**跑在它落盘之前** ⇒ VM 上"文件不存在" ⇒ `error[E0583]: file not found for module X`、`could not compile`。**看起来像代码错，其实是时序** | **复跑一次同步再判**（实测：第一次 `HEALTH=FAIL`＋5 条 error；重新同步后 **`HEALTH=OK`、0 error**——三个文件其实都在、且都在该工区的文件面内、`src/lib.rs` 没被碰）。判"树坏没坏"时**先看那几个 `mod` 声明的源文件在不在**，别急着当成缺陷报 |

**通则（与 §六 同一句）**：**"测试绿了/红了"要先问一句"我跑的是哪一个二进制、哪一个副本、哪一棵树"**。


## 十四、并行作业（多智能体/多人同时改）

- **一个工区独占一组文件**，边界写进任务书；跨了就是事故（哪怕改得对）。
- 别人的文件里发现问题：**只登记，不动手**（写进自己的回报，让对应的工区改）。
- 交件时**必须报**：改了哪些文件（`git status --porcelain` 逐字）、每个读数带时点与提交号、**没做的事逐条给原因**。
- 并发下"我开工时的事实"会过期：**给双坐标**（`HEAD` 上如何／工作区如何），**不替它下结论**。

---

**最后一句话**：这个项目里，**最贵的错不是"没做完"，是"把没做完说成做完了"**——因为后者会让所有下游判断一起错。
凡是拿不准的，写「无法判定（原因）」比写一个好看的结论有价值得多。
