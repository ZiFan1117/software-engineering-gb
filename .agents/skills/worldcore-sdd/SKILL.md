# 语义世界 · 软件开发 skill

> 这份是我们**唯一**的工作方式。它从真实事故里长出来——每条规矩后面都有"为什么"和一个当时的实例，
> 因为没有实例的规矩没人会执行。

## 一、上位规则：**书 ＞ 规格 ＞ 流程**

书＝`world-core/docs/理论/语义世界-理论书-第一版-合订.md`（**唯一正件**）。

任何一次"不按上位来"的处置，**必须写全让路三要素**：**让的是哪一条**（`path:line` ＋逐字引文）／**为什么要让**／**谁批的**。
**半写＝不写**（有机器项盯着：`world-core/tools/spec_bridge.py` 判据⑦）。

## 二、文档集是**封闭**的：每个阶段就那么几份

**不许新增文档。不许把一份拆成几册。** 要加/要拆，先经作者批准。

| 阶段 | 就那么几份（固定） |
|---|---|
| **S0 立项** | `WC-FSR-001` 可行性｜`WC-SDP-001` 项目计划｜`WC-SQAP-001` 质量保证｜`WC-SCMP-001` 配置管理｜`WC-ATOM-001` 原子化约定 |
| **S1 需求** | `WC-SRS-001` 软件需求｜`WC-IRS-001` 接口需求｜`WC-UM-001` 用户手册 |
| **S2 设计** | `WC-ARCH-001` 架构｜`WC-HLD-001` 概要设计｜`WC-LLD-001` 详细设计｜**`WC-IC-001` 接口契约（全部模块在这一册里）**｜`WC-FMT-001` 形式规定 |
| **S3 骨架** | `WC-SK-001` 骨架 |
| **S4 实现** | `WC-GSOP-001` 编码规范｜`WC-UT-001` 单元测试｜`WC-COV-001` 覆盖率 |
| **S5 测试** | `WC-ST-001` 系统测试 |
| **S6 验收** | `WC-AT-001` 验收测试 |
| **S7 交付** | `WC-RN-001` 版本说明 |

**为什么**：文档散开以后，同一件事会有两个说法，读者不知道该信哪一份；维护的人也只改一份、漏另一份。
**实例**：接口契约曾按模块拆成 `WC-IC-M01`–`M10` **十一册**，要查一个接口得先猜它在哪一册。

**规格层不放这里**：规格在 `openspec/specs/`（一个能力一份 `spec.md`），change 在 `openspec/changes/`。
两者的分工只有一句话：**规格写"世界必须怎样"，流程文档写"这个项目怎么干"**。

## 三、文档里写什么、不写什么

**写**：这件事是什么、判据是什么、谁负责、什么算通过。**能自足的就写全，不要外引。**

**不写**（这是硬规矩）：

| 不写 | 为什么 | 那它去哪 |
|---|---|---|
| **修订记录／变更历史**（"V0.6 改了什么""本轮改后…"） | 正文是给读者用的，他要的是"现在是什么"，不是"我曾经写错什么"；掺在一起他就得在一堆括号里找那条规矩 | **git 提交历史**（提交信息写清"为什么改、依据哪一条"）。change 的来龙去脉写在该 change 自己的 `design.md`／`audit.md` |
| **"原写…现改为…"这类对照** | 同上；而且形态门禁会因此判 `Requirement text is very long`（实测 28 条 INFO 就是这么来的） | 同上 |
| **改因块、评审意见、席次判词** | 它们是**过程证据**，不是**规范** | change 的 `audit.md`／`review.md`；`world-core/docs/评审/` |
| **"参考某某文档 §x"的链式外引** | 链条一长就断（实测：退场一次产生 14 处悬空引用） | 真属于别处的，**一句写清是哪个编号的哪一节**，例如「见 `WC-SRS-001` §6.1」；**不要**"参见…另见…详见…"堆一串 |

**一条自检**：把这份文档单独打印出来，一个没读过别的东西的人能不能照着干活？**不能，就是外引太多了。**

## 四、不做"探针"这类额外件

**为什么**：探针是"为了检查而另造一个东西"——它自己就成了要维护、要声明、要评审的第三个对象。
**实例**：系统探针脚本曾往世界写未声明实体（`world://check/probe`），在"声明以外不许落账"这条校验立起来之后，
它们全部变成了红——**红得对**（世界不该接受未声明的东西），但代价是**为了检查而造的东西本身不合规矩**。

**规矩**：
- 要检查，就**在最靠近它的那条门禁脚本里就地检查**（`world-core/check.sh` 的某一步），**不另立探针文件**；
- 检查用的数据**必须是已声明的**（用 `ontology.json` 里真有的实体与字段），**不许为了测试往出厂本体里塞测试专用实体**；
- 已经存在、确有独立价值的工具（`spec_bridge.py`／`module_graph.py`／`trace_matrix.py` 这类）**不是探针**——它们是**门禁**，有判据、有反例、进版本控制。

## 五、每条判据都必须会红（否则它是装饰）

- **一判据一反例**：反例不变红 ⇒ **判该守卫是装饰，拒绝合入**。
- **还要有正控**：把"不该红的"也钉住（`module_graph.py` 有 2 条"不应红"对照）。
- **反例不许互相污染**：夹具被前一个反例删掉，后面的反例就变成假绿（实测踩过）。

## 六、假证的四种形态（**都真的发生过**）

| 形态 | 长什么样 | 怎么破 |
|---|---|---|
| **脚本根本没跑** | 报"逐字节可复现"，其实生成器因路径错没执行 ⇒ 文件没变，hash 当然不变 | **用 mtime 证明它真跑了** ＋ **反向验证**（改一条输入，看输出是否随之变） |
| **相对路径解析到别处** | `[System.IO.File]::WriteAllText('openspec\x.py', …)` 写到了 `D:\Code\x.py`（.NET 的相对路径基准是进程 cwd，**不是 PowerShell 的位置**） | **一律绝对路径**；改完立刻回读 |
| **编码不符** | 子进程按 GBK 写、父进程按 UTF-8 解 ⇒ 六条读数全成 `—`，**看着有输出其实没读到** | 给子进程钉 `PYTHONIOENCODING=utf-8`；**正则匹配不到就当成失败**，不许当成"没有该项" |
| **命令不存在被当通过** | Windows 上 `openspec` 是 `.cmd/.ps1` 壳，`subprocess` 直调 `FileNotFoundError` | 解析 `shutil.which(name+'.cmd')`；**解析不到必须显式报错**，不许静默跳过 |

**通则**：**"没有输出"不等于"没有问题"。** 任何"检查通过"的结论，都要能说出它**为什么可能失败**。

## 七、不许把"没做到"写成"做到了"

- 还没有断言的条目：写 `- **证据（待补）**：…` 并给出落点。**不许**用「**证据**」这个标记而不给 token——那在形态上等于声称存在。
- 未实现的边界：**写真话**（"闸读不到风险等级"），不许写成"已防护"。
- 引用的东西必须真存在；**退场的件要给解析根**（`git show <退场前提交>:<原路径>`）。
- **不许**用"已并入别处"掩盖"它其实不在那儿"（实测：30 件来源材料**不在**合订本里）。

## 八、一个事实，只有一个权威载体；数值一律现算

别处**只引用、不复述**。数由生成器在生成时算，引用方给**复算命令**。
**读数必须带时点**：曾写"实测 5/5"，判据数一长到七条它就变成假证 ⇒ 改成"当时 5/0；现 6/1"。
**实例**：`BRIDGE.md` 的数值表写死过一次，在**建立它的那次提交上**就错了两个数（写 `133` 实测 `56`、写 `0 命中` 实测 `1`）。

## 九、生成物不许手编；生成链必须在仓内

`openspec/BRIDGE.md`、模块明细这类：**改输入、重跑生成器**，不许手改输出。
生成器与它的输入**必须在仓内**（实测：生成链原本在仓外，谁把输入退回旧版，判据④ 立刻红）。
**"闸在版本控制之外"等于没有闸。**

## 十、原子化（作者立的强制约定，`WC-ATOM-001`）

一个原子一件事：**单意图**（一句话说得清，出现"与／和／及"并列两事就拆）／**四件同夹**（契约＋实现＋测试＋生成物边车）／
**`deps == import` 且无环**／生成物不手编／UTF-8 无 BOM。机核：`world-core/tools/module_graph.py`。

## 十一、评审与签批

- **归档前必须有已签的评审**（结论 ∈ 批准／通过／有条件通过，且**批准人非空**）。CLI 的 `archive --yes` **不拦**（实测：缺 `review.md`、tasks 未勾，照样 rc=0 归档）⇒ 靠守卫判据①⑥。
- **结论枚举分档**：R4 ＝ 通过／有条件通过／退回；R5 ＝ 批准／驳回。**别混。**
- **不代签**：签字只在**评审通过之后**、按作者指示，并把作者原话**逐字**记在同栏。
- 评审记录必须写**"本档不能证明的事"**，否则读者会把它当万能背书。

## 十二、交付前自查（逐条过，不许跳）

1. 我说过的每个数，**现在**还能复现吗？命令与退出码抄了吗？（用 `openspec/tools/collect_evidence.py` 一次收齐四要素：时点／命令／原始输出／提交号）
2. 我新写的东西，**文档集里是不是多出来了一份**？正文里有没有掺修订记录、有没有堆外引？
3. 我新加的判据/断言，**有反例证明它会红**吗？有正控吗？
4. 有没有**把我没做的事写成了做过**？有没有**把"未定"写成"已定"**？
5. 我引用的文件/函数/节号**真的存在**吗？退场的件给解析根了吗？
6. 编码 UTF-8 无 BOM、行尾 LF 吗？（`git ls-files --eol` 查）
7. 生成物是**重跑生成器**得到的，还是我手改的？
8. 我碰了**不属于我**的文件吗？（并行作业时**独占文件**是硬边界）

## 十三、操作层的坑（省你半小时）

- **多行提交信息一律 `git commit -F <文件>`**。用 `-m "多行…"` 会被 PowerShell 拆坏：实测一次把消息里的 `--locked` 当成 git 选项、一次把后半段当成 pathspec。
- **PowerShell 变量名大小写不敏感**：`$b` 与 `$B` **是同一个变量**（曾因此静默毁掉一次对照循环）。
- **中文串里别用 ASCII 双引号**：Python 源码里写中文时用「」，否则不是语法错就是引号提前闭合。
- **门禁工具的工作目录**：`trace_matrix.py`／`doc_integrity.py` 的缺省路径以 **`world-core/` 为根**（与 `check.sh` 同口径）。在仓根跑会报"输入缺失即未能校验"——**那是我跑错了，不是别人报假**。
- **长任务（编译、VM 测试）放后台**，别阻塞；但**报告前必须收结果**。

## 十四、并行作业（多智能体/多人同时改）

- **一个工区独占一组文件**，边界写进任务书；跨了就是事故（哪怕改得对）。
- 别人的文件里发现问题：**只登记，不动手**（写进自己的回报，让对应的工区改）。
- 交件时**必须报**：改了哪些文件（`git status --porcelain` 逐字）、每个读数带时点与提交号、**没做的事逐条给原因**。
- 并发下"我开工时的事实"会过期：**给双坐标**（`HEAD` 上如何／工作区如何），**不替它下结论**。

---

**最后一句话**：这个项目里，**最贵的错不是"没做完"，是"把没做完说成做完了"**——因为后者会让所有下游判断一起错。
凡是拿不准的，写「无法判定（原因）」比写一个好看的结论有价值得多。
