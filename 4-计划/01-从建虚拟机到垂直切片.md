## 〇·补 · 环境结论（2026-09-25 定稿：**用 VM，不用 WSL**）

> **准话：跑这个项目用 Hyper-V 真 Arch VM。WSL 不做开发环境。**
> 本节**第三次修正**：初稿说"必须先建 VM"、二稿改成"WSL2 先行"，**两次都不对**，理由如下。

**为什么最终是 VM（不是 WSL）**：

1. **三条红线不是"以后的事"，它们就是验收标准本身**——`boot 进世界` / `载体快照回滚` /
   `换载不动世界`。**用一个做不到这三件事的环境去开发，等于在错误的标尺上量**；
2. **WSL 省不到时间**：P4（定本体）是纸上的活，**不需要任何 Linux**；等真要跑代码（P5）时，
   VM 早建好了。WSL 在关键路径上省 **0 分钟**，却多出一套环境；
3. **晚发现 = 最贵**：在 WSL 上写出来的代码，会不知不觉依赖微软那棵内核的配置、
   WSL 自己的 `/init` 行为、或设备的缺失。搬到真载体才发现——这正是"**世界漏进载体**"的病，
   而且是最晚才发现的那一种。

**WSL 唯一正当的用途**：将来做**第二载体对照实验**——
同一个世界在 WSL 与真 VM 上都能跑、核心一行不改 = "换插座不拆楼"的**实证**。
**那时才装它，不是现在。**

**正确的次序**：

| 什么时候 | 干什么 | 环境 |
|---|---|---|
| **今天** | **后台装 VM**（P0–P2）；**同时用纸做 P4** | **两条线并行** |
| **P3** | 基线自检全绿 + 打检查点 | **真 VM** |
| **P5** | 写 image 持久化、总线 v0、门禁 v0 | **真 VM** |
| 将来做对照实验时 | 装 WSL，把世界搬过去跑一遍 | WSL（第二载体） |

**关键**：VM 安装（2–3 小时）**不需要你盯着**——它在后台跑，你在纸上做 P4。
所以"建 VM 慢"根本不是理由。

**三条红线（记录备查，说明为什么 WSL 不够格）**：

| 红线 | WSL2 为什么过不了 |
|---|---|
| 要验 **`boot 进世界`** | 没有 boot 这一环，只有"启动一个进程" |
| 要验 **`载体快照回滚`** | 没有干净检查点（`wsl --export` 慢、拷 VHDX 粗） |
| 要验 **`换载不动世界`** | 内核只能重编微软那棵树，换不了发行版 / 微内核 |

## 一、工具选型：**Hyper-V + 真 Arch**（WSL 不做开发环境）

> 先读 §〇·补：**用 VM，不用 WSL**。下表说明为什么。

| 方案 | 优 | 劣 | 判 |
|---|---|---|---|
| **Hyper-V**（系统自带） | 零安装；原生性能；**检查点免费**；专业版自带 | Linux 客户机**图形弱**（无 3D）；USB 直通麻烦 | ✅ **首选** |
| VMware Workstation Pro（个人免费） | 图形好、快照成熟 | 要装；与 Hyper-V 共存有性能税 | ⚠ 将来真需要图形再上 |
| VirtualBox | 免费 | 在 Hyper-V 宿主上**不稳**、慢 | ⚠ 不推荐 |
| **WSL2** | 轻、启动快；`/mnt/d` 直连 Windows 侧文件 | 无 boot 环节；内核只能重编微软那棵树；无干净检查点 | ❌ **不做开发环境**（详见 §〇·补）；只留给将来的第二载体对照 |

**为什么 Hyper-V 就够**：我们要的三样它全给——
① **真 boot**（WSL 没有 boot 这一环，它只有"启动一个进程"）；② **检查点**（免费回滚，正是"实验舱"的雏形）；
③ 零安装。**图形不是现在的需求**——投影 v0 是**文本模式**。

## P0 · 准备（今天，1 小时）

**1. 开启 Hyper-V**（管理员 PowerShell）：
```powershell
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V-All -All
# 完成后重启
```

**2. 下载 Arch ISO**：archlinux.org 的 `archlinux-x86_64.iso`（每月更新），放到 `D:\vm\`。

**3. 建目录**：
```powershell
New-Item -ItemType Directory -Force D:\vm\world, D:\vm\iso | Out-Null
```

**判据**：`Get-VM` 能返回（哪怕是空列表）、ISO 在位。

## P1 · 建 VM（半小时）

```powershell
# 建 VM：第二代（UEFI）、80 GB 动态磁盘
New-VM -Name world -Generation 2 -MemoryStartupBytes 8GB `
       -NewVHDPath D:\vm\world\world.vhdx -NewVHDSizeBytes 80GB
Set-VMProcessor -VMName world -Count 8
Set-VMMemory   -VMName world -DynamicMemoryEnabled $true -MinimumBytes 4GB -MaximumBytes 16GB
# 关 Secure Boot（Arch 的 ISO 默认不带签名，不关起不来）
Set-VMFirmware -VMName world -EnableSecureBoot Off
# 挂 ISO 并设为第一启动项
Add-VMDvdDrive -VMName world -Path D:\vm\iso\archlinux-x86_64.iso
$dvd = Get-VMDvdDrive -VMName world
Set-VMFirmware -VMName world -FirstBootDevice $dvd
```

**三条关键选择与理由**：

1. **必须选第二代（UEFI）**——世界要"boot 进去"，UEFI + `systemd-boot` 是现在的标准；
   将来测"boot 进世界"也在这条路上；
2. **关 Secure Boot**——Arch 的 ISO 没签名。将来真要开，是自己签名的事，现在不碰；
3. **网络用 Default Switch（NAT）**——能上网就够（脐带要访问外网）。**不需要桥接**。

**可选（将来跑 microVM 才需要）**：
```powershell
# 嵌套虚拟化：让 VM 里还能再跑 KVM/Firecracker
Set-VMProcessor -VMName world -ExposeVirtualizationExtensions $true
```

**判据**：VM 能启动并停在 archiso 的 root 提示符。

## P2 · 装最小 Arch（2–3 小时）

> 机械步骤照 **Arch Wiki 的 Installation guide**（那是权威，别照抄二手教程）。
> 这里只定**我们的选择**——分区方案与包清单。

### 分区方案（btrfs + subvolume）

```
/dev/sda
├── p1  EFI   512M   fat32   → /boot
└── p2  btrfs  其余   subvolumes:
     ├── @           → /
     ├── @home       → /home
     ├── @snapshots  → /.snapshots      （snapper 用）
     ├── @var        → /var
     └── @world      → /srv/world       ← 世界的家
```

**为什么给世界单开一个 subvolume（`@world`）**：世界的状态要能**单独配额、单独盘点、单独导出**——
这是立宪四条里"退出权"的最低要求。

### 包清单（最小 + 我们需要的）

```
base  linux  linux-firmware  btrfs-progs  snapper
sudo  git  openssh  networkmanager  neovim
go  python
strace  bpf            # 后面审计/观测要用
```

**明确不装**：桌面环境（投影 v0 是文本模式）；任何 MAC 安全模块（SELinux/AppArmor）——
权限模型只保留我们自己这一层，调试时才分得清是谁拦的。

### 判据（逐条命令）

| 检查 | 命令 | 期望 |
|---|---|---|
| 内核够新 | `uname -r` | ≥ 5.13（Landlock 需要） |
| cgroup v2 unified | `cat /sys/fs/cgroup/cgroup.controllers` | 有输出（不是空） |
| btrfs 生效 | `findmnt -no FSTYPE /` | `btrfs` |
| subvolume 齐 | `btrfs subvolume list /` | 看到 `@` `@home` `@world` |
| 快照可用 | `snapper -c root list` | 能列出 |
| 网络 | `ping -c1 archlinux.org` | 通 |

## P3 · 基线四项自检（1 小时）

把总纲 §11 的判据变成**能跑的脚本**。写 `~/check-baseline.sh`，四项：

```bash
#!/usr/bin/env bash
set -u
fail=0
chk(){ printf '%-28s' "$1"; shift; if "$@" >/dev/null 2>&1; then echo OK; else echo FAIL; fail=1; fi; }

# ① 载：内核给了什么
chk "内核 >= 5.13"      bash -c '[ "$(uname -r | cut -d. -f1)" -ge 6 ] || [ "$(uname -r | cut -d. -f1)" -eq 5 -a "$(uname -r | cut -d. -f2)" -ge 13 ]'
chk "cgroup v2 unified" test -f /sys/fs/cgroup/cgroup.controllers
chk "btrfs 根"          bash -c '[ "$(findmnt -no FSTYPE /)" = btrfs ]'
chk "Landlock 可用"     bash -c 'grep -qw landlock /proc/kallsyms || dmesg | grep -qi landlock || true'

# ② 存：快照与回滚（载体级，将来要被世界级替代）
chk "snapper 可列"      snapper -c root list
chk "@world 独立"       bash -c 'btrfs subvolume list / | grep -q "@world"'

# ③ 可开发：寄主期刚需
chk "go"                command -v go
chk "python"            command -v python
chk "git"               command -v git

# ④ 审计与观测
chk "strace"            command -v strace
echo "---"; [ $fail -eq 0 ] && echo "基线全绿" || { echo "有 FAIL，别往下走"; exit 1; }
```

**判据**：脚本输出 **"基线全绿"**。任何一项 FAIL，**先修完再进 P4**。

**打完检查点**：`Checkpoint-VM -Name world -SnapshotName "baseline"`。

## 三、三条纪律

1. **不跳站，但允许并行**——纸上 **P4** 与后台**装 VM（P0–P2）**同时走；
   **P3 基线不绿，不许开始 P5 写代码**；
2. **每站先打检查点**——`Checkpoint-VM -Name world -SnapshotName "p2-done"`。
   VM 的最大价值就是这个：**搞坏了 30 秒回到上一站**；
3. **产出必须可验证**——脚本或命令，不接受"我觉得好了"。

## 四、三条停机线（什么时候承认走错了，回上一步）

1. P5 连续三次尝试仍做不到"**同一份状态同屏**" → 本体设计有问题，**回 P4**；
2. P6 超过**开工前预设的工期**仍无法用宿主工具改世界 → 世界核心抽象过重，**回 P4**；
3. P7 搬入后世界内工具**不可用** → `存` 或 `显` 能力不足，**回 P6 补**，而不是硬搬。

## 五、明确不做

1. **WSL 不做开发环境**（2026-09-25 定稿；本条经三次修正）：
   三条红线（`boot 进世界` / `载体快照回滚` / `换载不动世界`）**就是验收标准本身**——
   用一个做不到的环境去开发，等于**在错误的标尺上量**；而且 WSL 在关键路径上**省 0 分钟**
   （P4 不需要 Linux），却会让代码悄悄依赖微软那棵内核与 WSL 自己的 `/init`——
   那正是**最晚才发现**的"世界漏进载体"。
   **唯一例外**：将来做**第二载体对照实验**时接上它（那时才装，理由见 §〇·补）；
2. **不在 VM 里装桌面**（投影 v0 是文本模式）；
3. **不把世界的持久化建在 btrfs 快照上**——这是全项目**最承重的一条**（P5 动作 2 的判据就是为它设的）；
4. 不追 GPU / 3D；
5. 不开 Secure Boot（现在不碰签名）。

## 六、一个白送的实验（VM 独有的好处）

VM 里的载体快照**极便宜**，这正好给你一个**反面教材**：

```
① 打 VM 检查点 t0
② 在世界里做一次改动并记下
③ 在世界内回滚（只许用世界自己的机制，不许调 btrfs/snapper）
④ 用 strace 证明：回滚全程没有调用载体快照
```

**能通过 = "换插座不拆楼"成立**；不能通过 = 世界的状态还长在载体上，**换轨就是拆楼**。
这个实验在物理机上做很贵，在 VM 里做几乎免费。
