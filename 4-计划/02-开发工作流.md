# 02-开发工作流：让 Agent 把"手"伸进 Linux

> 一句话：**主机管"写"，Linux 管"跑"，一个入口管"伸进去"。** 三件事分开之后，
> 换载体（真 VM → 将来的 Genode → 对照实验用的 WSL）**只改一个变量**，工作流不动。
>
> 整理日期：2026-09-25。前置：[01-从建虚拟机到垂直切片.md](01-从建虚拟机到垂直切片.md)
> （**§〇·补 定稿：用 VM，不用 WSL**）。
> 本机实测：`ssh`/`scp`/`git`/VS Code 已装；**`rsync`/`make`/`just` 未装** → 同步与入口都不能依赖它们。

---

## 一、先分清三个角色（混在一起就会难受）

| 角色 | 放在哪 | 为什么 |
|---|---|---|
| **写代码**（读文件、改文件、搜索） | **主机**（Windows 的 `D:\Code`） | Agent 的原生文件工具直接作用于 Windows 文件系统，最可靠 |
| **跑与测**（构建、执行、测试） | **真 VM**（Hyper-V + Arch） | 三条红线（boot / 快照 / 换载）**就是验收标准本身**，只有真 VM 能做到 |
| **驱动**（发命令、收结果） | **主机**，通过一条**固定入口**伸进 VM | 入口固定 = 换载体不用改习惯 |

## 二、推荐形态

```
D:\Code\07-agent-native-os\          ← 唯一真相（git 仓库，Agent 在这里写）
        │
        │  ① 同步：git push（不用 rsync —— 本机没装）
        ▼
~/world/  （VM 原生盘 ext4）          ← 构建与测试在这里跑（快）
        │
        │  ② 执行：一个入口脚本，后端可切
        ▼
   后端 vm ：ssh world '<cmd>'                       ← 主力（现在就这个）
   后端 wsl：wsl -d <distro> -- bash -lc '<cmd>'    ← 将来做对照实验时才接
   后端 world：世界自己（阶段 C 自举后）             ← 留的口子
```

**两条要点：**

1. **工作区必须放在 VM 原生盘**（`~/world`）。跨边界挂载（SMB / 9p）对 git 与大编译极慢，
   而且以后换载体时那些挂载点不存在——**现在就把这个依赖掐掉**；
2. **同步用 git**，不用 rsync：本机没有 rsync；而 git 有增量、有历史，
   **顺便留下"什么时候搬过什么"的证据**。

### 同步怎么落地（VM 侧一次性配置）

```bash
# 在 VM 里
git init --bare ~/world.git
mkdir -p ~/world
cat > ~/world.git/hooks/post-receive <<'EOF'
#!/bin/sh
git --work-tree="$HOME/world" --git-dir="$HOME/world.git" checkout -f
EOF
chmod +x ~/world.git/hooks/post-receive
```

```powershell
# 主机侧（Windows 自带 git + ssh，无需 rsync）
git remote add vm ssh://world/~/world.git    # 只在第一次
git push vm main                              # 之后每次同步就这一条
```

> 推送后 VM 的工作区**自动签出**（靠 `post-receive`），不需要你进去手动 pull。

## 二·补 · 从 Windows 操控 VM 的六种接口

> ⚠ **修订标注（2026-09-26）：下表是 Hyper-V 的口径，与现行载体重不匹配——照抄会失败。**
> 本机实际是 **VirtualBox 7.2.20**，VM 名 **`newworld`**（`VBoxManage.exe` 在 `D:\VirtualBox\`），
> 而 **Hyper-V 模块在本机没有装**（`Get-VM` / `Checkpoint-VM` 等命令**不存在**）。
> 常用命令对照（详见 `D:\vm\调试报告-VM启动失败与搬家.md`）：
>
> | 动作 | 现行命令（VirtualBox） |
> |---|---|
> | 列出 VM | `& 'D:\VirtualBox\VBoxManage.exe' list vms` |
> | 开机 | `... startvm newworld --type headless` |
> | 关机 | `... controlvm newworld acpipowerbutton` |
> | **打检查点** | `... snapshot newworld take <名字>` |
> | 列检查点 | `... snapshot newworld list` |
> | **回滚** | `... snapshot newworld restore <名字>` |
> | 图形控制台 | `... startvm newworld --type gui` |
>
> **原文保留不改**（史料纪律）；执行时以本标注为准。**纪律 2"每站先打检查点"必须用上表命令。**

**都有，但用途不同。** 分三层：**管理面**（管机器本身）、**操作面**（用里面的系统）、**兜底面**。

| # | 接口 | 从 Windows 怎么用 | 能干什么 | 谁用 |
|---|---|---|---|---|
| **1** | **Hyper-V 管理面**（PowerShell） | `Start-VM` / `Stop-VM` / `Checkpoint-VM` / `Restore-VMSnapshot` / `Get-VMNetworkAdapter` | **开关机、打快照、回滚、查 IP**——不进去也能管 | **Agent 主力** |
| **2** | **SSH** | `ssh world '<cmd>'`；`scp` / `sftp` 传文件 | 完整 shell、跑构建与测试 | **Agent 主力** |
| **3** | **VMConnect**（图形控制台） | `vmconnect.exe localhost world`，或 Hyper-V 管理器里"连接" | **像坐在机器前**：看启动过程、内核日志、登录 | 人 |
| **4** | **VS Code Remote-SSH** | `code --remote ssh-remote+world ~/world` | **编辑在 Windows、运行在 VM**，体验接近本机 | 人 |
| **5** | **增强会话**（Enhanced Session） | VMConnect 里勾选"增强会话"（需 guest 装 `xrdp` + `xorgxrdp`） | **剪贴板互通、窗口自适应、共享盘、音频** | 人 |
| **6** | **串口控制台**（兜底） | `Set-VMComPort -VMName world -Number 1 -Path \\.\pipe\world-serial`，再用终端接这个命名管道 | **网络/sshd 没起来时也能进**——排 boot 问题用 | 人（出事后） |

### Agent 实际只靠前两条

```powershell
# ① 管理面：这是 WSL 给不了的"30 秒回上一站"
Checkpoint-VM -Name world -SnapshotName "p3-baseline"
Get-VMSnapshot -VMName world
Restore-VMSnapshot -VMName world -Name "p3-baseline" -Confirm:$false

# ② 查 IP（靠集成服务，不用登进去）
(Get-VMNetworkAdapter -VMName world).IPAddresses

# ③ 操作面：执行
ssh world "cd ~/world && ./check.sh"
```

**人只靠第 3、4、5 条**：开机时看 VMConnect（能看见引导过程），干活时 VS Code + 增强会话。

### 两条提醒（别浪费时间）

1. **PowerShell Direct 对 Linux 客户机不可用**——`Enter-PSSession -VMName` 是 **Windows 客户机**的功能。
   Linux 客户机走 SSH；
2. **增强会话会"接管"画面**：勾了它以后，VMConnect 直接进 RDP，**看不到引导过程**了。
   排 boot 问题时把它关掉，用普通控制台或串口。

### 唯一真相的规则（避免两个编辑面打架）

我们规定了 **`D:\Code` 单点写入**，所以：

- **Agent**：在 `D:\Code` 写 → `git push vm` → VM 工作区自动签出；
- **人**：VS Code **本地打开 `D:\Code`**（不是 Remote-SSH 打开 VM 里的副本），
  终端用 `.\linux.ps1 <命令>` 伸进 VM；
- Remote-SSH 只在"要进去深挖"时用（看 VM 侧的真实文件、跑交互式调试），**改完记得把改动带回 `D:\Code`**，
  否则两个编辑面会漂移。

## 三、一个入口，多个后端

在 `D:\Code` 放一个 `linux.ps1`，**所有 Linux 执行都走它**：

```powershell
# linux.ps1 —— 唯一入口。切载体只改 $Backend
param([Parameter(ValueFromRemainingArguments=$true)][string[]]$Cmd)
$Backend = 'vm'                  # 'vm' | 'wsl' | 'world'   ← 只有这一行需要改
$VmHost   = 'world'
$Distro   = 'Arch'
$line     = ($Cmd -join ' ')
switch ($Backend) {
  'vm'    { ssh $VmHost "cd ~/world && $line" }
  'wsl'   { wsl -d $Distro -- bash -lc "cd ~/world && $line" }
  'world' { <阶段 C 之后接上> }
}
exit $LASTEXITCODE
```

用法永远是一种形状：
```powershell
.\linux.ps1 ./check.sh          # 跑检查
.\linux.ps1 go test ./...       # 跑测试
.\linux.ps1 uname -r            # 看环境
```

**为什么这个设计值钱**：换载体时**只改一行**。
如果换的时候发现别处还要改，那就是**工作流里漏了耦合**——和"世界漏进载体"是同一类病，
**当场记下来**。

## 四、给 Agent 用的五条纪律（这才是"好方法"的核心）

Agent **不能交互输密码、不能盯屏幕、不能手动重试**。所以：

| # | 纪律 | 具体做法 |
|---|---|---|
| 1 | **一个稳定入口** | 仓库里放 `./check.sh`——把构建 + 测试 + 静态检查全包了。**Agent 永远只敲这一条** |
| 2 | **免密** | `ssh-keygen` + 公钥写进 VM 的 `~/.ssh/authorized_keys`。**Agent 输不了密码** |
| 3 | **非交互 + 幂等** | 每条命令一条龙跑完；重复跑结果一致（不能"跑第二次就报错"） |
| 4 | **明确退出码** | 成功 0、失败非 0，**不靠 Agent 读日志猜成败** |
| 5 | **产物不回流** | 构建产物留在 VM；`.gitignore` 挡住，别同步回主机 |

`check.sh` 模板（零依赖，不要求 make/just——本机也没装）：

> **修订标注（2026-09-26）**：纪律 3 的"**幂等**"必须分两种，否则与"**账本只追加**"直接冲突
> （见 [03 篇](03-世界核心的最小实现.md) §七 / [04 篇](04-模块清单与实现顺序.md) §六）：
>
> | 类型 | 要求 | 例子 |
> |---|---|---|
> | **命令幂等** | ✅ **必须**幂等（跑两次结果一样） | 构建、测试、静态检查 |
> | **数据幂等** | ❌ **天然做不到，也不该要求** | "追加一条事件"——跑两次就是两条 |
>
> **测试的落地方式**：业务测试必须用**一次性沙箱**（临时目录 / 临时账本），
> **绝对不许"清空真账本"**——清空 = 删除 = 违反"账本只追加"这条更根本的纪律。

```bash
#!/usr/bin/env bash
set -euo pipefail
echo "== env ==";   uname -r; go version 2>/dev/null || true
echo "== fmt ==";   gofmt -l . | tee /tmp/fmt.out; test ! -s /tmp/fmt.out
echo "== build =="; go build ./...
echo "== test ==";  go test ./...
echo OK
```

### 本机环境坑（2026-09-25 已踩，务必记住）

| # | 坑 | 症状 | 处理 |
|---|---|---|---|
| 1 | **默认 shell 是 Windows PowerShell 5.1**（`powershell.exe`），**不是 pwsh 7** | 用不了 .NET Core API（如 `[IO.Path]::GetRelativePath`）；行为与文档/示例不一致 | 写脚本按 5.1 兼容写；或显式装 pwsh 7 |
| 2 | **`.ps1` 必须带 UTF-8 BOM** | 无 BOM 时 5.1 按 ANSI 读，**中文字符串被打乱 → 直接语法错误**（`The string is missing the terminator`） | 写入时用 `New-Object System.Text.UTF8Encoding($true)` 再 `WriteAllText` |
| 3 | **控制台默认 GBK** | 读 UTF-8 输出全是乱码（如 `wsl --status`） | 每条命令前加 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` |

> 这三条合起来解释了一个现象：**同一段脚本在别处能跑、在这台机器上不行**时，
> 先怀疑编码与 PS 版本，而不是逻辑。

## 五、为什么不选另外两种

| 方案 | 为什么不推荐 |
|---|---|
| **代码就放主机挂载点，直接在挂载上跑** | 跨边界 I/O 慢（git、大编译尤其明显）；**而且换载体后那些挂载点不存在**——等于把工作流绑死在当前环境 |
| **代码只放 VM，Agent 用 shell（`cat >`、`sed`）改文件** | Agent 的原生文件工具用不上；改用 heredoc 拼文件，**易错、难回滚、看不见 diff** |
| **在 VM 里跑 Agent 本体（现在就做）** | 方向对（阶段 C 就要这样），但现在做会丢掉主机侧的文件工具与观察能力。**留口子，不提前做** |

## 六、一个和项目目标一致的红利

> **把 Agent 放进 Linux 里跑，正是阶段 C"自举"要练的姿势。**

现在你让 Agent 在主机上驱动 VM；等世界能自举，Agent 要**住在世界里面**开发世界。
所以 `linux.ps1` 的入参设计成"**在 Linux 里执行什么**"——将来 World 成为后端时，
只是多一个 `'world'` 分支，**其余一字不改**。

## 七、最小可用配置（VM 装好后 20 分钟）

```powershell
# 1) 在 VM 里建裸仓库 + post-receive（见 §二），把 VM 的 IP 或主机名记为 world
# 2) 免密
ssh-keygen -t ed25519                     # 已有就跳过
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh world "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"

# 3) 主机侧接上远端并首次推送
cd D:\Code\07-agent-native-os
git remote add vm ssh://world/~/world.git
git push vm main

# 4) 放好 linux.ps1（§三）与 check.sh（§四）

# 5) 验一条：应打印 VM 的内核版本
.\linux.ps1 uname -r
```

**完成判据**：`.\linux.ps1 uname -r` 有输出，且 `.\linux.ps1 ./check.sh` 跑到底并打印 **`CHECK_OK`**。

> **修订标注（2026-09-26）**：原文写"打印 `OK`"，与实际 `check.sh` 输出的 **`CHECK_OK`** 不一致。
> "产出必须可验证"（[01 篇](01-从建虚拟机到垂直切片.md) §三 纪律 3）要求判据精确到字样，故更正。

## 八、将来接 WSL 做对照实验时，改什么

WSL **不是开发环境**（理由见 [01 篇 §〇·补](01-从建虚拟机到垂直切片.md)），
它只有一个用途：**第二载体对照**——同一个世界在两处都能跑、核心一行不改 = "换插座不拆楼"的实证。

接的时候只做三件事：

1. 装 WSL 与一个发行版（发行版**随便**——如果世界的代码在乎这个，那本身就是漏水信号）；
2. `linux.ps1` 里 `$Backend = 'wsl'`（**一行**）；
3. 在 WSL 里 `git pull /mnt/d/Code/07-agent-native-os main` 拉一份工作区。

**其余一律不动。** 如果发现还要动别的——那就是发现了隐性耦合，**当场记下来**。

## 九、一条边界说明

如果"跑一些 AI"指的是**在 VM 里跑本地模型**：那是另一件事（要 GPU 直通），
Hyper-V 的 Linux 客户机 GPU 支持弱，**不建议**。
算力按 [../00-总纲.md](../00-总纲.md) §2.6 走**进口**（外购 + 可替换 + 降级模式）。
