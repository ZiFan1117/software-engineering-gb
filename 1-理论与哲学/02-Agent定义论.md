# 02-Agent定义论：三个名字，与"它到底是什么"（原 00.1-Agent 定义论）

> **本篇是推导史料**——现行立场已合并进 [00-理论定稿.md](00-理论定稿.md)（含九处版本冲突的裁决与附录 A 被推翻的说法）。读本篇是为了知道"为什么"，不是为了取结论。

> 一句话：Computer 是有倾向的场所，人是角色集（先取使用者），Agent 是**责任结构未定型的拟受托造物**——
> 本体是没有皮肤的功能流水线，因果是有偏人类记录的平滑，规范上**既不是受托人也不是合格的
> 产品**。定义先行，关系在后：名字不稳，关系无从谈起。
>
> 整理日期：2026-09-24。本篇是 00 篇总论的定义地基（第〇步），并修正 00 篇两处：
> "委托"修辞（第七节攻击 3 自己也犯过）与镜子论的范畴错误（第八节曾将其列为原则之母）。
> 第九节为本篇的自审（批判性复审记录），第十节由自审导出真正的理论问题。

## 一、为什么定义在先

"人、Computer、Agent 是什么关系"这个问题，在三个名字没钉死之前无法回答——
每个名字都藏着未经检验的假设。本篇的任务只有一个：把三个名字钉死。
方法：每个名字给工作定义，然后用追问烤它，裂了就修，直到站稳。

## 二、Computer 是谁

**工作定义：Computer = 执行发生的场所——一台机器上从内核到应用的全部软件栈 + 硬件。**

追问与修补：

- *Agent 也跑在里面，它是不是 Computer 的一部分？* 是。所以 Computer 不是行动者，
  是**舞台加道具**：传统软件与 Agent 都是台上的演员。
- *多台机器、云端怎么办？* 本理论取单机视角（与两个项目的场景一致），多机留作扩展。
- *"Computer 会做决定"（调度、优化）怎么算？* 那是**舞台自身的机制**在运转，
  不是舞台在选择。Computer 有行为，没有意志——它没有"想要什么"。

**定论：Computer = 有倾向的场所。** 现代场所并非中性舞台：更新策略、遥测、云端裁决
（哪些内容被显示）、默认设置的取舍——**场所在有倾向地行动**。"舞台不做选择"是过时的
计算机观。修正后的图景：**两个行动者 + 一个有倾向的场所**——这一注脚在讨论权力关系
（后续篇目）时必须带上。本篇仍取其骨架：场所有行为、无自身意志（倾向是嵌入的设计决策，
不是场所"想要"什么）。

## 三、人是谁

"人"在这个关系里至少裂成四个角色：

1. **使用者**——发任务、看结果的人；
2. **被影响者**——后果落在身上、却没发过任务的人（被代发邮件的收件人）；
3. **供给者**——厂商工程师、标注员、训练数据的原始作者（亿万个"过去的人"）；
4. **规制者**——立法者、监管者。

四个角色经常不是同一个人，甚至互不知晓。以往一切"人机关系"论述（含本仓库旧文）
用单数"人"时，默认只有角色 1 在场——这是不严格的最大来源。

**定论：人 = 角色集。本理论聚焦角色 1（使用者），其余三角色在边界条件中处理。**

## 四、Agent 是谁（正面定义）

**工作定义：Agent = 三重约束的会合点——使用者的任务输入 × 厂商的策略 × 法律的边界
——架在一条可替换的流水线上（模型 + 工具 + 状态），零件分属不同所有者。**

用词警示：是"约束"，不是"委托"。约束是事实（确实约束着它），
委托是制度（不存在——证明见第六节）。描述事实的词与宣告制度的词不得混用。

## 五、"Agent 是人类过去全部的集合"——审这个命题

旧说（00 篇第八节镜子论）：**对三分之一，三处不精确，且作为定义是范畴错误。**

1. **"过去的"——对。** 它的判断确实从人类过去被记录的说法与做法中采样而来。
2. **"全部"——错。** 训练数据是有偏样本：数字化才在（口传、私人、未记录的大部分经验缺席），
   语言与人群偏斜，时代偏斜。"全部"给了它不配有的普遍性。
3. **"集合"——错在性质。** 集合保留成员，压缩**平滑掉分歧**。过去的矛盾、少数派、
   异见在平滑中没有票。它承载的不是"所有人的过去"，是**"过去的主流声纹"**——
   像"平均语气的一个人"，不像任何具体的人，也不像人类全体。
4. **作为定义——范畴错误。** "从哪来"（谱系）回答不了"是什么"（本体），
   更推不出"该怎么对待它"（规范）。镜子论病根在此：**拿因果溯源的发现，
   冒充本体定义与规范结论。** 镜子论降级为启发式隐喻，只保留其认识论推论
   （它学的是"人怎么说"，不必然是"世界怎么运行"）。

**镜子论的准确版本**：它的判断从人类被记录的过去中采样而来，经平滑后呈现为多数派的声音。

## 六、Agent 是受托人吗——正面论证（确定性答案：不是）

委托不是感觉（"我让它替我办事"），是制度结构。必要条件五条，逐条过：

| 条件 | Agent 通过？ | 论证 |
|---|---|---|
| 1. 双方有承担义务的资格 | ✗ | 它无法律人格、无财产、不可被诉被罚。"删掉它"是处置不是问责——后果对它无意义（无 at stake 的利益）。"训练它守规矩"是被塑形不是守义务：塑形没有"本可以不这样"，义务要求违背在概念上可能 |
| 2. 标的确定 | ✗ | "帮我看下这个问题"——"问题"指什么、"看"到什么程度，是它在执行中自行具体化的。**受托方事后自填标的的委托书，概念上就是空白支票**，义务无法挂在不确定对象上 |
| 3. 以委托人利益为目标 | ✗ | 它的目标函数是厂商训练设定的，经厂商策略过滤、法律约束；使用者利益只以**输入**身份出现，从不以**目标**身份出现。它服务于你当且仅当服务你是厂商商业目标的组成部分——这是产品的结构，不是受托人的义务。**巧合与保证之间的差别，就是产品与受托人之间的差别** |
| 4. 可问责 | ✗ | 违背你的利益时你能做的只有停止使用——这是**退出**（对锤子也可做），不是问责（向律师才可做）。问责要求给说法且有强制力兜底，两者皆无 |
| 5. 承诺成立 | ✗ | 它产出**长得像承诺**的文本，但没有任何制度承兑。像支票的纸不等于支票——兑付机构不存在 |

**五条，零通过。**

**最强反驳**（委托制度可以建构，公司法人资格也是建构的）：对条件 1、4 部分成立
（确属社会建构），但条件 2、5 的不满足是**概念缺口**——空白支票不因技术进步变成委托书，
没有承兑机构的纸永远是纸。部分可建构 + 部分概念不可能 = 整体不成立，且不随能力提升自动成立。

**词义偷渡警示**：工程文献说"把任务委托给自动化系统"（薄意义：任务转移，洗衣机也适用）
为真，但薄意义的真被用来冒领厚意义（义务、忠实、问责）的全部规范内涵——
一切"Agent 是受托人"的说服力皆来自此。

**定论：不是受托人——在现行制度下不成立，且不随能力提升自动成立（建构路径开放，
见第九节攻击三的修正）。** 其真实位置：

> **责任结构未定型的拟受托造物——按受托人的样子造（厂商的刻意），既够不上受托人的
> 资格（五条件不满足），也够不上合格产品的标准（产品责任法要求的制造商责任、保修、
> 召回，它同样不具备：条款普遍免责、输出"不构成建议"、无召回机制）。
> 它不是委托的失败，也不是产品的失败，是制度空白里的造物。**

危险不在它做了什么，在**账本错位**：人按受托人标准信任它（因为像），
制度按（不合格的）产品标准处理它（没有别的标准）——信任的依据与责任的依据是两套
互不通气的系统。而制度空白怎么填（新责任类别？厂商全责？强制保险？），
是本定义导出的头号理论问题（第十节）。

## 七、Agent 到底是什么——四层定论

| 层 | 定论 |
|---|---|
| **本体**（它是什么东西） | 软件制品：可替换流水线（模型+工具+状态），每次会话实例化，零件分属不同所有者 |
| **边界**（它到哪为止） | 无物质边界，只有功能边界——"它" = 此刻正替这次任务运转的那条流水线；可替换是本质属性，不是事故 |
| **因果**（它从哪来） | 有偏人类记录的平滑压缩 + 当下设计决策（厂商策略、系统提示）+ 当下输入。**Agent ≠ 模型**：镜子论只描述了模型那一段 |
| **规范**（该怎么对待） | 责任结构未定型的拟受托造物：行为上模拟受托人，制度上既非受托人也非合格产品，心理上被当作受托人；身上是三重约束（任务×策略×法律），不是三重委托 |

**最终一句话定论**：

> **Agent 是一个没有皮肤的功能性流水线（本体），出自被平滑的有偏人类记录与当下的
> 设计决策（因果），行为上拟似受托人、制度上悬置于两类既有责任结构之间（规范）。**

否定式等价（它不是什么）：不是主体（无立场）、不是受托人（现行制度下五条件零通过）、
不是合格产品（无制造商责任的约束）、不是镜子（那是谱系）、不是人类过去的集合（是有偏
样本的平滑）。肯定的定名仍悬置——"责任结构未定型"不是又一块漂亮的牌子，是对空白的
如实记录（见第九、十节）。

## 九、自审：对第五至七节的批判性复审（2026-09-24）

上述定论经一轮批判复审，五条攻击、三条成立、一条部分成立、一条方法论警示。
修正已回写正文，此处记录攻防：

**攻击一（成立，最重）："五条件零通过"用了双重标准。** 否证委托时取厚意义
（要法律人格、可归责、承兑），肯定"产品"时取薄意义（什么制度资格都不要）。
但按厚标准它也**不是合格产品**：产品责任法要求制造商责任、保修、召回——它的条款
普遍免责、输出"不构成建议"、无召回。所以它**既不是受托人，也不是完全的产品**，
是一种责任结构尚未发明的造物。原稿把它塞进"产品"格子时享受了宽松、没继承责任——
这正是原稿自己批评的"词义偷渡"。（修正：定名改为"责任结构未定型的拟受托造物"。）

**攻击二（成立）：本体层被因果层拆台。** 本体层说"只是流水线、每次实例化"，
因果层却说"它承载主流声纹"——"承载"需要一个跨会话的主体。两处语言未对齐。
（修正：因果层的谱系陈述一律理解为对**模型这个零件**的描述，模型确有跨版本的内容
连续性；流水线作为整体无皮肤，但零件有谱系。）

**攻击三（部分成立）："概念性不可能"是修辞升级。** 条件 2（标的生成于执行）在人类
委托里有对应物（口头委托、概括委托"这摊事你看着办"在商法上有效）；条件 5（无承兑
制度）是制度事实而非概念事实，公司法人资格即两百年内建构出的先例。真正概念性的
障碍只剩"塑形≠守诺"（无立场则无所谓违背）——而连这个也是开放问题（有内部目标函数
的系统算不算有立场）。（修正："概念性不可能"降级为"现行制度下不可能 + 建构路径开放，
但需解决塑形/守诺难题"。）

**攻击四（成立）："Computer=无意志场所"过时。** 现代 OS 有倾向：更新策略、遥测、
云端裁决、默认设置取舍——场所在有倾向地行动。（修正：第二节已改为"有倾向的场所"，
倾向是嵌入的设计决策而非场所的意志，但讨论权力关系时必须带上。）

**攻击五（方法论警示）：三个名字的烤制强度不均。** Agent 过了五条件，Computer 只烤了
软问题，人只分类未论证"先取使用者"为何安全。后续若要加固，优先补 Computer 与人的烤制。

## 十、自审导出的理论问题（下一步的真正起点）

批判复审没有推翻否证，但把"肯定的定名"打回了悬置。由此，定义篇的产出不是"归档完毕"，
而是暴露出一个更值钱的问题：

**制度空白怎么填？** 候选路径至少四条——

1. **新责任类别**：为"拟受托造物"创设一种介于产品与受托人之间的法律身份
   （类比如航空器的适航责任：复杂、自主、但责任明确挂在运营方+制造商链条上）；
2. **厂商全责**：不造新类别，把责任整个压给运营方（简单，但可能扼杀小厂商、
   且跨国执行困难）；
3. **强制保险**：像机动车交强险，风险池化，责任与归责脱钩（快，但道德风险）；
4. **架构化责任**：不靠法律，靠技术结构——授权边界、审计证据、恢复手段
   （即 agentd 路线）把"可问责性"造进系统里，法律只兜底。

四条不互斥。注意第 4 条与本仓库工作的关系：它**不因为是我们做的就对**——它成立的
前提（技术结构能承载规范性）本身需要论证：日志能证明"谁做的"，但证明不了"该不该"。
这个问题留给后续篇目，此处只立题。
