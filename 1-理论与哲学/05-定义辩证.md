# 05-定义辩证：三个定义的正反合（原 00.4-定义辩证篇）

> **本篇是推导史料**——现行立场已合并进 [00-理论定稿.md](00-理论定稿.md)（含九处版本冲突的裁决与附录 A 被推翻的说法）。读本篇是为了知道"为什么"，不是为了取结论。

> 一句话：静态定义（00.1）给三张名片——场所、角色集、未定造物；辩证定义给名片背后的
> 动力学——Computer 是**被争夺的场所**，人是**循环且监督衰减的位置**，Agent 是
> **三股定型力量争夺的战场**。三角合成一个自我强化的循环系统，且**定义行为即参战行为**。
>
> 整理日期：2026-09-24。方法：每个定义走正（自身主张）→ 反（它靠什么对立面才成立）→
> 合（包含对立面的定义）。本篇取代 00.1 第二、三、四节作为"现行定义"，00.1 保留为
> 定义工作的历史记录（其第六节委托否证不受影响，仍然成立）。

## 一、Computer 的辩证定义

**正**：场所——执行发生的场地，有行为无意志（00.1 第二节）。

**反**：中立场所靠**被争夺**才成其为问题。三方同时定义它：厂商（更新/遥测："我的软件
跑在上面所以我有权看见"）、使用者（购买/配置："我付了钱所以它是我的"）、法律（合规：
"无论如何必须可审计"）。且"中立"是历史产物——个人计算机曾真属个人（无法远程变更），
云端化后"场所"实为**租约的集合**。没有这场争夺，"场所"概念根本不会被提出。

**合**：**Computer = 被持续争夺的执行场所。** 它的每项属性（谁能看、谁能改、谁被执行）
都是争夺的暂时结果，不是本性。完整定义 = 场所 + 当前生效的产权与控制格局（00.3 混合
产权三档即此格局的刻画）。推论：agentd 的本地主权设计不是技术偏好，是争夺中站在
使用者一边的表态。

## 二、人的辩证定义

**正**：角色集——使用者/被影响者/供给者/规制者，先取使用者（00.1 第三节）。

**反**："使用者"靠 agent 的存在才被构造出来（有 agent 之前只有"操作者"；是 agent 需要
一个被代表者，才把人构造为使用者）；且人是**供给者在先、使用者在后**——今天向 agent
提问的人，正成为明天 agent 回答别人的原料；监督悖论更反噬定义本身：验收能力持续衰减，
"使用者"的定义里内置着自己的消解。

**合**：**人 = 在"原料 ↔ 客户 ↔ 监督者"循环中被轮流指派的位置，且监督者角色结构性衰减。**
"此刻的使用者"与"下一刻的原料"是同一个人——定义人必须写进时间。"角色集"由并列的帽子
升级为循环的位置。

## 三、Agent 的辩证定义

**正**：责任结构未定型的拟受托造物——三重约束会合点，可替换流水线（00.1 第四、七节）。

**反**："未定型"靠三股定型力量的拉扯成立：厂商往**产品**定型（免责、订阅、"不构成建议"）、
法律往工具或出版物归类（各法域拉扯）、使用者用心理往**受托人**定型（信任、托付、拟人化）。
"未定型"不是它的状态，是三股力量暂时打平的**僵局**；且每方都在用使用行为加固自己的定型
（越信任越受托化，越免责越产品化）。反身性最强的一条：**本理论工作也是一股定型力量**——
说它"未定型"，就在同时对抗"只是工具"与"是伙伴"两种定型。定义行为即参战行为。

**合**：**Agent = 三股定型力量（产品化/受责化/受托化）争夺中的造物；"未定型"是僵局而非
本性；最终归类不取决于技术性质，取决于哪股力量赢。** 力量消长部分取决于基础设施——
谁握着审计、授权、恢复的机制，谁定型得快。四层定义（本体/边界/因果/规范）保留，
第四层改写为：**规范地位 = 定型战场**。

## 四、三个定义的咬合：循环系统

| 定义 | 静态版（00.1） | 辩证版新增 |
|---|---|---|
| Computer | 场所 | 被持续争夺的执行场所（产权与控制是暂时结果） |
| 人 | 角色集 | 原料↔客户↔监督者循环，监督位结构性衰减 |
| Agent | 未定型拟受托造物 | 三股定型力量争夺的战场，定义即参战 |

咬合动力学：**人循环的每一圈给 Agent 的战场输送弹药（数据加固模型、信任加固受托化），
定型结果反过来改变 Computer 的争夺格局（谁的定型赢，机器按谁的主权配置）。**
三角不是三个东西的关系，是一个自我强化的循环系统。

## 五、待批判项

1. "定义即参战"有自我豁免风险——本定义也可能只是又一股伪装中立的定型力量（需自证立场）；
2. 循环系统给出动力学但未给出**均衡条件**（僵局何时/何种条件下破裂）；
3. 辩证定义的操作化：它如何指导 cap.d/审计的具体设计（除"站在使用者一边"的表态外）。
