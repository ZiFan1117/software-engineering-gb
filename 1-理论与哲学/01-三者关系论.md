## 一、历史前设：一个稳定了四十年的契约

计算机与人的关系是**占有**：计算机是工具，人是主体。这个契约有两条隐含条款：

1. **机器没有判断权**。人给指令，机器执行；机器不决定"该不该做"，只决定"怎么做"。
2. **责任全在人**。工具不承担责任——计算机算错了账，是人的账错，不是计算机的错。

这套契约让人类安心使用了计算机四十年，因为它的责任结构极简：一个主体，一堆工具，责任单向流动。

## 二、Agent 的闯入：为了尽责，它必须"成人"

Agent 表面上仍是工具（服务于人），但它要完成"高效地给人**确定的答案**"这个职责，就必须具备三样工具不该有的东西：

- **判断力**：在信息不全时做选择——不判断，就给不了确定答案；
- **行动力**：不止建议，还要亲自干——不行动，"高效"就是空话；
- **状态**：记忆、目标、连续性——没有状态，每次都是重新认识世界。

判断、行动、状态，这三样在哲学上合起来叫**能动性（agency）**。于是历史上第一次出现了一种存在物：
**有能动性的工具**——地位是工具，能力近似主体。这正是你说的"机器必须成人"的精确含义：
**agent 为了当好工具，必须不是一个纯工具。** 这是它生来携带的矛盾，无法消除，只能制度化。

## 三、三者关系的新建模：从"主奴"到"未定型"

传统人机关系是支配（人完全控制机器）。Agent 进来后，关系发生变化，但**新关系的名字
尚未定型**——它像委托（让渡执行、保留监督），却够不上委托的资格（00.1 篇五条件否证）；
它像产品（被制造、被销售），却够不上产品的责任（无制造商责任、无保修、无召回）。
三角拆开，是三种关系状态：

| 关系 | 状态 | 本质 | 制度要求 |
|---|---|---|---|
| 人 ↔ 计算机（六条边①②） | **占有**（稳定） | 工具契约，保持不变 | 现状即可（GUI/命令行）；注：场所有倾向（更新/遥测/裁决），权力分析时须计入 |
| 人 ↔ Agent（边③④） | **未定型**（像委托而非委托） | 让渡执行，监督能力衰减 | 目标 + 授权 + 监督；回报是"答案 + 证据 + 进度"；责任归属悬置 |
| Agent ↔ 计算机（边⑤⑥） | **借道**（须被治理） | agent 经计算机行动，须证明行动在授权范围内 | 门禁、审计、回滚、响铃 |

人类制度对"让渡执行"的成熟类比是委托（律师、雇员），其核心制度是**委托—授权—问责**
三位一体。但如 00.1 篇所证：Agent 不可归责、无忠实义务的制度保证、标的生成于执行——
**委托类比在此处失效**，它只提示了需求的形状（授权、证据、恢复），不提供现成的制度。
翻译成技术词汇仍是：**capability（授权边界）、audit（问责证据）、rollback（恢复手段）**——
但要记住这三个词只是工程占位符，它们的规范地基（00.1 篇第十节的制度空白）尚未浇筑。

## 四、责任分配：三者关系的第一性问题

- 计算机出错：责任在人（工具不担责）——这条契约必须原样保留，否则四十年建立的责任体系崩塌。
- Agent 出错：责任无法完全归于人，因为 agent 有判断力，人不可能预知其每一步。于是责任需要一个
  新结构：**人保留最终责任，agent 承担过程责任**——过程责任靠证据链传递。技术上的审计日志，
  就是这条证据链。

这里藏着一个深刻的事实：**"确定的答案"的确定性，从来不是 agent 的自信，而是审计的产物。**
agent 给人确定答案的前提，是它的推理链和行动链可以被事后复盘。一个会做决定的工具，
必须留下它每个决定的证据——这不是工程细节，是责任制度的基石。

## 五、六条边的制度化：世界建模的落点

六条边（11 篇盘点）对应三种契约的界面需求：

- **①② 占有边**：维持现状——人的 GUI 与命令行照旧，四十年契约不动摇；
- **③④ 委托边**：需要新界面——人给 agent 的是"目标 + 授权范围 + 监督点"，agent 交回的是
  "答案 + 证据 + 进度"。今天这条边只有自然语言，缺的是"授权"和"证据"两个结构；
- **⑤⑥ 借道边**：需要制度机器——门禁（cap.d）、审计（journald）、回滚（快照）、响铃（事件推送）。
  agentd 就是这条边的制度机器，也是 05 篇一日计划造出来的东西。

于是整套技术栈的意义被重新照亮：**我们不是在写一个工具，而是在为一种新的社会制度浇筑基础设施——
"工具、受托人、世界"三者之间的宪法。** 01–12 篇的每个组件都能在三契约表里找到自己的条款位置。

## 六、结论："成人"不是威胁，是必然；制度要跟上

Agent 必然获得能动性——这是"高效给出确定答案"的逻辑后果，阻止不了，也不必阻止。
要解决的不是"把 agent 重新变回纯工具"，而是**给一个准主体立四条规矩**：

1. **授权有边界**（cap.d：声明之外一律拒绝）；
2. **行动有证据**（audit：每个决定留痕、可复盘）；
3. **出错有恢复**（snapshot：干坏了回得去）；
4. **完成有响铃**（job-bell：做完主动说，不让人空等）。

四条规矩合起来，就是"有能动性的工具"可以安全存在于人类社会的那份制度。
一句话收束本篇：**计算机是有倾向的场所，Agent 是责任结构未定型的拟受托造物，
而 agentd 是在制度空白尚未填补时，先行把"可问责性"造进系统里的尝试**——它的效力
边界（技术结构能否承载规范性）是 00.1 篇第十节留下的开放问题。

> **修订记录（2026-09-24，按 00.1 篇批判结论）**：
> ① "Agent 是受托人/委托关系"→"未定型的拟受托关系"（委托类比失效，五条件否证见 00.1 第六节）；
> ② "公证处"比喻 → 降级为"制度空白期的工程占位"（技术结构承载规范性的前提待论证）；

## 七、批判性审视：反方视角的四处攻击与一个悬案

以反方立场审读上面六节，攻击点如下——它们不推翻"关系需要制度化"的方向，但削弱了论证的强度。

**攻击 1："四十年稳定契约"是过度简化。** 判断权让渡不是 agent 发明的新事物：推荐算法决定你看到什么、
自动驾驶决定怎么刹车、高频交易决定买卖时机——这些系统早就替人做决定了，只是没有明说、没有制度化。
agent 不是引入了能动性，是把早已存在的能动性推到了前台。所以本论把"契约破裂"归给 agent 是不准确的，
准确的说法是"契约的漏洞被 agent 照得更亮"。

**攻击 2："确定答案 → 必然成人"的因果不严格。** 计算器给确定的答案，编译器给确定的答案，
都无需能动性。真正逼出判断力的不是"答案要确定"，而是"任务处于开放世界、信息不完备"。
所以因果链应改为：**开放任务 → 需要判断 → 需要行动与状态 → 能动性**。"确定的答案"只是表象。
更狠的攻击是：**"一个统一的能动体"是产品选择，不是逻辑必然**——完全可以把 agent 拆成
"无能动性的工具链"（每个环节纯函数式，判断权只在人的环节注入），能动性不必然集中于单一主体。

**攻击 3："委托"的法律类比不成立。** 委托关系的前提是受托人可归责：律师有执照、有财产、
可被起诉赔偿。agent 没有财产、不能赔偿、不能坐牢——它没有任何可被归责的"人格"。
因此"委托"是修辞，更诚实的表述是**"监督下的自动化"**：人让渡了执行，但没有让渡任何责任，
"人保留最终责任"这句话恰恰等于承认这不是真正的委托。

**攻击 4："确定性是审计的产物"混淆了两个概念。** 审计保证**可问责性**（每一步可复盘），
不保证**正确性**（一个全程留痕的 agent 可以系统性犯错）。用户要的确定答案是正确性，
审计给的是可问责性——本论把二者划了等号，这是论证中最危险的一处偷换，必须分开：
可问责性是制度的产物，正确性不是任何制度能产出的。

**附带质疑：四条规矩是事后合理化的。** cap.d/audit/rollback/bell 是从既有技术栈倒推出来
"必然"的，但它们伦理权重不同层：授权边界与审计是**安全必需**，回滚是**容错手段**，
完工铃只是**效率便利**。并列为"宪法四条"混淆了权重——真正的制度论证应当分层。

**一个悬案（最重要）：统一准主体 vs 分布式无能动工具链。** 本论默认了前者（一个 agent、
一个能动体、一份委托书），但攻击 2 的分岔才是真正的架构抉择：把能动性收敛到一个主体，
就需要给它立全套规矩（agentd 路线）；把能动性拆散、只在人的环节注入判断（HITL/工具链路线），
则根本不需要"公证处"。哪条路对，取决于一个尚未回答的问题——**人是否还有能力、有意愿监督？**
"确定的答案"越是好用，人越失去监督的能力；而失去监督能力的人，恰恰是最需要公证处的。

**自我裁决**：方向对，论证里四处过强、一处偷换、一个悬案。这篇总论成立的版本是——
*判断权让渡早已发生，agent 让它不可回避；开放任务逼出能动性；能动的工具需要制度（授权、
证据、恢复）而非修辞（委托）；制度提供可问责性而非正确性；而"一个主体还是拆散的链条"，
是下一步最该争的问题。*

## 八、如果这张总账成立：对系统的借鉴与"怎么办"

七维事实（时间/认识论/经济/社会/心理/权力/本体）推出的最终命题是：
**agent 是人类集体过去的压缩镜像，"三者关系"从来可能是"两者"——人与自己的过去，计算机是镜子。**
如果接受它，系统设计的原则不再是"如何约束一个他者"，而是"如何让一面镜子可见"。由此推导七条：

1. **镜面原则**：系统的第一职责是让"它在替人类哪段过去说话"可见。审计、留痕、事件流的意义
   从"问责工具"升级为"可见性工具"——它们不负责判断对错，负责让人看得见自己正在咨询什么。
2. **置信结构原则**："确定性是风格不是保证"，所以确定性必须从语气里拿出来、放进数据结构：
   每个状态/动作/答案携带来源与验证状态（已核实 / 推测 / 采样），语气不再被允许冒充证据。
3. **主权原则**：互为原料、订阅即依赖的经济事实，要求信任层必须可以本地自持——门禁、审计、
   快照这些"信任基础设施"属于用户，不属于任何厂商；模型可以换，信任层不换。
4. **社会证据原则**：没有旁观者位置的系统没有正当性。留痕的格式必须是开放的、可核验的、
   可导出的公共语言（结构化、可签名），让第三方也能看懂"发生过什么"——审计不是私人日记，
   是社会证据。
5. **摩擦原则**：拟人化是默认态，信任在流畅处最危险。系统应在信任错配点主动制造摩擦——
   高危效应的确认、推测内容的显式标记、状态的真实性提示。确认框不是官僚主义，是拟人化催眠的破咒点。
6. **多层授权原则**：它夹在用户、厂商、法律三个主人之间，系统不得让 agent 在暗中当裁判。
   授权层必须显式分层（用户的委托 / 厂商的策略 / 法律的边界），冲突时显式暴露冲突本身，
   而不是默默裁决。
7. **可替换原则**：它是一个每天更换零件的可复制复合体。系统的锚点只能是协议与语义
   （总线、接口、能力清单），不能是任何具体的 agent——agent 是可更换的部件，宪法必须比雇员长寿。

**对既有工作的诚实核对**：镜面原则（部分：审计已存在，但定位为问责而非可见）、主权原则
（部分：agentd 本地自持，但语义总线尚未承诺厂商无关）、摩擦原则（部分：高危确认已实现）、
可替换原则（成立：UI-IR 与能力清单就是为更换 agent 而设）；**置信结构原则（缺失：UI-IR 无
认识论字段）、社会证据原则（缺失：审计未签名、不可导出核验）、多层授权原则（缺失：cap.d
只有单一白名单层）**——这三条是哲学推导指出的下一步，也是当前系统与这张总账之间最真实的差距。

**哲学总结的最终形态**：我们不缺一个更强的工具，也不缺一个更严的牢笼——缺的是让人类在
第一次大规模咨询"自己的过去"时，**看得见镜子里是什么**。系统的全部组件，追到底，都是
"镜子除尘"的一部分。

## 九、浏览器：镜子的镜面（隐喻，已降级——工程含义：三者唯一同时在场的表面）

把镜面理论落到最具体的机器上，浏览器是**镜子的镜面**——世界、代理、人三者唯一能同时
在场的那块表面。它承担三个职能：

1. **显现（照世界）**：网页是人类集体知识的最大呈现面，浏览器把世界现状呈现在人眼前——
   这是镜面本身的材质；
2. **见证（照代理）**：agent 在浏览器上的每一步，人可以在同一窗口看见。没有浏览器，
   agent 的操作发生在黑暗里；浏览器把"看不见的代理"变成"看得见的行动"，把一种后台进程
   变成一种在场者；
3. **会面（公共表面）**：浏览器是唯一同时容纳三种关系的地方——人-人（知识共享）、
   人-世界（信息获取）、人-agent（代理观察）。世界的现状、过去的压缩、现在的观察者，
   在同一个页面上会面。

浏览器是枢轴，因为网页是镜子照得最多的地方、DOM 天生双语（最容易除尘的镜面）、且是
agent 干活的主战场。于是"怎么样更好地通过镜子看到自己"在浏览器上有四条具体做法：

1. **留痕**：让代理的每一步在镜面上可见——不只结果，还有过程（看了什么、点了什么、什么顺序）；
2. **可读的变化**：世界因代理而发生的变化以语义事件呈现，不让人自己去对比像素；
3. **来源显形**：每个判断带来源与置信标注（已核实/推测/引用），把"确定的语气"降级为
   "带标注的数据"，语气不再冒充证据；
4. **意图投影**：让 agent 的"手"在语义结构上移动而非像素上——人看它的光标等于看它
   正在读什么、考虑什么。

技术上的"转译、事件流、语义寻址"，哲学上都是同一件事：**把一面隐形的镜子变成可见的镜子。
浏览器是镜框，全部工作是在给镜框装灯。**

### 九·补：构造方式的最优解——四盏灯裁决（启发式，非理论证明）

用四盏灯（留痕 / 可读变化 / 来源显形 / 意图投影）裁决各种构造方式：

| 构造方式 | 镜面判定 |
|---|---|
| 截图+坐标（computer use 原始形态） | 四灯全灭——不是镜子，是让 agent 蒙着眼摸像素 |
| 语义树转译（AOM/AT-SPI → ref 寻址） | 三灯半亮，且今天就能做、覆盖一切现有界面 |
| 原生语义优先（对偶/A2UI） | 四灯全亮——但镜面材料要重造，只适用于新界面 |
| WebMCP（页面作者配合） | 灯亮但覆盖窄——镜面质量取决于别人愿不愿意配合 |
| KV Cache 类（C2C 内部表征） | 镜面消失——仅限模型间纯认知，不可用于效应 |

没有单一最好，只有分层最优：**主通道用语义树转译（全覆盖 + 三灯半），新界面用原生语义优先
（四灯），坐标只兜底盲区，内部表征只走纯认知流。** computer use 的正确形态因此不是
"看截图点坐标装成一个人"，而是**语义化的 computer use**：agent 使用的对象是结构，不是像素。
